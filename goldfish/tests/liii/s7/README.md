# (liii s7) 模块函数分类索引

`(liii s7)` 提供底层的 S7 原生内置原语导出，供需要直接使用 S7 底层语义或高性能内建实现的场景使用。

## 与标准库函数的区别

`xxx`（如 `ceiling`、`floor`、`truncate`、`round`、`min`、`max`、`modulo`、`lcm`、
`sqrt`、`make-hash-table`、`hash-table-set!`）是符合 R7RS / SRFI 语义的标准库实现：
参数校验完整、错误类型统一（`type-error`、`division-by-zero`）、精确性保持规则明确，
并且可移植。

`s7-xxx` 是 S7 原生内建原语的直接导出：不做额外包装与 R7RS 校验，行为以 S7 为准。

常见差异（实测）：

| 表达式 | 标准库 | S7 原生 |
| --- | --- | --- |
| `(ceiling 1.1)` | `2.0`（不精确） | `(s7-ceiling 1.1)` => `2`（精确） |
| `(ceiling -0.0)` | `-0.0`（保留符号） | `(s7-ceiling -0.0)` => `0` |
| `(min 1 2.0)` | `1.0`（不精确） | `(s7-min 1 2.0)` => `1`（原始参数） |
| `(lcm 2 3.0)` | `6.0` | `(s7-lcm 2 3.0)` => 报错（只接受有理数） |
| `(modulo 13 0)` | 抛 `division-by-zero` | `(s7-modulo 13 0)` => `13` |

选择建议：

- 常规业务代码、可移植代码、需要统一错误处理的地方：用标准库的 `xxx`。
- 需要"确定得到精确整数"（例如把浮点输入规整成整数索引）、热路径追求原生性能、
  或需要直接操作 S7 原生对象（如原生哈希表）：用 `s7-xxx`。
- 在对外暴露的库代码中不要依赖 `s7-xxx` 的错误类型与消息。

## 查看函数文档

使用以下命令查看函数文档和测试用例：
```bash
gf doc "函数名"
```
或者指定库名：
```bash
gf doc liii/s7 "函数名"
```

## 函数分类索引

### 一、数值运算
- `s7-ceiling` - S7 原生向上取整函数
- `s7-floor` - S7 原生向下取整函数
- `s7-truncate` - S7 原生向零截断函数
- `s7-round` - S7 原生银行家舍入函数
- `s7-min` - S7 原生求最小值函数
- `s7-max` - S7 原生求最大值函数
- `s7-modulo` - S7 原生模运算
- `s7-lcm` - S7 原生最小公倍数运算
- `s7-sqrt` - S7 原生平方根函数

### 二、哈希表
- `s7-make-hash-table` - 创建 S7 原生哈希表
- `s7-hash-table-set!` - 设置 S7 原生哈希表键值

### 三、优化与调试
- `s7-optimize` - S7 底层代码优化与调试辅助函数
