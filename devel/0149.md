## 2026-09-08 修复 g_http-post 的 files 参数 multipart 路径类型检查缺失

### What

1. `src/liii_http.cpp` 新增 `check_multipart_part_spec` 与 `check_multipart_files`：
   - 校验 `files` 的每个 part-spec 是 proper list；其内每个 entry 是 pair，key 为 string/symbol，value 为 string。
2. `f_http_post` 入口处要求 `files` 必须是列表（否则 `type-error`），与 params/headers/proxy 的守卫行为一致；非空时再逐 part-spec 校验。
3. `tests/liii/http/http-post-test.scm` 离线测试段新增 5 条直接调用 `g_http-post` 的回归用例（files 非列表、part 非列表、entry key 非法、entry value 非字符串、entry cdr 为列表）。

### Why

此前 `f_http_post` 只校验了 `params`/`headers`/`proxy`/`body_or_data`，`files` 非空 proper list 时直接进入 `to_cpr_multipart_part`，其内部对 `s7_car(entry)`、`s7_string(raw_key)`、`s7_string(s7_cdr(entry))` 全部无类型检查。根环境直接调用 `(g_http-post "http://x/" '() '() '() '() '(#\a) #f)` 时，`s7_car(#\a)` 解引用立即数导致 SIGSEGV（与 c32~c39 同一威胁模型）。公开接口 `http-post` 由 `http-normalize-files` 保护，不受影响。另外 `files` 传非列表值（如 `42`、`#f`）此前会被静默忽略并走普通 body 分支，现在统一抛 `type-error`。

## 2026-09-08 之前的提交和任务描述

C++ 层为 http 模块胶水函数增加参数类型检查，修复非法参数导致的崩溃（#972）。

### What

1. `src/liii_http.cpp` 增加辅助函数 `string_type_error` 与 `check_string_alist`：
   - `check_string_alist` 严格校验参数是否为字符串键值对列表（`((string . string) ...)`）。
2. 在 `f_http_head`、`f_http_get`、`f_http_post` 以及异步版本 `f_http_async_get`、`f_http_async_post`、`f_http_async_head` 入口处增加类型守卫：
   - `url` 不是 string 时抛出 `type-error`。
   - `params`、`headers`、`proxy` 不是 string alist 时抛出 `type-error`。
   - `body` 不是 string（或 multipart 时不是 alist）时抛出 `type-error`。
   - `callback` 不是 procedure 或 boolean 时抛出 `type-error`。
3. 对应测试文件中增加参数类型回归测试（均使用公开接口，不暴露 `g_*`，无网络依赖）：
   - `tests/liii/http/http-head-test.scm`（`http-head`）
   - `tests/liii/http/http-get-test.scm`（`http-get`）
   - `tests/liii/http/http-post-test.scm`（`http-post`）
4. 验证完成后移除 demo/crash 目录。

### Why

`demo/crash/c32` ~ `c39` 展示了根环境直接调用 `g_http-*` 时可能触发的各类崩溃：
- `url` 传整数：`s7_string` 返回空/非法指针，进入 `cpr::Url` 构造 `std::string` 抛出 `std::logic_error` 导致 SIGABRT（exit 134）。
- `params`/`headers`/`proxy` 传非列表、列表项不是 pair 或 pair 内元素非 string：在解引用或构造 `cpr::Parameter` 时触发 SIGSEGV（exit 139）或 SIGABRT。
- `post` 的 `body` 传整数：构造 `cpr::Body` 时触发 SIGSEGV。

通过在 C++ 胶水层全面增加类型检查，统一抛出 `(liii error)` 约定的 `type-error`，彻底解决未定义行为与进程异常终止问题。

### How

- 使用 `string_type_error` 辅助函数经 `s7_error` 抛出 `type-error`。
- 使用 `check_string_alist` 遍历列表并校验每一项是否为 pair 且 car 和 cdr 均为 string。
- 在各胶水函数入口先校验全部输入参数，异常时立即返回错误，不再进入 libcpr 流程。
