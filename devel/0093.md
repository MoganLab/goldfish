## 2026-07-30 用 C++ 实现 string-split

### What
1. 在 bench/string-split.scm 中对原 Scheme 实现做性能基线评测
2. 新建 src/liii_string.cpp，用 C++ 实现 f_string_split 并注册为
   `g_string-split`；xmake.lua 与 goldfish.hpp 完成接线
3. goldfish/liii/string.scm 中 `(define string-split g_string-split)`，
   替换原 Scheme 循环实现
4. tests/liii/string/string-split-test.scm 补充 2 个多字节字符分隔符用例
   （`(string-split "你，好" #\，)` 等），42 项全部通过，
   `bin/gf test --all` 1492 项全部通过

性能对比（秒，越少越好）：

| 场景 | Scheme 基线 | C++ 实现 | 加速比 |
|---|---|---|---|
| 短字符串（3字段） 逗号分隔 (100000 次） | 0.0473 | 0.0175 | ~2.7x |
| 中字符串（10字段） 逗号分隔 (100000 次） | 0.1255 | 0.0471 | ~2.7x |

### Why
string-split 是文本处理高频函数，原 Scheme 实现每个字段都要经过
string-position + substring 的 Scheme 层循环；空分隔符路径还要逐字符调用
utf8-string-length / utf8-substring，开销尤其大。沿用 0088 (filter) /
0089 (take) / 0090 (take-right/drop-right) 的思路下沉为原生实现。

### How
- 语义与 Python `str.split(sep)` 对齐（见 devel/210_31.md）：保留空字段、
  不重叠匹配；空分隔符按 UTF-8 字符拆分是 Goldfish 的扩展
- 非空分隔符路径是纯字节操作：std::string_view::find 循环定位，
  用 (offset, length) 对收集字段，最后一次性构造 s7 字符串列表
- 空分隔符路径直接按 UTF-8 首字节推断码点宽度切分，非法字节按单字节处理
- 字符分隔符在 C++ 侧做 UTF-8 编码（utf8_encode），等价于原实现的
  `(string sep)`，多字节字符分隔符行为由新增测试固化
- 错误契约保持不变：str 非字符串、sep 非字符串/字符均抛 type-error
  （消息文本与原实现一致）；参数个数错误由注册 arity (2, 0, false)
  自动抛 wrong-number-of-args
- 结果列表构造沿用 g_take 的 dummy head + s7_gc_protect_via_stack
  锚点模式，无 Scheme 回调，args 不会被求值器覆写
- 接入模式参考 liii_path.cpp：注册名 g_string-split + 库内别名
