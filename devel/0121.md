## 5. 2026-08-17 拆分 (liii http) 为三个模块

### 5.1 What
1. 新增 `goldfish/liii/http-common.scm`，存放 `(liii http)` 与 `(liii http-async)` 共享的代码：公共 API `http-ok?`，以及 `http-require-*`、`http-normalize-*` 等参数校验与规范化辅助函数。
2. `goldfish/liii/http.scm` 仅保留同步 API（`http-head`、`http-get`、`http-post`），从 `(liii http-common)` 导入辅助函数，并 re-export `http-ok?` 保持向后兼容。
3. 新增 `goldfish/liii/http-async.scm`，提供异步 API（`http-async-get`、`http-async-post`、`http-async-head`、`http-poll`、`http-wait-all`），同样 re-export `http-ok?`。
4. 单元测试移动到对应目录：`http-ok-p-test.scm` 移至 `tests/liii/http-common/`，五个异步测试移至 `tests/liii/http-async/`，并更新 import；新增 `tests/liii/http-common-test.scm`、`tests/liii/http-async-test.scm` 模块索引，同步更新 `tests/liii/http-test.scm`。
5. 更新 demo：`demo/async_http_demo.scm` 改为导入 `(liii http-async)`，`demo/async_vs_sync_demo.scm` 同时导入两个模块。
6. 顺手修复预先存在的 import 缺陷：`tests/liii/http-async/http-async-get-test.scm` 与两个异步 demo 使用 `current-second` 但误导入 `(liii time)`（该库并不导出它），改为导入 `(scheme time)`。
7. `README.md`/`README_ZH.md` 模块表新增 `(liii http-async)`、`(liii http-common)` 条目。

### 5.2 Why
`(liii http)` 同时承载同步与异步 API，且异步功能依赖后台线程。拆分后使用方可以只引入同步客户端，模块职责更清晰，也便于后续分别演进。

### 5.3 How
辅助函数全部下沉到 `(liii http-common)` 并按需导出；`(liii http)` 与 `(liii http-async)` 通过 re-export `http-ok?` 保持原有调用代码不变（s7 的 define-library 支持 re-export 导入的绑定，`(liii base)` 已有先例）。

## 6. 2026-08-17 新增 DeepSeek 流式聊天 demo

### 6.1 What
1. 新增 `demo/demo_deepseek_chat.scm`：基于 `(liii http)` 流式 API（`:stream #t :callback`）的 DeepSeek 多轮对话 REPL，运行方式 `bin/gf demo/demo_deepseek_chat.scm`。
2. 配置从 `~/.deepseek.json` 读取（api_key / base_url / model），文件缺失或缺 key 时提示手动输入 API Key。
3. 流式输出：SSE 半行缓冲解析，内容每积累 100 个 UTF-8 字符 flush 一次到终端；流式回调每累计 100 字符写一条日志到 `/tmp/deepseek.log`。
4. 请求参数 `thinking: {"type": "disabled"}` 关闭 v4 系列模型默认开启的思考模式（否则响应会多一个 reasoning_content 阶段）。
5. 多轮对话：每次请求携带全量对话历史，且仅在请求成功后才把问答提交进历史，失败不污染历史。
6. 输入校验：非法 UTF-8 输入直接提示，不发起请求。

### 6.2 Why
为 `(liii http)` 的流式能力提供一个真实完整的示例，同时检验 `(liii json)` 序列化、`(liii logging)` 文件日志、`(liii path)` 等模块在真实场景下的配合。

### 6.3 How
- 用 `define-record-type` 组织三类数据：`config`（配置）、`stream-state`（单次请求的流式解析状态，`ask` 前整体重建即完成重置）、`chat-request`（请求体，经 `chat-request->json` 转成 alist/vector 结构后由 `json->string` 序列化，避免手工拼接 JSON 字符串）。
- SSE 按 `\n` 切分，不完整行留在 pending 与下一 chunk 拼接；0x0A 不会出现在 UTF-8 多字节序列中，按行拼接对多字节字符安全。
- `utf8-string-length` 遇到非法 UTF-8 字节会抛 value-error，兼作输入校验器。
