## 2026-08-18 gf pr 从 origin 远程获取仓库 URL 并改用 (liii subprocess)

### What
1. 去掉硬编码的 `pr-remote`（原写死 `git@github.com:MoganLab/goldfish.git`），新增 `pr-remote-url`，通过 `git remote get-url origin` 获取当前仓库的 origin 远程 URL；无 origin 时报错退出
2. git 命令执行从 `(liii os)` 的 `os-call` 迁移到 `(liii subprocess)` 的 `run` / `run-values`
3. 新增 `current-branch`：重复执行 `gf pr NUM` 时若正处于 `pr_<num>` 分支，先 `git switch --detach` 再删除重建，避免"无法删除被工作区使用的分支"
4. 日志格式调整：`remote: <url>`，每条命令前打印空行 + `-->` + `run: <完整命令>`
5. 新增单元测试 `tools/pr/tests/liii/goldpr/pr-remote-url-test.scm`（4 个用例）

### Why
`gf pr` 写死了 goldfish 仓库地址，在 mogan 等其他仓库中使用时会在错误的远程上找 `pull/<num>/head`，报 `PR #<num> not found on remote`。

### How
- `pr-remote-url` 用 `run-values` 执行 `(list 'git "remote" "get-url" remote)` 并 `:stdout 'capture`；注意 `(liii subprocess)` 的命令列表必须写成"符号 + 字符串"形式，C 层（src/liii_subprocess.cpp）会静默丢弃列表中的符号参数
- 捕获的输出需用 `string-trim-both` 去首尾空白：`(liii string)` 的 `string-trim` 是 SRFI-13 语义，只去左侧空白，残留的尾部换行会拼进 fetch 命令导致失败

## 2026-08-17 之前的提交和任务描述

### What
1. 新增 `tools/pr/liii/goldpr.scm`，实现 `(liii goldpr)` 库，导出 `main`/`parse-pr-args`/`run-pr`
2. 在 `gfproject.json` 中注册 `pr` 工具（organization: liii, module: goldpr）
3. 新增参数解析单元测试 `tools/pr/tests/liii/goldpr/parse-pr-args-test.scm`（9 个用例）
4. 删除被替代的 `bin/pr`（elvish 脚本）和 `bin/pr.bat`

### Why
`bin/pr` 依赖 elvish shell，Windows 上还需要 `pr.bat` 包装。改为 `gf pr` 子命令后跨平台一致，且与其他 gf 工具（doc/fmt/fix/code）保持同一套注册与分发机制。

### How
- `gf` 的子命令通过 `gfproject.json` 动态注册，C++ 侧（src/goldfish.hpp）自动加载 `tools/pr/` 下对应模块的 `main` 函数，无需修改 C++ 代码
- `parse-pr-args` 基于 `(liii argparse)` 解析命令行，要求恰好一个纯数字位置参数，否则返回 #f
- `run-pr` 复刻原 elvish 脚本逻辑：本地 `pr_<num>` 分支存在则先删除，然后 `git fetch --force git@github.com:MoganLab/goldfish.git pull/<num>/head:pr_<num>` 并 `git switch`；fetch 失败输出 `PR #<num> not found on remote` 并返回退出码 1
- `main` 的返回值即进程退出码（0 成功 / 1 失败）
