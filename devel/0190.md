## 5. 2026-09-22 规划引入 (liii regex) 正则表达式支持

### 5.1 What
1. 建立 `(liii regex)` 库，为 Goldfish Scheme 提供标准实用的正则表达式处理能力。
2. 提供核心文本清洗与匹配的高频 API：
   - `(regex-match pattern str)`：尝试匹配整个字符串或前缀，成功返回 match-data，失败返回 `#f`；
   - `(regex-search pattern str)`：在字符串中检索匹配的子串；
   - `(regex-replace pattern str replacement)`：替换首个匹配项；
   - `(regex-replace-all pattern str replacement)`：全局替换所有匹配项；
   - `(regex-split pattern str)`：根据正则模式分割字符串。
3. 良好支持常见模式：
   - 支持字符串正则表达式或 Scheme SRE（Scheme Regular Expressions，如 SRFI-115）；
   - 保证多字节 UTF-8 字符（如中文、带圈数字、全角标点）的正确匹配，不发生字节错位或乱码。
4. 补充完整的单元测试和文档用例。

### 5.2 Why
在实际古籍清洗、日志解析、爬虫与转换脚本（如去除《史记》中的 `<1>`、`<23>` 等标签或带圈序号）场景中，缺少正则表达式是最大的开发瓶颈。开发者被迫针对每一个特定模式手动编写数十行复杂且易错的状态机游标循环（`lookahead`、字符逐步比对）。引入标准 `(liii regex)` 库能让脚本编写效率产生质的飞跃。

### 5.3 How
1. 技术选型评估：
   - 路线 A：纯 Scheme 实现 SRFI-115（Scheme Regular Expressions），优势是完全可移植、支持丰富的 SRE 表达式且无额外编译依赖；
   - 路线 B：基于 Goldfish 已集成的轻量 C 库（如 tbox 内置的 regex 模块，或通过 C 胶水层绑定轻量 PCRE2/POSIX regex 引擎）；
2. 封装用户友好的顶级接口（`regex-search`、`regex-replace-all` 等），确保接口兼顾直观性与执行效率；
3. 全面覆盖单元测试与错误处理。
