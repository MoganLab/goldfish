# [0145] 修复 g_listdir 传入非字符串参数导致 gf 崩溃的问题

## 任务相关的代码文件
- src/liii_os.cpp
- tests/liii/os/listdir-test.scm
- demo/crash/README.md

## 如何测试
```bash
xmake b goldfish
bin/gf tests/liii/os/listdir-test.scm
```

预期：测试输出 `7 correct, 0 failed`。

## 2026-09-08 C++ 层为 g_listdir 增加参数类型检查

### What

1. `src/liii_os.cpp` 的 `f_listdir` 入口处增加类型守卫：`path`
   （第 1 参数）不是 string 时返回
   `s7_wrong_type_arg_error(sc, "listdir", 1, path_arg, "a string")`。
2. 顺带修复同一函数内空字符串参数的越界读取：
   `path_s[path_N - 1]` 在 `path_N == 0` 时是未定义行为，
   改为 `path_N > 0` 时才取末字符。
3. `tests/liii/os/listdir-test.scm` 增加 3 个 C 层入口参数类型回归测试
   （`(g_listdir 99)`、`(g_listdir 'dir)`、`(g_listdir #t)`）。
4. 崩溃片段 `demo/crash/c11-g_listdir-integer.scm`
   （`(g_listdir 99)`）修复验证完成后移除。

### Why

`bin/gf demo/crash/c11-g_listdir-integer.scm`（即 `(g_listdir 99)`）会让
进程 abort（SIGABRT, exit 134）。根因在 C++ 层：`f_listdir` 直接
`s7_string(s7_car(args))`，垃圾指针后续进入 `std::string` 构造，
抛出未捕获的 `std::logic_error`。

`(liii os)` 公开包装 `listdir` 已有检查（`%check-dir-andthen`），
本修复使根环境直接调用 `g_listdir` 的代码也受保护。

修复前运行新测试会直接 abort（TDD 红灯），修复后 7/7 通过。

### How

与 devel/0142.md 相同的模式：C++ 入口先 `s7_is_string` 检查，非字符串走
s7 标准的 `s7_wrong_type_arg_error`。
