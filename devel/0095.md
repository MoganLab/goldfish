## 2026-08-06 迁移 20 个 let 相关函数到 (scheme let)

### What
1. 新增 `goldfish/scheme/let.scm`，定义 `(scheme let)` 库，导出 20 个
   scheme_let.c 实现的 let 相关函数：
   `let?` `openlet?` `funclet?`（谓词）
   `curlet` `outlet` `rootlet` `owlet` `funclet`（环境获取）
   `inlet` `sublet` `varlet` `cutlet` `openlet` `coverlet` `unlet`（环境构造与操作）
   `let-ref` `let-set!` `let->list`（绑定访问）
   `symbol->value` `symbol->dynamic-value`（符号查找）
2. 从 `goldfish/liii/base.scm` 的 export 列表移除上述 20 个函数
   （`defined?` 在 0092 之前就属于 `(liii base)` 的通用工具函数，保留不动）。
3. 将 20 个测试文件从 `tests/liii/base/` 迁移到 `tests/scheme/let/`，
   import 由 `(liii base)` 改为 `(scheme let)`。
4. 新增 `tests/scheme/let-test.scm` 模块概览文档，`gf doc scheme/let` 可用。
5. `bin/gf doc --build-json` 重建索引后，20 个函数均归属 `(scheme let)`；
   `bin/gf test --all` 共 1493 项全部通过。

### Why
这 20 个函数由 src/s7_scheme_let.c 实现（0092 从 s7.c 拆出），是 S7 的
环境操作 API，放在 `(liii base)` 只是过渡；独立的 `(scheme let)` 库
边界更清晰，与 `(scheme eval)` 等库的风格一致。

### How
- **空 begin 即可导出**：`define-library` 的库体在 `(sublet (unlet))`
  环境中求值，s7 内建函数天然可见，export 只需列名字（同 `scheme/cxr.scm`
  的先例），无需 import 或重新定义。
- **移除 export 不破坏依赖方**：`(liii case)` 等在库体内使用 `funclet`/
  `curlet`/`symbol->value`，库体环境继承自 unlet，与 import 无关；
  脚本顶层环境是 rootlet，同样不受影响。gf REPL 预 import `(liii base)`
  也不受影响。
- **测试文件即文档**：golddoc 按 `tests/<group>/<library>/<func>-test.scm`
  定位文档，`git mv` 到 `tests/scheme/let/` 并改 import 后即完成迁移。
