## 2026-08-08 用 C 实现 any / every / find

### What
1. 在 bench/any-every-find.scm 中对原 Scheme 实现做性能基线评测
2. 在 src/s7_liii_list.c 中新增共用的 any_every_find_loop 及 g_any / g_every / g_find，
   并在 src/s7.c 中注册
3. goldfish/srfi/srfi-1.scm 中 `(define any g_any)`、`(define every g_every)`、

### Why
any / every / find 是列表处理高频谓词循环，原实现每个元素都多走一层 Scheme
递归调用。加速比低于 filter（~6x）是因为单元素成本由 pred 回调本身主导，
C 化消除的是递归骨架开销。最终目标是让 mogan 的 exists?（168 处调用）/
forall?（13 处）/ list-find（79 处）直接落到这三个原生实现上。

### How
- 单次遍历，短路语义与原实现一致：any 命中即归一化返回 #t，every 遇假即返 #f，
  find 返回元素本身；空列表分别返回 #f / #t / #f 且不调用 pred
- 点列表在遍历到非 pair 尾部时抛 wrong-type-arg（与原 Scheme 实现行为一致，
  测试用不命中/不短路的谓词固化，避免短路绕过尾部检查）
- GC 安全沿用 g_filter 的模式：args 可能住在求值器复用的临时 cell 里，
  把 pred/lst 复制进自己分配的 anchor pair 并 s7_gc_protect_via_stack 保护
- 与 g_filter 不同，这里不构造结果列表，anchor 只需一对 cons
- any 归一化为 #t（而非返回 pred 真值）是有意为之：保持 goldfish any 既定
  语义，同时免去 Scheme 层包装，直接别名零开销；mogan 侧 exists? 语义为
  谓词用法，返回值归一化同样适用

### 方案讨论：g_any 返回 #t 还是 pred 真值（已定稿）
- SRFI-1 canonical any 返回 pred 的真值，但 goldfish 既有实现与文档均归一化为 #t
- 曾实现「g_any 返回真值 + Scheme 层 if 归一化」，基准显示短列表/短路场景
  包装开销抵消收益（首部命中场景 0.0065 → 0.0097 秒，反而退化）
- 定稿：C 侧直接归一化返回 #t，srfi-1 直接别名
