## 日期 任务描述

### What
1. 把 expander kernel 从"平铺源码 + 清单（load-kernel.scm）"改造为正式 R7RS 库：新增 `goldfish/expander/kernel.scm`，`(define-library (goldfish expander) (export ...205 个名字...) (begin (include ...) ...))`。2. define-library 机制支持 R7RS `include` 子句（顶层与 begin 内均可，递归拼接）。
3. build-combined.scm 自举构建从"读清单拼 forms 当做一个程序展开"改为"经 parse-library-clauses（含 include）+ expand-library-body 展开 kernel.scm 库"；不产生运行时模块注册表达式（kernel 即 base 库，artifact 加载时模块层尚未就绪）。
4. `(import (goldfish expander))` 正式接入：`load-library!` 对 base-library 名短路（注册活绑定记录 + 标记 runtime-registered），此前走 `library-record` 特判可 import 但 `load-library!` 报错。
5. driver.scm 的 `(load-source-file install.scm)` 移至 load-kernel.scm（bootstrap-0 便利），driver 的 module-define! 注册随库体进入工件。
6. 重建工件（665 forms），fixpoint 验证：冷缓存下连续 from-artifact 构建产物逐字节一致（自举不动点成立）；from-source（bootstrap-0）与 from-artifact 产物语义等价（仅内部 gensym 编号不同）。

### Why
kernel 是 expander 本体，此前没有库身份：无导出面、依赖隐式、运行时每次由 s7 解释预展开工件。库化让 kernel 以正式 R7RS 库存在（自文档 API 面、显式依赖、可被 expander 自身展开），构建成为真正的库级 fixpoint 自举，并为"用户代码 import (goldfish expander)"提供正式入口。

### How
- include 子句在 parse-library-clauses 处理：对 `(include "file")` 子句 splice 文件 forms 后重处理；对 `(begin ...)` 子句递归拼接内部 include 后保留为单个 body 子句（避免重处理死循环）。注意子句是 syntax 树，拼接前需 `syntax->datum`。
- 自举构建直接复用 parse-library-clauses + expand-library-body（而非 expand-define-library）：后者会附加运行时模块注册表达式，但 artifact 在模块层（install.scm）加载前执行，注册引用 `runtime-registered-add!` 会 unbound。kernel 的身份由 artifact 的 rootlet 重绑定 + driver module-define! + load-library! 短路共同确立。
- 导出面是"公共 API"（205 个源码顶层 define）；宏展开生成的内容访问器（如记录选择器）不在导出列表，但重绑定覆盖全部 toplevel 绑定，运行时语义不变。build 校验导出名不产生 primitive 回退（防导出表笔误）。

## 已知边界
- seed 别名（bytevector? 等）保留为宿主 ABI：artifact 由 s7 执行，R7RS 名必须以宿主名存在；与库化无直接关系。
- 热缓存下重建工件内部 gensym 编号可能漂移（lib-layer 宏缓存既有行为），冷缓存 fixpoint 成立。
- `(liii base64)` 加载失败（&match 宏卫生 bug）为既有问题，本任务未触碰。

## 日期 后续修复：rootlet ABI 注入 + 默认关闭 VM transformer

### What
1. **rootlet ABI 注入**（module.scm `install-rootlet-abi!`）：r7rs-small 纯 syntax 改造（删除 Phase 1 varlet import）后，s7 宿主环境失去 (scheme base) 的 R7RS 名，而三处消费方按 rootlet 解析：s7 求值的引导代码（reader 的 `#u8(...)` 解析用 `exact-integer?`）、primitive-by-name 裸名引用、缓存工件 `(eval d (rootlet))`。修复：`(scheme base)` 经 expander 加载后，将其 toplevel 值绑定注入 rootlet（含覆盖 seed 的坏 `floor/`）。验证：`#u8(1 2 3)` 读取、`(floor/ 5 2)`、`(min ...)` 全部恢复。
2. **默认关闭 VM transformer 编译**（install.scm `compile-transformer-to-program`）：VM 编译的 transformer 若 body `apply` 了 VM 闭包（所有 s7 define-macro transformer，如 (liii base) typed-lambda），VM 重入 bug 使输出不包 syntax → 缓存重建后"macro output is not a syntax object" → 毒化共享 ccache（并行/顺序复现 `((srfi srfi-151))` 库名作为宏输出）。修复：默认走 lowered+eval 路径（正确），`GOLDFISH_VM_TRANSFORMER=1` opt-in VM 路径待修 bug。
3. 验证：并行 `gf test tests/scheme/base -j 6` 从 ~20 失败 → 215/215 通过；typed-lambda/srfi-151/boolean-eq-p 全恢复；fixpoint 构建稳定。

### Why
32c37ca8（r7rs-small 纯 syntax）删除了 Phase 1 varlet 注入，连带移除了宿主 ABI 面；a47ea0ac（VM transformer 编译）引入了缓存毒化路径。这两个回归影响所有含 `#u8` 字面量的测试与并行测试基础设施。

### How
- ABI 注入：`(scheme base)` 库加载完成（load-library! 末尾）后，遍历其 exp-library 的 toplevel 绑定，`(eval (list 'define name (toplevel-ref-gensym ref)) (rootlet))`；幂等（flag），每个 define 带 catch（部分导出是 s7 常量不可重绑定）。
- VM 关闭：`compile-transformer-to-program` 默认返回 #f（缓存存 lowered 形式），重建走 `(eval data ...)`；最小复现 `(apply <vm 闭包> ...)` 在 VM 内执行返回裸 datum（`syntax?` 为 #f），而 lowered+eval 路径正常。

## 日期 宿主 ABI 收编（单一来源）

### What
1. 新建 `goldfish/liii/host-abi.scm`：R7RS 值面单一来源——base.scm 的 58 个值定义（移到此处）+ s7 宿主完全缺失的 46 个 R7RS 名（min/max 已由 base.scm 覆盖；新增实现：string-upcase/downcase/foldcase、char 大小写/分类/ci 比较、string-ci、bytevector-copy!、make-promise/promise?、字节 I/O（read-u8/peek-u8/write-u8/write-bytevector/read-bytevector!/open-input-bytevector/open-output-bytevector/get-output-bytevector）、write-shared/write-simple、环境与时间（command-line/get-environment-variable(s)/environment/current-second/current-jiffy/jiffies-per-second））。纯 s7 可加载（无 expander 依赖），seed 与 base.scm 共用。
2. seed 加载：`bootstrap_scheme_reader`（src/liii_reader.cpp）新增 `tiny_load_path` 加载 host-abi.scm（rootlet）。
3. base.scm：值定义替换为 `(include "liii/host-abi.scm")`，保留宏面（let-values/define-values/define-record-type/guard）。
4. 删除 workaround：module.scm 的 `install-rootlet-abi!` 注入与 load-library! 钩子；boot.scm 散落的 8 个别名与坏 `floor//truncate/`（引用未绑定名）；`bytevector->u8-list`/`u8-list->bytevector` 移入 host-abi.scm。
5. 修复存量 bug：`(string-upcase ...)`、`(finite? ...)` 等 46 名此前经导出回退为 primitive 裸名 → rootlet 缺失 → 完全不可用，现已实现。

### Why
r7rs-small 纯 syntax 改造（32c37ca8）删除了 Phase 1 varlet 注入，但未建立显式宿主 ABI 替代；a6ec3410 的运行时注入是 varlet 的镜像 workaround（时序脆弱、与 base.scm 定义重复）。宿主 ABI 收编为单一来源：host-abi.scm 由 seed（rootlet）与 base.scm（include）共用，无注入、无镜像、无时序问题。

### How
- ABI 全集 = 需要以裸名解析的 R7RS 值名：primitive-by-name（install-primitives! 267 名）与 (scheme base) 导出回退中 s7 rootlet 缺失的并集。枚举探针确认 46 个需全新实现（其余 s7 默认环境或 glue 已有，host-abi 直接定义/别名）。
- 实现来源：char 大小写/分类用 glue（g_char-upcase 等）+ Scheme 补缺；字节 I/O 借用 s7 字符端口（字节=码点 0-255 的字符）；时间用 g_get-time-of-day；环境用 g_command-line/g_getenvs；promise 用 seed 的 make-lazy-promise/force 表示。
- 验证：并行 scheme/base 215/215、scheme 目录 290/290、全套件 48/50（仅既有的 2 个 match 卫生 bug）、fixpoint 构建稳定、#u8 读取正常。
