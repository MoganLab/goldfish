## 2026-08-16 L2-1 编译 pass 管线验证
### What
L2（自研运行时替换 s7 eval）的第一步验证：自研编译 pass 能否处理 expander 产物。

1. 新增 `(goldfish compiler)` 库，定义 pass 管线框架：
   - `run-passes` : sexp (list pass) -> sexp，按序应用 pass
   - `compile-defs` : defs (list pass) -> defs，对展开后的库 defs 逐条应用管线
2. 实现第一个 pass `constant-fold`：递归折叠 `*foldable-functions*` 表中的纯函数调用
   （+ - * quotient remainder modulo abs min max expt 比较 字符串 字符 布尔等），
   参数全为常量时求值替换；quote/quote-syntax 内容作为数据永不进入。
3. 实现第二个 pass `simplify-if`：`(if #t t e)` -> t，`(if #f t e)` -> e，
   同时是第一个死代码消除。
4. 系统级等价验证：capture-library-cache 展开真实库（srfi-1）得到 48 个 defs，
   跑管线后 5 个 defs 被改写（`(if #f #f (if #f #f))` 死分支消除等），
   原/编译 defs 分别 eval 到独立 inlet，take/drop/append-map/find 调用结果一致。

### Why
L2 有三条路线（字节码 VM / 编译到 C / 解释器优化），共同前置是"自研代码能
处理 expander 产物"。本任务验证这条路径：pass 输入是 lower 后的核心 IR
（define/lambda/if/begin/set!/call-with-values/values/quote），输出仍可被 s7 eval，
不改动宿主求值器，风险低可回退。后续 L2 换后端时 pass 管线原样复用。

### How
- pass 输入层选择 lower 后的纯 sexp（datum 层）：scope 信息在展开时已固化，
  编译阶段不需要，且便于 write 验证与 diff 比较。
- `*foldable-functions*` 只收录**全函数且无副作用**的 primitive：折叠绝不允许把
  运行期错误变成编译期错误，也不允许改变可观察行为；`catch` 保护折叠本身
  （如 `(expt 2 100000)` 溢出），任何错误保留原形式。
- 折叠结果用 `self-evaluating?` 判断：数字/字符串/字符/布尔/空表/EOF 直接输出，
  其余（符号/列表/向量）用 `quote` 包装。
- 等价验证的关键：defs 的 define 名是带 scope 后缀的 gensym（如 `take:15`），
  编译不改名，因此原/编译 defs eval 到两个独立 `(inlet)` 后，同名绑定可直接
  构造调用比较——无需处理导出名到 gensym 的映射。
