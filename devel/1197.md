## 5. 2026-11-23 修复 review 发现的五个高优先级往返缺陷

### 5.1 What
分支 `da/1197/stem_to_md` review 发现的高优先级问题清单，以下缺陷均已实测复现：

1. 相邻 em/strong/strikeout 定界冲突：正向可达输入完整往返损坏，嵌套场景误报错。
2. 自动链接判定过宽：链接内容丢失或变成 raw HTML 块。
3. `&` 实体未转义：反向输出被正向解析再解码，文本改变。
4. 行首转义被空串首项击穿：段落变成列表/标题。
5. `!` + link 合并为 image：escaped `!` 变体正向可达且未登记例外。

### 5.2 Why
多数缺陷的输入可由正向解析（`markdown->md-stem`）产生，属于真实可达的语义往返损坏，
与 `(liii cmark markdown)` "非法输入报 md-stem-error，不静默丢弃内容" 的契约相悖。
逐项复现与根因：

**（1）相邻 em/strong/strikeout 定界冲突**

```scheme
;; 完整往返损坏：正向可达
(markdown->md-stem "_a_*b*")            ; => (md-stem (p (em "a") (em "b")))
(md-stem->markdown '(md-stem (p (em "a") (em "b"))))
;; => "*a**b*\n"，重解析为 (p (em "a**b"))，语义改变

;; strong 嵌套内的相邻 em：直接报错，但本可安全渲染
(md-stem->markdown '(md-stem (p (strong (em "a") (em "b")))))       ; => md-stem-error
(md-stem->markdown '(md-stem (p (link "/u" "" (em "a") (em "b"))))) ; => md-stem-error

;; strikeout 完全没有 prev 防护
(md-stem->markdown '(md-stem (p (strikeout "a") (strikeout "b"))))
;; => "~~a~~~~b~~\n"，重解析为 (p (strikeout "a~~~~b"))
```

根因：`%render-inline-items-state` 计算了 `prev`，但 `render-emphasis-inner` 与
`%render-strikeout` 递归时重置状态；`delims` 参数全链路从未被消费（死参数）。
段落/标题路径走 `render-paragraph-inlines` → `%render-inline-item`，完全无状态。
`choose-1char-delim` 逻辑有洞：prev 尾为 `*` 且内部无尾随星号时直接返回 `#f` 报错，
而改用 `_` 定界本可安全输出。

另外 e2e-directions.scm 中 Example442/444/445 登记的理由（"转义后开标记游程冲突，
无法往返"）不成立：实测 `\*_foo_`、`\*__foo__` 均能正确解析回
`(p "*" (em "foo"))` / `(p "*" (strong "foo"))`。

**（2）自动链接判定过宽**

```scheme
;; 合法 CommonMark，正向可达；em 内容直接丢失
(markdown->md-stem "[ab*x*](ab)")
;; => (p (link "ab" "" "ab" (em "x")))
;; 反向输出 "<ab>\n"，重解析为 (raw-block "html" "<ab>")

;; 相对 URL 不是合法 autolink
(md-stem->markdown '(md-stem (p (link "/url" "" "/url"))))
;; => "</url>\n"，重解析为 raw HTML 块

;; autolink 内不允许反斜杠转义，输出碎片
(md-stem->markdown '(md-stem (p (link "http://a<b" "" "http://a<b"))))
;; => "<http://a\\<b>\n"，重解析为 link + raw-inline 碎片
(md-stem->markdown '(md-stem (p (link "http://a b" "" "http://a b"))))
;; => "<http://a b>\n"，重解析为 (p "<" (link ...) " b>")
```

根因：`link-autolink?`（inline.scm）只拼接 children 中的字符串、忽略结构节点；
不校验 URL 是否满足 autolink 语法（scheme / email、无空白、无 `<>\`）。

**（3）`&` 实体未转义**

```scheme
(markdown->md-stem "&amp;copy;")        ; => (md-stem (p "&copy;"))
(md-stem->markdown '(md-stem (p "&copy;")))
;; => "&copy;\n"，重解析为 (p "©")，文本被再解码
```

根因：`escape-text` 不转义 `&`；stem 文本中形如 `&name;` / `&#123;` / `&#x1F;`
的片段反向输出后被正向解析重新解码。
注意 Example14 的例外只覆盖"实体形式丢失"，不覆盖本问题，修复后 Example14
仍保留 forward-only。

**（4）行首转义被空串首项击穿**

```scheme
(md-stem->markdown '(md-stem (p "" "- x")))
;; => "- x\n"，重解析为 bullet-list
(md-stem->markdown '(md-stem (p "" "# x")))
;; => "# x\n"，重解析为 h1
```

根因：`%render-inline-items-state` 的 `first?` 只看第一个 item 而非第一个
非空渲染结果；`render-paragraph-inlines` 的 line-start 状态同样被空串消耗。

**（5）`!` + link 合并为 image**

```scheme
(markdown->md-stem "\\![t](/u)")        ; => (md-stem (p "!" (link "/u" "" "t")))
(md-stem->markdown '(md-stem (p "!" (link "/u" "" "t"))))
;; => "![t](/u)\n"，重解析为 (p (image "/u" "" "t"))
```

根因：文本项 `"!"` 紧邻 link 节点时原样输出，与 `[` 合并成图片语法。
Example593 登记的是 `!` + 无效链接同形问题，本变体（转义 `!` 后跟有效 link）
没有条目，且可修。

### 5.3 How
1. **prev 状态贯穿所有渲染路径**（段落、标题、link 文本、表格单元格、嵌套递归），
   删除无用的 `delims` 参数或真正使用它。prev 尾字符与候选定界冲突时切换
   星号/下划线家族，两者都不可行才报 md-stem-error；strikeout 增加同样的
   相邻防护（prev 尾为 `~` 时报错或规避）。修复后删除 Example442/444/445
   条目并复核 Example417。
2. **收紧自动链接化条件**，必须同时满足：children 全部为纯字符串（含任何
   结构节点则回退内联形式）；URL 满足 CommonMark autolink 语法
   （`scheme:...`，scheme 以字母开头后跟字母/数字/`+.-`，或合法 email），
   不含空白、控制字符与 `<` `>` `\`。不满足则一律输出 `[文本](url)` 内联形式。
3. **`%escape-with` 转义可能开启实体引用的 `&`**：输出 `\&`
   （实测 `\&copy;` 正向解析回 `"&copy;"`，可安全往返）。保守起见可转义
   所有 `&`，或仅当后跟 `[A-Za-z#]` 时转义。
4. **line-start 上下文持续到第一个非空渲染片段**：空字符串项不消耗
   line-start 状态，`%render-inline-items-state` 与 `render-paragraph-inlines`
   两条路径都要修。
5. **`!` 尾文本紧邻 link 时输出 `\!`**：利用 prev 状态，文本项以 `!` 结尾
   且下一项是 link 时补转义（或渲染 link 前检查 prev 尾字符为 `!`），
   与第 1 项的 prev 贯穿改造一并实现。
