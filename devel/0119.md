## 2026-08-15 string->json 替换为 C++ 实现 g_string->json，提升性能

### What
1. 在 `src/liii_json.cpp` 中新增 `g_string->json`，语义与原 (guenchi json) 的 Scheme 实现完全一致：
   - 沿用「改写 + read」算法：C++ 逐字节扫描，把 `{ } [ ] : ,` 改写为 Scheme 可读形式后交给 s7 reader
   - 只在分隔符处落盘：最后一个分隔符之后的内容被丢弃（故顶层标量解析为 eof-object）
   - 上下文栈初始为 `(#t)`，空栈顶按真值处理（对应 `loose-car`/`loose-cdr` 语义）
   - 转义处理一致：`\" \\ \b \f \n \r \t` 原样保留交由 reader，`\/` 变为 `/`，`\uXXXX` 直接展开为 UTF-8 字节（含代理对合并，码点编码规则与 (liii unicode) 的 `codepoint->utf8` 一致，不排斥代理区码点）
   - 错误类型一致：非法转义/非法 hex/hex 过短抛 `parse-error`；码点越界抛 `value-error`；输入不完整由 reader 抛 `read-error`；非字符串输入抛 `wrong-type-arg`
2. `(guenchi json)` 移除 `string->json` 的导出与 Scheme 实现（含私有辅助函数 `handle-escape-char`、`string-length-sum`、`fast-string-list-append`），仅在 `(liii json)` 中导出 `string->json`（绑定到 `g_string->json`）。
3. 扩充 `tests/liii/json/string-to-json-test.scm`：新增顶层标量、空白容忍、尾部忽略、数字（浮点/指数/大整数）、嵌套结构、宽松语法、字符串内容、截断与非法输入等 30 余条用例（先以原 Scheme 实现验证语义，再切换 C++ 实现回归）。
4. 新增 `bench/string-to-json-perf.scm`，同进程对比 C++ 与历史 Scheme 实现（含正确性 sanity check）。

### Why
`string->json` 是 JSON 解析的热路径，原 Scheme 实现逐字符执行 `cond`/`case` 循环并在每个分隔符处做 `substring` + `string-append`，解释执行开销大。

### How
不改写算法、只在 C++ 中复刻同一套「改写 + read」流程，从而按构造保证语义逐字节一致：
- C++ 侧用单次扫描直接拼接 `std::string`，消除 Scheme 解释循环、分段 substring 和 `fast-string-list-append` 的分配开销；
- 数字、符号、引号等 token 的解析仍由 s7 reader 完成，凡是 reader 接受的历史输入（宽松键、`#t`、有理数等）行为不变；
- `\u0000` 可能在改写结果中嵌入 NUL 字节，因此不使用基于 C 字符串的 `s7_open_input_string`，而是用 `s7_make_string_with_length` 构造定长字符串后经 `open-input-string` + `s7_read` 读取，与原实现完全等价。

性能对比（Windows，release 构建，bench/string-to-json-perf.scm）：

| 场景 | C++ | Scheme | 加速比 |
|---|---|---|---|
| 对象（200 键） | 0.0041s/200 次 | 0.0744s/200 次 | ~18x |
| 数组（200 元素） | 0.0017s/200 次 | 0.0263s/200 次 | ~16x |
| 转义密集（50 字符串，含 \n \t \\ \/ \u 代理对） | 0.0022s/200 次 | 0.1902s/200 次 | ~85x |
| 嵌套结构 | 0.0039s/2000 次 | 0.0691s/2000 次 | ~18x |
