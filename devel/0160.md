## 2026-09-08 移除 3rdparty/nlohmann_json/ 并将 gfproject 逻辑迁移至 Scheme

### What
1. 移除 `3rdparty/nlohmann_json/` 源码目录与 `xmake/packages/n/nlohmann_json/` 本地包脚本，清理 `xmake.lua` 中全部 `nlohmann_json` 依赖配置。
2. 新增 Scheme 模块 `(liii gfproject)`（`goldfish/liii/gfproject.scm`），将 `gfproject.json` 的查找、读取、解析、字段级深度合并、工具路由解析（包含 local override 失败时的单命令回退机制）以及动态工具准备与执行（`main` 调用）全部迁移至 Scheme 原生实现。
3. 大幅精简 C++ 侧（`src/goldfish.hpp`）：移除 `#include <nlohmann/json.hpp>`、`using nlohmann::json;` 以及所有 C++ 侧 JSON AST、深合并与工具查找函数（清理超 300 行 C++ 冗余代码），C++ CLI 路由直接调用 Scheme 侧的 `(gfproject-run-tool ...)`。
4. `tools/help/liii/goldhelp.scm` 直接复用 `(liii gfproject)` 获取配置，无需再通过 C++ dump 字符串进行双重解析。
5. 新增单元测试 `tests/liii/gfproject-test.scm`。

### Why
1. 彻底解耦 C++ 底层对外部第三方 JSON 库的依赖，减小解释器二进制体积；
2. 消除此前“C++ 读入解析 -> C++ 合并 -> C++ dump 回字符串 -> Scheme 再次 string->json 解析”的双重解析冗余；
3. 符合 Scheme 哲学，利用已有的 `(liii json)` 高性能接口与表达力更强的 Scheme 代码管理工具注册与分发。

## 2026-09-08 移除 (liii njson) 模块及相关代码

### What
1. 移除 Scheme 层的 `(liii njson)` 模块（`goldfish/liii/njson.scm`）及其测试（`tests/liii/njson-test.scm`、`tests/liii/njson/`）与 bench 代码（`bench/*njson*`）。
2. 移除 C++ 实现 `src/liii_njson.cpp`，在 `src/goldfish.hpp` 中移除 `glue_njson` 注册调用与声明，清理 `src/liii_json.cpp` 中相关注释。
3. 移除仅被 njson 使用的 `json_schema_validator` 依赖包、构建配置与 `3rdparty/json-schema-validator` 源码。
4. 将 `tools/doc` 索引生成和读取全面迁移至标准 `(liii json)` 模块，替换关联测试用例中的 njson 样例。
5. 更新 `README.md` 与 `README_ZH.md`。

### Why
统一 JSON 处理接口，减少底层冗余依赖与二进制体积，保持 Goldfish 核心库精简。
