## 2026-08-24 方案调整：备份并整体替换 settings.json（替代 --settings 参数）

### What
1. `gf code --profile bigmodel` 启动前：若 `~/.claude/settings.json.gf-backup`
   不存在，先把当前 `settings.json` 备份到该路径；再将
   `settings.json.bigmodel` 整体复制为 `settings.json`，然后调用
   `claude --dangerously-skip-permissions`
2. claude 退出后不做恢复，settings.json 保留 profile 内容；
   原始配置始终在 `settings.json.gf-backup`，需要时可手动拷回
3. backup 已存在时不覆盖，避免把上次替换进来的 profile 内容当成原始配置备份
4. 新增 `backup-settings!` / `claude-settings-path` / `backup-settings-path`，
   并配套单元测试
5. 启动前打印实际执行的 claude 命令

### Why
`claude --settings` 是在默认 `~/.claude/settings.json` 之上**合并**加载，
不是替换。默认 settings 中未被 profile 文件覆盖的键（如 `ANTHROPIC_MODEL`）
会残留生效，导致 BASE_URL 已切换但模型仍指向旧服务商，profile 切换不完整。

### How
- `backup-settings!`：settings 存在且 backup 不存在时复制 settings 为 backup
- `launch-claude`：备份后用 `path-copy` 将 profile 文件整体覆盖 settings.json，
  再 `os-call` 启动 claude，退出后不恢复
- 注意：goldfish 的 `guard` 宏在 body 成功返回时也会走 `else` 分支，
  不能用它做"异常时恢复"的兜底

## 2026-08-24 之前的提交和任务描述

### What
1. `bin/gf code --profile bigmodel`（或 `-p bigmodel`）启动 Claude Code 时加载
   `~/.claude/settings.json.bigmodel`，即执行
   `claude --dangerously-skip-permissions --settings <该文件>`
2. 未指定 profile 时维持原行为（加载默认的 `~/.claude/settings.json`）
3. 指定的 settings 文件不存在时打印错误并以退出码 1 结束，不启动 claude
4. 新增可测试的纯函数 `parse-profile-args` 和 `profile-settings-path`

### How
- `parse-profile-args` 扫描 `(command-line)` 参数列表，提取 `--profile NAME` 或 `-p NAME`
- `profile-settings-path` 基于 `(liii path)` 的 `path-home` 拼接
  `~/.claude/settings.json.<profile>` 路径
