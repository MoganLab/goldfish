# Native runtime layers

Goldfish runs on its native evaluator. Vendored S7 and the S7 host/oracle were
removed during R4; the migration history and remaining compatibility surface
are recorded in `RUNTIME_CONTRACT.md` and `CORE-SEMANTICS.md`.

The Scheme pipeline remains layered and follows one-way dependencies:

```text
CLI / loader → evaluator → compiler → expander libraries → kernel → core IR
```

## Runtime and language pipeline

- **Native runtime** (`src/runtime/`): `Value`, heap/GC, environments, reader,
  core evaluator, continuation control machine, primitive implementations,
  artifact loading, and bootstrap. `src/runtime/native_main.cpp` is the `gf`
  executable entry point. No runtime source includes an S7 header or links an
  S7 implementation.
- **L1 reader/bootstrap**: `src/runtime/reader.cpp` reads source and lowered
  datums. `goldfish/liii/boot.scm` establishes the early library loading path.
- **L2 core contract**: `goldfish/core/ir.scm` defines the 14 lowered core
  forms. The native evaluator implements this contract; the frozen inventory
  is `tools/substrate-baseline.txt`, regenerated by
  `tools/freeze-substrate.sh`.
- **L3 expander kernel**: `goldfish/expander/kernel/` and the generated
  `kernel-combined.scm`. Rebuild with `sh tools/build-kernel.sh` after kernel
  source edits.
- **L4 expander libraries**: syntax-case, reader integration, and tree-IL
  lowering live under `goldfish/expander/` and `goldfish/liii/reader.scm`.
- **L5 compiler**: pure Scheme transformations under `goldfish/compiler/`;
  it consumes the shared core IR and does not depend on runtime internals.
- **Library layer**: R7RS, SRFI, and `(liii ...)` sources are ordinary Scheme
  libraries. Runtime-owned mechanisms stay in C++; library policy and
  orchestration belong in Scheme.

## Bootstrap and validation

The native bootstrap reads source, loads the core and kernel artifacts, starts
the expander, then loads libraries through the native runtime. Warm and cold
bootstrap paths are checked by `tools/test-native.sh` and
`tools/test-native-c3.sh`.

`sh tools/lint-layer.sh` checks the frozen core-form inventory, rejects S7
headers/types in runtime sources, and checks compiler/expander dependency
boundaries. C2 host/native counts and skips are historical migration evidence;
they are archived in `tests/C2-ACCEPTANCE.md`, with the reviewed skip scope in
`tests/c2-skip.tsv` and `tests/C3-SKIP-DISPOSITIONS.tsv`.

The native bootstrap still carries a small set of migration compatibility
bindings for existing lowered artifacts. They are not a dependency on S7 and
are tracked separately in `RUNTIME_CONTRACT.md` for future removal or
replacement.
