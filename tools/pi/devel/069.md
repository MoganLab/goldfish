## 2026-10-21 任务描述

### What

1. **根因定位**：
   在任务 068 引入跨平台控制台 Raw 模式后，Windows 平台的 `f_console_getch` 实现为：
   ```cpp
   static s7_pointer
   f_console_getch (s7_scheme* sc, s7_pointer args) {
   #ifdef TB_CONFIG_OS_WINDOWS
     int ch = _getch();
     return s7_make_integer(sc, ch);
   #else ...
   ```
   `_getch()` 是 Windows CRT 提供的阻塞式字符读取函数。在单元测试 `tests/liii/os/console-raw-mode-test.scm` 第 4 项中：
   ```scheme
   (let ((c (console-getch)))
     (check-true (or (boolean? c) (exact-integer? c)))
   )
   ```
   测试用例在非交互无输入环境下直接调用 `(console-getch)`。Linux 平台通过 `read(STDIN_FILENO, &ch, 1)` 返回 0 并安全降级为 `#f`，而 Windows 平台则直接挂起在 `_getch()` 上等待用户键盘敲击，导致本地 `bin/gf test --all -j 1` 及 GitHub Actions Windows CI 永久超时卡死。

2. **修复方案**：
   在 `src/liii_os.cpp` 的 `f_console_getch` 中，Windows 分支先通过 `_kbhit()` 检查键盘缓冲区：若 `_kbhit() == 0`（无就绪按键），直接返回 `s7_make_boolean(sc, false)`；仅当 `_kbhit() != 0` 时才调用 `_getch()` 读取并返回按键码。

3. **测试验证**：
   修复后重新编译运行，`tests/liii/os/console-raw-mode-test.scm` 由挂起超时变为即刻通过，断言正确接收 `#f`。
