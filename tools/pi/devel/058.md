### 架构约定与设计原则

1. **容器与 Component 协议对齐**：
   - 所有的布局容器（`make-box`、`make-vstack`、`make-hstack`）均实现标准的 `<component>` 协议（来自 `(liii tui component)`）；
   - `component-render` 接受给定的总渲染宽度 `width`，返回渲染后的行文本列表 `(list of string)`；
   - 交互输入下发 `component-handle-input`：容器将键盘输入事件按子组件次序下发，任一子组件消费（返回真）则中止派发；
   - 状态失效通知 `component-invalidate!`：级联触发所有包含子组件的 `component-invalidate!`。

2. **`make-box` 边框与内边距组件**：
   - 封装子组件（若传入字符串则自动提升为 `make-text` 组件）；
   - 支持边框风格配置（`:style`）：
     - `'single`：Unicode 单线（`┌ ┐ └ ┘ │ ─`）
     - `'double`：Unicode 双线（`╔ ╗ ╚ ╝ ║ ═`）
     - `'rounded`：Unicode 圆角线（`╭ ╮ ╰ ╯ │ ─`）
     - `'ascii`：纯 ASCII 字符（`+ + + + | -`）
     - `'none`：无边框（仅内边距 padding 效果）
     - 允许自定义边框字符定义列表；
   - 支持内边距配置（`:padding`）：
     - 单整数：统一设置上下左右内边距；
     - 细粒度支持：`:padding-top`、`:padding-bottom`、`:padding-left`、`:padding-right`；
   - 支持可选标题（`:title`）：嵌入顶部边框，展示形如 `┌─ Title ─┐`；
   - 宽度自适应与边界保护：
     - 内容区可用宽度为 `(- width border-left-right padding-left-right)`；
     - 当总宽度过窄（不足以容纳边框和内边距，或有效宽度 <= 0）时，提供安全保底渲染，不崩溃。

3. **`make-vstack` 垂直堆叠布局组件**：
   - 将多个子组件纵向依次拼接排版；
   - 支持子组件间距配置（`:spacing`，默认 0）：在子组件渲染行之间填充指定行数的空白行；
   - 宽度透传：所有子组件统一以给定的容器 `width` 进行渲染计算；
   - 扁平合并：按次序汇聚各子组件产出的文本行。

4. **`make-hstack` 水平分列布局组件**：
   - 将多个子组件横向并列排版；
   - 列间距支持（`:spacing`，默认 0）：列与列之间插入指定列宽的空白字符；
   - 列宽分配策略（`:widths`）：
     - 缺省均分：扣除列间距后，剩余总宽度在各列之间均分，余数依次回填；
     - 明确指定：支持传入比例或固定宽度数值列表（如 `'(20 40 20)`）；
   - 行对齐与空白填充：
     - 各列子组件在各自列宽上独立渲染，高度可能不同；
     - 默认顶部对齐（`:valign 'top`），高度不足的列自动使用空格在右侧补齐对应列宽；
     - 依赖 `(liii tui text-width)` 中的 `display-width` 计算 ANSI / CJK 混合文本的真实屏幕列宽，确保纵向列边界绝对垂直对齐。

5. **嵌套布局与动态宽度自适应**：
   - 支持多层复杂嵌套：如 `make-box` 内部嵌套 `make-vstack`，`make-vstack` 的某一行为 `make-hstack`，`make-hstack` 的子列内又包含 `make-box`；
   - 当顶层容器接收不同的总宽度（如 80、60、30、15 等）时，所有层级按比例与规则自适应收缩与换行，保持整体 UI 结构稳定。

6. **单文件 300 行与拆分规范**：
   - 严格遵循 `bin/gf check` 的单文件 <= 300 行硬约束；
   - 模块划分为：
     - `(liii tui box border)`：边框字符常量、风格定义与边框行生成纯函数
     - `(liii tui box box)`：`make-box` 组件实现
     - `(liii tui box vstack)`：`make-vstack` 垂直堆叠组件实现
     - `(liii tui box hstack)`：`make-hstack` 水平分列组件实现
     - `(liii tui box)`：统一门面导出
     - `(liii tui)`：顶级门面再导出
   - 测试按 goldfish 规范单函数单测试，镜像源码库结构。

## 验收点

1. **`make-box` 边框与内边距**：
   - 支持 `'single`、`'double`、`'rounded`、`'ascii` 与 `'none` 五种内置边框风格；
   - 支持统一 padding 以及细粒度 `:padding-left` / `:padding-right` / `:padding-top` / `:padding-bottom`；
   - 支持可选的 `:title` 顶部标题嵌入；
   - 支持超窄宽度边界条件，不抛异常崩溃。
2. **`make-vstack` 垂直拼接**：
   - 顺序拼接子组件渲染的多行文本；
   - 支持 `:spacing` 插入空行；
   - 递归转发 `component-handle-input` 与 `component-invalidate!`。
3. **`make-hstack` 水平分列**：
   - 并排渲染子组件，支持列间距 `:spacing`；
   - 支持默认均分列宽与自定义 `:widths` 分配；
   - 结合 `display-width` 准确对齐列边界，支持 ANSI 样式文本和 CJK 双宽文本不串行；
   - 多列不同行高时的垂直对齐与空格填充。
4. **嵌套布局与宽度自适应**：
   - 支持 box / vstack / hstack 任意层级多层嵌套；
   - 在总宽度动态变化时，各层级自动按可用宽度重新折行和对齐；
   - 单函数单测试，镜像源码库结构，全量通过 `bin/gf test`。
5. **工程门禁全绿**：
   - `xmake b goldfish`、`bin/gf fmt`、`git diff --exit-code`、`bin/gf check` 均 0 退出码；
   - 无真实 TTY 依赖，非交互式运行完全确定性通过。

### 2026-10-21 [058] PLAN 建档

#### What

1. 建立 `tools/pi/devel/058.md` 任务书，详细规划 `(liii tui box)`、`make-box`、`make-vstack`、`make-hstack` 的架构设计与测试覆盖；
2. 明确容器组件与 `(liii tui component)` 的协议整合，以及与 `(liii tui text-width)` 的显示宽度配合；
3. 规划模块拆分方案以确保单文件保持在 300 行以内；
4. 明确验收脚本 `058.scm` 的设计指标。

#### Why

布局与容器（边框、垂直堆叠、水平排列）是任何终端 UI 库组织内容和视图层次的基础积木。只有具备了边框容器与灵活的弹性流式排版，后续的转轮（059）、交互编辑器（060）与终端贪吃蛇（062）才能拥有结构化、清晰优雅的界面展现。

#### How

- 抽象边框字符表定义，将边框生成提炼为纯函数（`border.scm`），支持单线/双线/圆角/ASCII 等不同风格，便于测试和定制；
- `make-box` 计算内容可用宽度 `(- width border-w padding-w)`，将渲染交给子组件，再将返回的每行内容包上内边距和左右边框；
- `make-hstack` 根据设定的列宽规则分配每列的宽度，各自调用子组件渲染后，逐行利用 `display-width` 计算实际宽度并拼接；
- 封装为标准 `<component>`，保持统一的组合性和嵌套能力。
