## 验收点

- 模型与 Provider 不匹配时明确报错并退出：
  - 指定 `--provider X --model M` 时，若模型 `M` 经 `models-store` 判定不属于 Provider `X`，必须明确报错输出错误信息并以退出码 1 退出，**不允许 fallback 继续**。
- 模型在 models-store 查无记录时明确报错：
  - 指定的 `--model M` 在 `models-store` 中不存在时，将原先的 `Warning: Model "..." not found in models store; using fallback defaults` 警告+降级回退行为改为明确报错，退出码 1。
- 正常匹配场景保持兼容：
  - 属于对应 provider 的模型（如 `--provider google --model gemini-2.5-flash`、`--provider kimi-coding --model k3`、`--provider deepseek --model deepseek-v4-flash`、`--provider glm --model glm-5.3` 等）正常命中解析，无告警与报错。
- TDD 单测覆盖：
  - 覆盖模型与 provider 不匹配报错、模型未在 models-store 中找到报错，以及正常命中的单测。
- 门禁检查：
  - `timeout 600 xmake b goldfish`
  - `timeout 120 bin/gf fmt`
  - `git diff --exit-code`
  - `timeout 120 bin/gf check`
  - `bin/gf doc --build-json`

## 日期 任务描述

### 2026-10-19 任务建档

#### What

1. 查阅 `PI_PLAN.md` §3 任务 034 验收点与用户裁定规则（2026-10-19）：`--provider X --model M` 若 M 不属于 X（models-store 判定），必须明确报错退出码 1，不允许 fallback 继续；models-store 查无此模型也明确报错退出。
2. 从 `tools/pi/devel/ddd.md` 模板复制建立 `tools/pi/devel/034.md` 任务文档。
3. 明确任务涉及的代码文件、验收点、测试方法与门禁要求。

#### Why

- 此前系统遇到未在 models-store 中登记的模型或 provider 与 model 不一致时，仅在 stderr 输出 warning 并尝试使用 fallback defaults 继续执行，导致请求可能打向错误 provider 或使用错误协议/参数。
- 按照用户裁定，提升配置严格性：不匹配与模型未登记属于配置错误，应立即退出码 1 报错阻断，保证行为可预期。

#### How

- 在 `tools/pi/liii/pi/config.scm` 及 `tools/pi/liii/pi/models.scm` 中强化校验逻辑。
- 在 `resolve-pi-config` / `pi-route-provider-and-model` 阶段，检验 model 是否属于 provider；若查无此模型或 provider 不匹配，触发结构化错误并终止。
- TDD 编写单元测试验证不匹配及未登记情况退出码 1，并确保既有合法模型匹配正常通过。
