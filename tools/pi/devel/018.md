## 验收点

- 命令行参数支持：
  - 支持 `bin/gf pi --list-models` 选项。
  - 支持配合 `--provider <name>` 过滤特定 provider 的模型；当未显式指定 `--provider` 时，列出当前 provider（或全部已配置 provider）的可用模型。
  - 支持可选搜索过滤词（如 `bin/gf pi --list-models kimi`）。
- 数据提取与格式对齐：
  - 从 `models-store.json`（支持 `PI_CODING_AGENT_DIR` 重定向）中读取模型的 `id`、`contextWindow`、`maxTokens`、`reasoning`（thinking）、`input`（images）等字段。
  - 格式对齐上游 `pi --list-models`：包含 `provider`、`model`、`context`、`max-out`、`thinking`、`images` 列，数值按 K / M 人性化缩写展示，列宽对齐整齐。
- 用法文档更新：
  - 将 `--list-models` 的用法与示例写入 `PI_SPEC.md`。
- 测试与质量门禁：
  - 单元测试覆盖模型过滤、空数据/缺失文件兜底以及表格格式化。
  - 真实冒烟验证：`bin/gf pi --list-models` 与 `bin/gf pi --provider google --list-models` 正常输出。
  - 门禁检查全部通过：
    - `timeout 600 xmake b goldfish`
    - `timeout 120 bin/gf fmt`
    - `git diff --exit-code`
    - `timeout 120 bin/gf check`

## 日期 任务描述

### 2026-10-19 任务建档

#### What

1. 查阅 `PI_PLAN.md` §3 任务 018 验收点，调研上游 `pi --list-models` 的行为与格式：
   - 表头为 `provider`、`model`、`context`、`max-out`、`thinking`、`images`。
   - `context` 与 `max-out` 格式为如 `128K`、`1.0M`、`65.5K`、`131.1K`。
   - 数据来源为 `~/.pi/agent/models-store.json`（各 provider 下的 models 数组）。
2. 从模板复制并建立 `tools/pi/devel/018.md` 任务文档，详细规划代码文件、验收点与测试方法。
3. 规划实现方案：
   - 在 `(liii pi args)` 中支持 `--list-models` 标志解析。
   - 在 `(liii pi models)` 中实现数据过滤与格式化逻辑。
   - 在 `(liii pi cli)` 中优先分发处理该命令并正常退出。
   - 更新 `PI_SPEC.md` 相应文档。

#### Why

用户需要直观了解当前环境下有哪些配置好的模型及其上下文容量、最大输出限制与能力特性（thinking、images），格式对齐上游 `pi --list-models` 方便开发者无缝迁移与查看。

#### How

1. 在 `(liii pi args)` 中添加 `'list-models` 标志及其可选参数解析。
2. 在 `(liii pi models)` 中增加解析 `models-store.json` 中各个 provider 对应模型信息的函数，提取 `id`、`contextWindow`、`maxTokens` 等属性，实现按 provider / pattern 过滤，并格式化为对齐的纯文本表格。
3. 在 `(liii pi cli)` 中检测到 `--list-models` 时，执行查询并打印表格，退出码为 0。
4. TDD 方式编写单元测试，更新 `PI_SPEC.md`，执行冒烟测试与门禁验证。
