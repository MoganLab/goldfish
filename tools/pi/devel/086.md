## 验收点

1.0 **增量文本 Chunk 捕获与状态累加（Streaming Chunk Ingestion）**：
- 在 Agent 流式 SSE 触发 `message_update` 事件时，捕获增量文本 chunk；
- 若当前不存在活跃的 Assistant 消息，自动初始化一条空 Assistant 消息；
- 原地将 chunk 文本累加至活跃 Assistant 消息的内容尾部，并维持 `STREAMING` 状态与脏标记。

2.0 **末尾行自然折行局部增量重排（Incremental Line Wrapping）**：
- 结合 `(liii tui text-width)` 与 085 的 `wrap-text`，针对被修改的末尾文本进行自然折行更新；
- 避免全量历史消息的无谓重复排版，提升流式打字性能与响应速度；
- 保持视口自动贴底跟随（`scroll-offset = 0`），保证最新打字机输出始终展示在视口底部。

3.0 **基于 MainScreen 的行级差分渲染（Line-diff Screen Update）**：
- 借助 `(liii tui main-screen)` 维护的屏幕行缓冲区对比；
- 仅原地覆写被追加修改的 1~2 行文本，未变动的上部历史行不重复向终端输出；
- 行缩短或字符退格变更时，正确使用 ANSI 清行或擦除尾部残余字符（`terminal-clear-line-to-end`）。

4.0 **DECSET 2026 同步包裹与 0 闪烁终端输出（DECSET 2026 Synchronized Output）**：
- 每次流式帧渲染均由 `\x1b[?2026h`（Begin Synchronized Update）与 `\x1b[?2026l`（End Synchronized Update）包裹；
- 终端原子刷新整帧，达成 0 瞬时空白与跳闪现象。

5.0 **TDD 单元测试覆盖与门禁验证**：
- 对增量 chunk 累加、末尾折行更新、行级 diff 以及流式状态切换编写独立测试用例；
- 门禁四连：`timeout 600 xmake b goldfish`、`timeout 120 bin/gf fmt`、`git diff --exit-code`、`timeout 120 bin/gf check`；
- 全量测试（包括 `bin/gf test tools/pi/tests/liii/...`）100% 通过。

## 2026-10-21 任务描述

### What

1. 依据 `Agents.md` §3 任务 086 验收点从模板建立任务文档 `tools/pi/devel/086.md`；
2. 梳理流式 SSE 中 `message_update` 事件结构，规划 `streaming.scm` 模块；
3. 设计增量 chunk 累加与视口排版更新逻辑，确保高效响应打字机效果；
4. 对接 `(liii tui main-screen)` 的行差分对比引擎与 DECSET 2026 同步刷新，杜绝终端重绘闪烁。

### Why

在大模型会话中，流式增量文本打字机效果是终端交互的核心体验之一。如果每次收到 1~2 个字符的 chunk 就对整个终端屏幕或全量消息历史进行全量重绘，会造成极其严重的屏幕跳闪与 CPU 性能浪费。通过捕获 chunk、就地追加、局部重新断行排版、行级差分覆写以及 DECSET 2026 原子包裹，能够实现丝滑流畅且 0 闪烁的原生终端打字机呈现。

### How

- 在 TUI 状态中维护当前流式生成的累加缓冲区与活跃状态；
- 当捕获到 `message_update` 事件时，提取 chunk 字符串；
- 将 chunk 追加到最后一条消息的 content 中，仅重新排版最后若干受影响的物理行；
- 渲染层通过 `screen-render!` 与 MainScreen 的两套行缓冲区（current 与 previous）对比，只对脏行发出光标定位与文本覆写指令；
- 利用 DECSET 2026 原子帧包裹，由终端一次性原子上屏。
