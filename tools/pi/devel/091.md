## 2026-10-21 任务描述

### What

1. 调查并修复 `bin/gf pi` 首次启动黑屏的根因（`run-tui-flow` 未接入 `MainScreen` 与首屏渲染，导致备用屏切入后无画面输出）；
2. 完善终端全生命周期管理，确保启动有界面、输入立即可用、退出干净还原；
3. 使用虚拟终端实现启动缓冲区非空断言，防止首屏黑屏问题回归；
4. 全面核查 081~090 各项交互功能真实可用性并留痕。

### Why

用户在真实终端实测执行 `bin/gf pi`（无参进入 TUI 交互模式）时发现首次启动屏幕完全黑屏，
虽然进程运行中且进入了备用屏，但没有任何 UI 渲染，用户无法感知当前状态也无法有效交互。
这是影响 TUI 原生可用性的最高优先级阻碍性缺陷，必须彻底根治。

### How

1. 根因分析：`run-tui-flow` 创建了标准终端并调用 `with-pi-tui-terminal` 切入备用屏，但调用 `(run-tui-loop term)` 时未传入 `:screen` 或 `:render`，且 `opts.scm` 默认 screen 为 `#f`，导致主循环中 `render-tui-screen!` 从未被触发，终端保持清屏后的全黑；
2. 解决方案：在 `run-tui-flow` 中根据终端规格构造 `make-main-screen` 并传入 `run-tui-loop`（或在 `run-tui-loop` 缺省时自动构建默认 screen），确保首帧直接将状态渲染上屏；
3. 增加启动缓冲区测试：通过 VirtualTerminal 初始化并驱动 loop，断言获取的屏幕缓冲区包含预期三区内容。
