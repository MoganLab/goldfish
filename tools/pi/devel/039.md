## 验收点

从 `PI_PLAN.md` §3 任务表 039 复制并细化为可验证项：

1. **除 `sleep` 外无 `(liii time)` 依赖**：`tools/pi/liii/` 下不再出现
   `current-time` / `time-second` / `time-nanosecond` / `time-utc->date`
   / `current-second` 等时间 API；`(liii time)` 仅出现在需要 `sleep` 的 6 个
   request/stream 文件中，且每个文件对 `(liii time)` 的使用只剩 `sleep`。
2. **时间 API 来源统一**：时间相关功能一律来自 `(liii date-time)` 系列
   （PI_PLAN 中写作 `(liii datetime xxx)`；本仓库实际库名为
   `(liii date-time ...)`，如 `current-utc-timestamp`、
   `timestamp->utc-posix-time`、`timestamp-year/month/day/hour/minute/second`）。
   `agent.scm` 的 `(scheme time)` 直接 import 一并移除。
3. **行为不变（ISO 8601）**：`pi-iso-8601-utc-now` 输出仍为
   `YYYY-MM-DDTHH:MM:SS.mmmZ`——UTC、`T` 分隔、**固定三位毫秒**、`Z` 结尾；
   与迁移前的逐字符格式一致（会话文件名与 session header 的 `timestamp` 依赖它）。
4. **行为不变（毫秒时间戳）**：`pi-current-time-millis` 仍返回
   **精确整数**（不是浮点/有理数），量级与 epoch 毫秒一致，继续被
   message/event/session/multikey 消费而无类型回归。
5. **流式空闲超时不变**：gemini/kimi/anthropic 三路 SSE 的空闲超时仍按
   “整秒 epoch”比较，超时语义、重试与报错路径不变。
6. **TDD 覆盖时间函数输出格式**：先补/强化测试（格式正则、整数性、UTC、
   秒级辅助函数单调性/量级），再迁移实现；全部既有测试不回归。
7. **门禁通过**：`xmake b goldfish`、`bin/gf fmt`（`--check` 无 diff）、
   `bin/gf check`、`bin/gf -I tools/pi doc --build-json` 全绿。

## 迁移映射（开发阶段按此实现，可微调）

| 位置 | 迁移前 | 迁移后 |
|---|---|---|
| `pi/time.scm` | `(current-time)` + `time-utc->date` + `time-nanosecond` | `(current-utc-timestamp)` + `timestamp-*` 访问器 + `timestamp->utc-posix-time` |
| `pi-iso-8601-utc-now` | `date-year/month/...` + 自写补零 | 保留固定三位毫秒补零逻辑，时间源换为 UTC timestamp；**不得**直接用 `timestamp->iso-8601`（其小数秒不保证三位，会破坏格式） |
| `pi-current-time-millis` | `time-second*1000 + ns/1e6` 截断 | `(floor (* 1000 (timestamp->utc-posix-time (current-utc-timestamp))))`，保证精确整数 |
| 新增 `pi-current-time-seconds`（建议） | 各 stream 自行 `(time-second (current-time))` | 经 `(liii pi time)` 统一暴露整秒 epoch，agent 与三路 stream 共用 |
| `agent.scm` | `(scheme time)` 的 `current-second` | `pi-current-time-seconds`，移除 `(scheme time)` import |
| 三路 `stream.scm` | `(time-second (current-time))` | `pi-current-time-seconds`；`(liii time)` 仅为 `sleep` 保留 |
| `session.scm` | `(liii time)` import 未使用 | 删除该 import |
| 三路 `request.scm` | 仅 `sleep` | 不动（继续用 `(liii time)` 的 `sleep`） |

注意点：

- `(liii date-time current-time)` 内部使用 `get-time-of-day` 微秒精度；
  `current-utc-timestamp` 已固定 UTC，不要误用 `current-system-timestamp`
  （本地时区会破坏 `Z` 语义）。
- `timestamp->utc-posix-time` 返回**精确有理数**；转毫秒/整秒时必须显式
  `floor`/`exact`，避免下游 JSON 序列化出现比率数。
- 时间单调性不保证（墙钟），与迁移前 `current-time` 语义一致，不引入新行为。

## 2026-10-20 任务描述

### What

1. 建立任务 039 文档（本文件），明确迁移范围、映射关系与验收点；
2. 开发阶段以 TDD 先强化/新增时间函数格式测试，再把 `(liii time)` 时间 API
   全部迁移至 `(liii date-time)`；`(liii time)` 仅保留 `sleep`；
3. 全量回归 + 静态 grep 检查，确保 ISO 8601/毫秒输出与会话、事件、流式
   超时行为不变。

### Why

用户裁定（2026-10-19）：`(liii time)` 只保留 `sleep`，其余时间函数全部改用
`(liii date-time)`。当前 `tools/pi/` 中 8 个文件依赖 `(liii time)`，其中
`time.scm`、三路 `stream.scm`、`agent.scm` 直接使用其时间对象 API，
`session.scm` 甚至只是无效 import。统一到 `(liii date-time)` 后，
pi 子命令的时间来源单一、可维护，并与 goldfish 库的演进方向一致。

### How

- 以 `tools/pi/liii/pi/time.scm` 为唯一迁移入口：内部换成
  `current-utc-timestamp` / `timestamp->utc-posix-time`，对外导出保持不变，
  另加 `pi-current-time-seconds` 供 agent 与流式模块复用。
- `pi-iso-8601-utc-now` 保持手工组装 `...T...SS.mmmZ`（固定三位毫秒），
  不直接使用 `timestamp->iso-8601`（小数秒位数不固定）。
- 三路 stream 与 agent 的时间读取统一改为 `pi-current-time-seconds`，
  消除 `(time-second (current-time))` 与 `current-second` 两种写法。
- 验证采用“测试先行 + grep 静态门禁 + 全量回归”三重手段，确保零行为变化。
