## 根因分析与复现证据

通过在 `tests/demo/tui/snake/view-test.scm` 中构造长蛇、拐弯与穿墙场景，逐层对比 `render-grid-lines` 原始字符串、`component-render` 视图输出以及 `virtual-terminal` 屏幕缓冲区，查明问题的完整链条：

1. **直接根因 1（棋盘错误使用 `make-text` 与 `wrap-text` 导致前导空格被剥离）**：
   - 在 `demo/tui/snake/view.scm` 原实现中，`make-game-view` 将棋盘各行用 `\n` 拼接为长字符串，然后调用 `(make-text ...)` 构造组件；
   - `make-text` 底层调用 `(wrap-text str width)`；
   - 在 `goldfish/liii/tui/text-width/wrap.scm` 中，`%wrap-single-line` 处理空格的代码为：
     ```scheme
     ((eq? (caar rest) 'space)
      (cond ((= cur-w 0) (loop (cdr rest) cur-line cur-w active-ansi lines))
            ...))
     ```
     只要当前行为首且尚未输出非空格字符（`cur-w == 0`），**所有前导空格被无条件丢弃**；
   - 棋盘中每一行如果没有落在 `x=0`，其左侧所有的空白字符全部被剥离，整行字符被强制左移吸附到最左边界；
   - 当蛇拐弯或穿墙时，不同行左移的距离完全不同（如 Row 3 左移 5 格，Row 4 左移 2 格，Row 5 无左移），导致蛇头与蛇身、蛇身各节之间出现严重的水平剪切与断裂，中间列的蛇节被拉扯到最左侧或与其它节重合，在原坐标位置留下空缺，表现为“身体中间有一段不可见”。

2. **直接根因 2（定宽游戏棋盘被当做自然语言段落排版）**：
   - 贪吃蛇棋盘每一行是严格固定列宽（20 字符）的预格式化字符阵列；
   - 将预格式化阵列重新转为换行文本再做 word-wrap 不仅性能浪费，而且天然违背了字符矩阵的直通渲染语义。

3. **次要根因（容器组件配置参数不规范）**：
   - `make-box` 实际支持参数为 `:style`、`:padding-left/right/top/bottom`，而 `view.scm` 传递了 `:border-style` 与 `:padding-x`，导致双线框和 padding 回退默认值；
   - `make-vstack` 与 `make-hstack` 参数为 `:spacing`，而原代码传递了 `:gap`；
   - `make-hstack` 未锁定左侧棋盘宽度，总宽 60 下均分导致棋盘内部多出无效右侧空白。

## 修复改动方案

1. **`demo/tui/snake/view.scm` 棋盘组件直通化与规范化**：
   - 棋盘组件由 `make-text` 重构为预格式化直通组件：`(make-component (lambda (comp width) grid-lines))`，零拼接、零折行、零丢失；
   - `make-box` 修正参数：`:style 'double`，`:padding 0`；
   - `make-hstack` 修正参数：`:widths (list board-w 'auto)`，锁定棋盘宽度为 22 列（20 列内容 + 2 列双线框），右侧留给计分与帮助面板；
   - 修正 `make-stats-box`、`make-help-box`、`make-game-over-view` 中的 `:style` 与 `:spacing` 参数。

2. **`goldfish/liii/tui/text-width/wrap.scm` 通用折行修复**：
   - 修改空格判定：`((and (= cur-w 0) (pair? lines)) ...)`，仅在发生软折行（次行及后续行）时去除折行点空格，保留段落首行的原始缩进与前导空格；
   - 在 `wrap-text-test.scm` 补充首行缩进与前导空格保留的单测。

3. **补充长蛇、拐弯与穿墙的完整可见性单测**：
   - `tests/demo/tui/snake/view-test.scm`：补充长蛇 S 形拐弯坐标精确断言、左右穿墙两侧身体可见性、上下穿墙两侧身体可见性、以及虚拟终端屏幕差分渲染端到端断言，测试用例扩充至 53 项全绿。
