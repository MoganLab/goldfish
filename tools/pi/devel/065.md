## 排查方向与复现设计

1. **游戏逻辑与坐标检查 (`demo/tui/snake/logic.scm`)**：
   - 检查 `snake-tick` 中 `snake-body` 的移动与增长逻辑，是否会产生不连续的坐标段、重复坐标或坐标丢失；
   - 检查穿墙计算 `snake-pass-wall`（`modulo` 计算）在长蛇跨越左右边界或上下边界时，坐标列表是否正常。

2. **游戏视图渲染检查 (`demo/tui/snake/view.scm`)**：
   - 检查 `render-grid-lines`：`%cell-char` 是如何判定 head 与 body 的；
   - 特别注意：`render-grid-lines` 中传递给 `%cell-char` 的是 `head` 与 `(cdr body)`，当食物被吃下或普通移动时，蛇身各节判定是否存在 bug；
   - 检查长蛇或者穿墙时，`render-grid-lines` 每一行生成的字符串长度与内容，统计每行中的 `o` 字符总数是否等于 `(length body) - 1`。

3. **TUI 布局与文本折行检查 (`(liii tui box)`, `(liii tui text-width)`)**：
   - `make-game-view` 中 `board-box` 包装了 `board-text`（由 `render-grid-lines` 每行加换行拼接）；
   - `make-text` 内部使用 `wrap-text`，如果 `board-box` 分配的 `content-w` 小于棋盘宽度（20 列），`wrap-text` 会强制按宽度拆行/截断，导致网格行错乱变形；
   - 检查 `make-hstack` 分配给左右两栏的宽度（总宽 60 下，左侧 `board-box` 分得宽度是否充足，边框与 padding 占用是否合理）。

4. **差分渲染输出层检查 (`(liii tui main-screen)`)**：
   - 检查 `screen-render!` 的 `diff-ops` 在蛇身移动时，前一帧与后一帧覆写时是否存在覆盖遗漏或行尾截断异常；
   - 通过 `virtual-terminal` 截取整帧屏幕缓冲区，比对棋盘中 `@` 与 `o` 的数量与位置。

5. **复现测试设计**：
   - 在 `tests/demo/tui/snake/` 中编写针对长蛇（如长度 5、10）在直线前进、多次转弯、穿过四面墙壁时的测试；
   - 断言 `render-grid-lines` 输出中 `@` 数量为 1，`o` 数量为 `length(body)-1`，总计恰好等于蛇身长度；
   - 将完整视图渲染至 `virtual-terminal`，断言屏幕中提取的棋盘内 `@` 与 `o` 无一遗漏。
