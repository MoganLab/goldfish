## 验收点

1.0 **扩展名称推断与 URL 解析**：
- 支持从各类 Git 仓库 URL（HTTPS、SSH、本地路径等）中准确提取扩展名 `<name>`（剥离 `.git` 后缀与尾部斜杠）；
- 严格进行安全性校验：扩展名称必须合法，严禁包含路径分隔符、`..` 相对路径穿透或非法字符。
2.0 **目标安装目录计算与隔离**：
- 默认安装到全局扩展目录：`<agent-dir>/extensions/<name>`（优先尊重环境变量 `PI_CODING_AGENT_DIR`，缺省为 `~/.pi/agent/extensions/<name>`）；
- 支持 `--local`（或 `-l`）参数，指定后安装至当前工作工程目录：`<cwd>/.pi/extensions/<name>`；
- 自动创建不存在的父级 `extensions` 目录。
3.0 **冲突检测与原子性安全防范**：
- 若目标插件目录已存在，拒绝操作并输出明确的冲突错误提示，不覆写已有目录；
- git clone 失败或异常中断时，自动清理半成品目标目录，避免残留损坏的扩展。
4.0 **外部 Git 调用与超时防卡死**：
- 使用 `(liii subprocess)` 执行 `git clone`，必须携带强制 `:timeout` 限制（默认 120 秒）；
- 能够妥善捕获网络失败、非零退出码或超时异常，并输出人可读的错误摘要。
5.0 **CLI 集成与一键生效验证**：
- 支持 `bin/gf pi install <url>` 与 `bin/gf pi install --local <url>` 命令行语法；
- 安装完成后，所克隆扩展能够被 `pi-discover-extensions` 发现引擎自动扫描感知；
- 门禁检查（xmake 构建、bin/gf fmt、git diff --exit-code、bin/gf check）全绿，全量单元测试与验收脚本全绿通过。

### Why

在任务 070~075 确立的 Extension 发现层级中，全局目录（`~/.pi/agent/extensions/`）和项目目录（`.pi/extensions/`）是用户与工程自定义插件的核心承载点。为了打造轻量、开箱即用的扩展生态，需要提供与原生 pi 类似的 `pi install <git-url>` 子命令，让用户或开发者能够通过一条命令直接从 Git 仓库拉取安装扩展，并结合目录扫描机制实现「克隆即生效」。

### How

1.0 在 `(liii pi extension install)` 中提供纯函数解析扩展名，如 `https://github.com/org/pi-plugin.git` 解析出 `pi-plugin`；
2.0 校验扩展名是否为简单标识符（仅允许字母、数字、下划线、短横线），防止路径遍历注入；
3.0 解析目标路径：检查当前工作目录 `.pi/extensions` 或 agent 目录下的 `extensions`；
4.0 检查目录是否已存在，存在则抛出 `install-error` 或结构化错误；
5.0 调用 `(subprocess-run ... :timeout 120)` 执行 `git clone <url> <dest>`，并在失败时尝试清理目标目录；
6.0 在 `tools/pi/liii/pi/cli.scm` 中分流 `install` 指令，执行成功返回 0，失败输出错误摘要并返回 1。
