## 验收点

（从 `PI_PLAN.md` §3 任务表展开，逐条可验证）

1. **Gemini 搜索请求体 tools 构造与注入**：
   - 提供辅助函数（如 `gemini-inject-google-search` / `gemini-build-search-tools`），支持在 Gemini 请求体中注入 Google Search Grounding 节：`{"googleSearch": {}}`（或兼容 `google_search` 节）；
   - 兼容共存场景：当请求已包含 `functionDeclarations`（既有工具调用声明）时，能够与 Google Search 节安全组合在一个 `tools` 列表中；
   - 原有无 search 请求体构造逻辑完全不受影响，无回归。
2. **groundingMetadata 核心三要素解析（对齐原生 pi）**：
   - 参考 `~/git/pi-web-search/src/providers/google.ts`（`extractGoogleSearchDetails`）的实现逻辑，从 `groundingMetadata` 解析以下三要素：
     - a. `searchQueries`：提取 `webSearchQueries` 字符串列表，缺失或为空时安全返回 `'()`；
     - b. `searchResults`：提取 `groundingChunks` 列表，每项解析其 `web.title`（缺省为 `"Unknown"`）、`web.uri`（作为 URL）、来源标记 `google.groundingChunks` 等结构化字段；
     - c. `citations`：提取 `groundingSupports` 列表，关联 `groundingChunkIndices`，解析段落佐证（`segment.text`、`startIndex`、`endIndex`）与引用 chunk 索引之间的映射关系。
3. **响应与流式分片兼容与健壮性**：
   - 函数能够直接消费非流式 API 返回的完整 JSON 对象（`candidates[0].groundingMetadata`），也能消费 SSE 流式分片中的 candidate 数据；
   - 遇到缺失 `groundingMetadata`、`candidates` 为空、字段残缺（如 chunk 缺少 `web`、非 list/vector）时，安全返回空结构，绝不抛出未捕获异常。
4. **TDD 测试覆盖与示例 JSON**：
   - 在 `tools/pi/tests/fixtures/gemini/` 下保存标准 Grounding 响应 JSON fixture；
   - 按照测试目录镜像源码库结构的规范，针对每个导出函数编写独立测试文件；
   - 单元测试不得引用三份计划文档，断言验证解析结果三要素与字段完整性。
5. **范围约束**：
   - 本阶段专注于纯数据结构构造与解析，不发起外部网络请求（网络执行器由 042 实现），不改动 Agent 循环调度（由 043 实现）。
6. **门禁规范**：
   - 遵守单文件 300 行约束；
   - 通过 `timeout 600 xmake b goldfish`、`bin/gf fmt`、`git diff --exit-code`、`bin/gf check`、`bin/gf doc --build-json`。

## 2026-10-20 任务描述

### What

1. 建立任务 041 任务文档，明确阶段二（Gemini 搜索请求体构造与 Grounding 解析）的开发范围与验收标准；
2. 梳理对照基准 `~/git/pi-web-search/src/providers/google.ts` 中 `extractGoogleSearchDetails` 的结构细节，确立三要素（queries / chunks / supports）解析契约；
3. 规划 `tools/pi/liii/pi/gemini/grounding.scm` 独立模块，避免既有 `core.scm`（294 行）与 `request.scm`（291 行）超出 300 行硬约束。

### Why

在阶段一（任务 040）中，已成功注册 `web_search` 工具 Schema 与参数校验规范。
而在 Gemini 模型通道中，Google 提供了原生 Grounding with Google Search 能力。
为了实现 Gemini 通道下的网络搜索与引用来源解析，需要先把请求体中的 Google Search 节注入以及响应中的 `groundingMetadata` 三要素提取出来，作为后续 042（执行器拼装）与 043（Agent 闭环）的核心支撑。

### How

1. 在 `tools/pi/liii/pi/gemini/grounding.scm` 中实现：
   - `gemini-inject-google-search`：向现有 tools 结构中注入 `(("googleSearch" . ()))`（若 tools 为空则创建含单个 googleSearch 节的 tools vector/list；若已有 tools 则追加合并，不破坏已有 `functionDeclarations`）；
   - `gemini-extract-grounding-details`：纯函数解析 `groundingMetadata`，提取 `searchQueries`、`searchResults`、`citations` 三要素；
2. 准备 fixture 数据文件，基于真实的 Gemini Grounding 响应样本编写测试；
3. 导出至 `(liii pi gemini)` 与 `(liii pi)` 门面。
