## 日期 任务描述

### What

1. 建立任务文档 `tools/pi/devel/005.md`（文档阶段建档）。
2. 先为消息结构（user/assistant/toolResult）与 content block（text/toolCall）编写 `define-record-type` 谓词与访问器单测（TDD）。
3. 在 `tools/pi/liii/pi/` 下实现消息与 content block 的 record 定义及转换层，保持原有构造函数与 assoc 访问习惯向前兼容。
4. 全量运行已有测试并执行各端点调用抽验，确保 JSON 输出与 CLI 行为零变化。
5. 编写并运行 `tools/pi/devel/005.scm` 验收脚本。

### Why

将原先基于松散 alist 的消息与 content block 结构统一升级为强类型的 Scheme record（`define-record-type`），消除魔法 key 与类型混乱，与任务 004 的事件 record 化呼应，为后续配置/工具 record 化打好坚实基础。

### How

使用 R7RS `define-record-type` 定义各消息与 content block 类型，提供统一谓词、访问器与构造函数，并在序列化/provider 映射层保持透明转换兼容。
