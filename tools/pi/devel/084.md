## 验收点

1.0 **界面拓扑结构划分（Layout Topology）**：
- 基于 `(liii tui box)` 与 `(liii tui main-screen)` 划分界面拓扑：顶部消息视口（Message Viewport）、中部自适应高度输入框（Editor Box）、底部状态栏（Status Bar）；
- 输入框高度根据实际行数动态自适应（最小高度如 3 行，最大高度受限例如不超过总行数 40%）；
- 顶部消息视口自动分配剩余空间，保证终端高度占满且不溢出。

2.0 **终端尺寸动态感知（Size Detection）**：
- 动态通过 `terminal-detect-size` 读取终端当前的列宽和行高；
- 具备兜底能力：在无法检测或非 TTY 虚拟终端下提供合理的缺省尺寸（如 80x24）；
- 提供布局计算纯函数，输入 `(cols, rows, editor-line-count)` 计算各区域的矩形范围（top, left, width, height）。

3.0 **窗口 Resize 监听与差分重绘（Resize Adaptation）**：
- 在主事件循环 tick 或按键轮询节拍中检测尺寸变动（`cols` / `rows` 改变）；
- 检测到尺寸变动时，调用 `screen-resize!` 重新配置主屏幕缓冲区并标记全量重绘，杜绝画面错位与闪烁；
- 状态机同步更新 `cols` 与 `rows`。

4.0 **窄屏优雅折叠降级（Narrow Screen Adaptation）**：
- 当终端宽度较窄（`< 60` 列）或行数过小（`< 15` 行）时，优雅折叠状态栏详细信息，使用紧凑单行或隐藏非关键提示；
- 装饰边框（如复杂外框）根据宽度优雅切换为紧凑线条或极简前缀，确保关键内容优先可见。

5.0 **TDD 单元测试覆盖与门禁**：
- 针对拓扑计算函数、自适应高度约束、窄屏降级逻辑编写独立单元测试；
- 利用虚拟终端注入窗口尺寸变化，验证 `screen-resize!` 与重绘机制；
- 门禁四连：`timeout 600 xmake b goldfish`、`timeout 120 bin/gf fmt`、`git diff --exit-code`、`timeout 120 bin/gf check` 与相关测试 100% 通过。

## 2026-10-21 任务描述

### What

1. 依据 `Agents.md` §3 任务 084 验收点建立任务文档 `tools/pi/devel/084.md`；
2. 梳理 `(liii tui main-screen)`、`(liii tui box)` 与 `terminal-detect-size` 的 API 原语；
3. 设计响应式布局计算模块 `tools/pi/liii/pi/modes/tui/layout.scm`，实现三段式（消息/输入/状态）屏幕划分与自适应高度；
4. 规划主循环 `loop.scm` 中的 Resize 检测与重绘机制，以及窄屏紧凑降级规则。

### Why

TUI 交互界面在不同终端窗口（全屏、分屏、拖拽调整大小）下必须具备响应式自适应能力。若固定写死行列大小，一旦用户调整终端窗口就会导致重叠错位、截断或换行混乱。通过构建灵活的拓扑划分与 Resize 差分响应，能够确保界面在任何终端尺寸下都整洁美观且稳定可靠。

### How

- 在 `layout.scm` 中定义纯函数 `compute-tui-layout`：接受 `cols`、`rows` 与 `input-lines`，返回消息视口高度、输入框高度、状态栏高度以及是否启用窄屏紧凑模式；
- 输入框高度采用弹性计算：基础高度 + 内容行数，受上下限（最小 3 行，最大不超过 `rows * 0.4`）限制；
- 状态栏高度根据 `cols < 60` 或 `rows < 15` 决定是否折叠为 1 行或 0 行；
- 剩余高度全部赋予顶部消息视口；
- 在事件循环中通过 `terminal-detect-size` 周期对比当前尺寸，变化时调用 `screen-resize!` 并重新计算各区域尺寸，触发 dirty 标记进行差分重绘。
