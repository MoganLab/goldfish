### 架构设计与差分渲染原理

1. **终端闪烁的根源与差分渲染（Differential Rendering）**：
   - 终端 UI 刷新若采用全量清屏（`clear-screen`）再重绘，在连续更新（如光标移动、打字、转轮动画或游戏主循环）时会产生剧烈的屏幕闪烁（screen tearing / flickering）；
   - 差分渲染的核心思想是维护双缓冲区概念：**前一帧（previous frame / cached lines）** 与 **新一帧（current frame / new lines）**；
   - 逐行对比前后帧文本：
     - 若第 $i$ 行文本完全相同（含 ANSI 样式序列一致），则完全跳过该行，不向终端发出任何写入，IO 消耗为零；
     - 若第 $i$ 行发生变更，则移动光标到该行行首（`terminal-set-cursor!`），输出新行文本并清除行尾剩余残留（`terminal-clear-line` 或补空格）；
     - 若新帧行数少于旧帧行数，需要对超出新帧范围的旧行依次清空，避免屏幕下方遗留残影；
     - 若新帧行数多于旧帧行数，则依次向下追加新行。

2. **终端驱动引擎与生命周期管理（Screen Driver）**：
   - 封装 `<main-screen>` 记录类型，关联底层 `<terminal>`（既可对接真实的 `standard-terminal`，也可对接脱机无头的 `virtual-terminal`）；
   - 提供核心接口：
     - `make-main-screen term [opts]`：创建主屏幕驱动实例；
     - `screen-render! screen lines`：将一组字符串行渲染到屏幕（执行差分比较并驱动 terminal 写入）；
     - `screen-refresh! screen`：强制全量重绘当前帧（重新输出所有行，无论前后帧是否一致）；
     - `screen-invalidate! screen`：使当前帧缓存失效（标记 dirty）；
     - `screen-resize! screen cols rows`：响应终端尺寸变更，重新计算 viewport 并触发全量重绘；
     - `screen-clear! screen`：清空终端屏幕并重置行缓存；
     - `screen-terminal screen`：获取关联的底层终端对象；
     - `screen-lines screen`：获取当前屏幕已渲染的行列表快照。

3. **Resize 尺寸感知与自适应重绘**：
   - 当终端窗口缩放或调用 `screen-resize!` 时，原有的字符换行与列宽发生改变；
   - 驱动器检测到终端尺寸改变或收到 resize 通知时，将前一帧缓存作废，以新尺寸触发全量绘制，保证显示内容自适应终端边界。

4. **无头虚拟终端的确定性断言（Virtual Terminal Testing）**：
   - 基于 `(liii tui terminal)` 的 `virtual-terminal`，全程不依赖真实 TTY；
   - 断言 1：前后帧完全一致时，终端 `virtual-terminal-raw` 无新增写入；
   - 断言 2：仅局部行修改时（例如 10 行中仅第 3 行修改），底层终端仅发生对应行的光标跳转和单行重写；
   - 断言 3：行数伸缩（收缩时清除残余行，扩张时追加）逻辑正确；
   - 断言 4：resize 触发全量重写；
   - 捕获原始 write 验证 ANSI 序列与最终 `virtual-terminal-screen` 屏幕矩阵完全一致。

5. **单文件 300 行与模块拆分策略**：
   - 严格遵循 `bin/gf check` 的单文件 <= 300 行硬约束；
   - 模块划分为：
     - `goldfish/liii/tui/main-screen/diff.scm`（纯函数行差分比较算法，输出差异更新指令流）
     - `goldfish/liii/tui/main-screen/buffer.scm`（帧缓冲区记录，管理前后帧行列表与 dirty 状态）
     - `goldfish/liii/tui/main-screen/driver.scm`（`<main-screen>` 驱动引擎，整合 terminal 执行差分写入、全绘与清屏）

## 日期 任务描述

### What

1. 建立任务 062 建档文档 `tools/pi/devel/062.md`，明确主屏幕输出驱动与差分渲染的设计规范与验收标准；
2. 设计 `(liii tui main-screen)` 模块架构，遵循单文件 <= 300 行约束，拆分为差分算法、双帧缓冲与驱动引擎三层；
3. 设计纯函数行差分比较算法，生成精细化的差异更新指令（跳过、行更新、行追加、清理残余行）；
4. 基于 `(liii tui terminal)` 驱动屏幕输出，测试全部使用 `virtual-terminal` 在无头环境下验证 ANSI 输出与屏幕矩阵；
5. 实现尺寸变更（resize）检测与强制全屏重绘，避免终端残留或布局错乱；
6. 规划单函数单测试用例与端到端验收脚本 `tools/pi/devel/062.scm`。

### Why

终端交互应用（如 REPL、编辑器、状态面板、贪吃蛇游戏等）在频繁更新时，如果简单地清屏并重绘整个屏幕，会产生明显的闪烁和光标跳动，严重影响用户体验。差分渲染（Differential Rendering）只对发生改动的行进行定向光标定位和覆写，对于没有变动的行完全不做任何 IO 操作，既消除了闪烁，又大幅降低了终端 IO 负载，是通用 TUI 库和后续 063 贪吃蛇交互游戏的核心基础驱动设施。

### How

1. **纯函数行差分比较（`screen-diff`）**：
   - 接收旧行列表 `old-lines` 与新行列表 `new-lines`；
   - 遍历各行索引：
     - 若 `i < len(old)` 且 `i < len(new)` 且 `string=?` 相同，记录 `'(keep i)`；
     - 若 `i < len(old)` 且 `i < len(new)` 但内容不同，记录 `'(update i text)`；
     - 若 `i >= len(old)` 且 `i < len(new)`，记录 `'(append i text)`；
     - 若新行数少于旧行数，对于超出范围的旧行索引记录 `'(clear i)`；
2. **驱动引擎（`main-screen`）执行差分指令**：
   - 遍历差异指令列表：
     - 对于 `keep`：跳过，光标不动，不写终端；
     - 对于 `update` / `append`：调用 `terminal-set-cursor!` 移动到第 $i$ 行（0-based 或 1-based 对齐），写出新文本，若存在多余尾部字符则清除或清行；
     - 对于 `clear`：移动到第 $i$ 行并执行 `terminal-clear-line`；
   - 渲染完成后，根据需要将光标移至指定位置或隐藏；
   - 更新内部帧缓冲区（当前帧成为下一次渲染的前一帧）；
3. **全量重绘与 Resize 处理**：
   - 提供 `screen-refresh!` 与 `screen-invalidate!`：将旧行缓存置空或强制将所有行作为 `update` 指令重新写出；
   - 当收到 resize 时，同步重设尺寸并强制重绘；
4. **虚拟终端断言**：
   - 通过 `virtual-terminal-raw` 捕获所有写入操作，严格断言局部更新时未触碰不变行，验证零闪烁与最小写入。
