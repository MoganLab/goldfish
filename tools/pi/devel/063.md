## 架构设计

1. **纯游戏逻辑引擎（State & Game Loop）**：
   - 核心状态 `<snake-game>`：网格尺寸 (width, height)、蛇身坐标队列（head + body 节）、当前运动方向 (`'up`, `'down`, `'left`, `'right`；支持箭头键与 WASD 控制）、食物坐标 `(fx, fy)`、当前得分与最高分、游戏状态（`'running`、`'paused`、`'game-over`）；
   - 移动与碰撞逻辑：
     - **四面墙壁可穿越（Wrap-around）**：头部越界时模运算环绕回对侧（如 $x < 0 \to x = width - 1$，$x \ge width \to x = 0$），避免边界误触过快结束；
     - **自碰碰撞判定**：若新头部位置与现有蛇身重叠，则触发游戏结束 `'game-over`；
     - **食物生成与蛇身增长**：吃到食物时蛇身长度增加一节、得分增加，并在空白区域随机生成下一个食物；未吃到食物时尾部出队；
   - 纯函数状态机：输入 `(game-tick game [key])` 返回下一个状态，支持完全脱离 TTY 确定性回放。

2. **渲染层与 `(liii tui)` 组件复用**：
   - 使用 `(liii tui box)` 构建游戏外边框与计分信息卡；
   - 使用 `(liii tui main-screen)` 差分渲染驱动，仅在蛇身移动、分数变更时局部重绘，消除终端闪烁；
   - 整合 `(liii tui component)`、`text-width`、`loader`（游戏启动动画/等待状态）与 `editor`（最高分名字登记等），全面检验 `(liii tui)` 各模块协同能力。

3. **终端输入与 Windows 平台最小补齐（Terminal Raw/Non-blocking Input）**：
   - 复用 `(liii tui keys)` 的 `parse-key`/`parse-keys` 统一解析方向键/转义序列；
   - 针对当前 Windows 开发机（不考虑 Linux 分支，保证超时可控），在 Windows 下提供轻量控制台非阻塞按键读取胶水接口（如 C/C++ 胶水层调用 `_kbhit()` 与 `_getch()`，或在 `(liii tui terminal)` 封装 `terminal-poll-key`）；
   - 若无输入则立刻返回 `#f`，确保主循环以固定 tick 步进（如 100ms），绝不因阻塞读取导致挂起。

4. **双层验收体系**：
   - **第一层：非 TTY 纯逻辑与脚本化按键自动化回归**：
     - 在 `virtual-terminal` 下模拟按键输入序列（回放预定转向与吃食物指令）；
     - 验证蛇身延长、计分板刷新、穿越对侧边界、自碰结束；
     - 耗时 < 10 秒，纳入 CI/单测常态门禁。
   - **第二层：Windows 真实终端 Python + pynput 自动化冒烟**：
     - 测试脚本 `tools/pi/devel/063-smoke.py`；
     - 通过 `pygetwindow`/`ctypes` 定位 Windows Terminal 窗口（若不存在则调用 `wt.exe` 启动，并在测试后自动关闭恢复现场）；
     - 发送 `Ctrl+Shift+T` 打开独立新标签页，键入 `cd ~/git/goldfish` 并运行 `bin/gf demo/tui/snake.scm`；
     - 借助 `pynput` 发送方向键序列控制小蛇移动与吃食物；
     - 利用 Pillow `ImageGrab` 在**启动**、**转向移动**、**计分吃食物**与**结束**四个关键时刻截图留档存入 `tools/pi/devel/063-screenshots/`；
     - 模型通过图片视觉确认游戏画面完好、计分板实时更新、渲染无闪烁与撕裂。

5. **单文件 300 行与规范策略**：
   - 遵循 `bin/gf check` <= 300 行约束；
   - 拆分为纯逻辑模块、渲染组件模块、交互入口脚本与自动化测试脚本；
   - TUI 实现文件使用 MIT 许可协议头；测试文件无协议头；单函数单测试镜像源码结构。

## 日期 任务描述

### What

1. 设计贪吃蛇游戏逻辑、差分渲染与 Windows 终端非阻塞按键读取方案。
2. 规划双层自动化验证：非 TTY 脚本化回放与真实终端 Python+pynput 截图审计。
3. 建立 063 任务文档与验收规格。

### Why

作为 `(liii tui)` 第一阶段通用终端 UI 基础库的终验成果，通过贪吃蛇交互游戏全面检验 `(liii tui)` 核心能力（组件体系、文本宽度、转义按键、终端抽象、边框布局与差分渲染），并在 Windows 开发机上打通真实终端的自动化冒烟与截图视觉验收闭环。

### How

- 采用纯函数状态机分离游戏逻辑与渲染，使游戏过程可脱离终端完全确定性回归。
- 借助 `(liii tui main-screen)` 差分更新特性，仅刷新变化行，避免游戏主循环重绘闪烁。
- 编写 `063-smoke.py` 调用 Windows Terminal 创建独立标签页，结合 `pynput` 发送模拟按键，并用 Pillow 截图保存至 `tools/pi/devel/063-screenshots/`，由模型进行视觉多模态校验。
