## 验收点

1.0 **代码目录迁移与解耦**：
- 用户裁定：将 `compass` 和 `blueprint` 的源码移动到两个相应的扩展目录即可（无需在 GitHub 创建外部仓库）；
- 核心代码库（`builtin/flags.scm`、`builtin/flows.scm`、`builtin/prompts.scm`、`modes.scm`、`pi.scm` 等）彻底移除对 `compass` 与 `blueprint` 的显式 import 与硬编码注册逻辑；
- 扩展完全遵循 `ExtensionAPI` 规范，通过 `register-tool!`、`register-flag!`、`register-flow!`、`register-prompt-injector!` 自主挂载。

2.0 **自动发现与动态加载**：
- 放置于扩展目录下后，`pi` 启动时能够自动扫描并成功加载 `compass` 与 `blueprint` 扩展；
- 不指定扩展参数时，扩展按目录约定自动生效；加载过程容错性完备，无崩溃或隐式失败。

3.0 **功能完整性端到端验证**：
- 端到端验证 `--codemap`、`--tour` 相关指令及 `codebase_map` / `code_tour` 工具调用正常运作；
- 端到端验证 `--blueprint`、`--plan-status`、`--plan-next`、`--plan-verify`、`--plan-abandon` 及 `blueprint_*` 工具调用正常运作；
- 既有单元测试与系统门禁无回归，全量单测 PASS。
