### What

1.0 在 `tools/pi/liii/pi/extensions/` 下建立 `compass.scm` 与 `blueprint.scm`，通过标准 `ExtensionAPI` 自主挂载 flags、tools、flows、validator、config augmenter 与 prompt injector；
2.0 彻底清理核心层 `builtin/flags.scm`、`builtin/flows.scm`、`builtin/prompts.scm`、`pi.scm` 与 `modes.scm` 中的残留硬编码；
3.0 增强 `(liii pi extension discovery)`，支持根据二进制可执行文件位置智能推导内置扩展路径；
4.0 新增 `compass-test.scm` 与 `blueprint-test.scm` 独立单元测试；
5.0 编写可执行验收脚本 `tools/pi/devel/078.scm`，完成门禁、解耦断言、动态加载验证与端到端 CLI 实测。

### Why

根据用户 2026-10-20 裁定与全局战略路线规划，Extension 扩展机制的核心价值在于让特定功能彻底从主干解耦。`compass`（代码地图）和 `blueprint`（多任务规划）此前虽然具备扩展形态，但核心的 `builtin` 包中仍残留了大量显式硬编码注入。通过将两者正式迁移至标准扩展目录，并通过 `ExtensionAPI` 动态挂载，实现主核心代码与具体扩展的彻底分离，为用户自定义扩展打下坚实示范。

### How

1.0 利用 `make-extension-flag-def`、`register-tool!`、`register-flow!`、`register-validator!`、`register-config-augmenter!` 与 `register-prompt-injector!`，将 `compass` 与 `blueprint` 的能力自包含在扩展入口函数中；
2.0 清空 `builtin/flags.scm`、`builtin/flows.scm`、`builtin/prompts.scm` 中的特定扩展注册逻辑，使内置骨架成为完全通用的透传注册表；
3.0 在 `tools/pi/devel/078.scm` 中通过子进程隔离测试 `--plan-status`、`--tour`、`--codemap` CLI 指令，并在运行前后严格清理测试目录，确保工作区无任何临时残留。
