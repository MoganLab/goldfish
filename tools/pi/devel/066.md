## 架构与配色方案设计

### 1. 配色视觉层级规划

在遵循终端 16 色 ANSI 标准的基础上，规划清晰且现代的配色体系：
- **蛇头 (`@`)**：高亮亮绿或黄色粗体（`\x1b[1;32m` 或 `\x1b[1;33m`），突出头部动向；
- **蛇身 (`o`)**：常规绿色（`\x1b[32m`），与蛇头形成梯度区分；
- **食物 (`*`)**：粗体亮红或红色高亮（`\x1b[1;31m`），醒目警示；
- **棋盘边框与标题**：青色双线框（`\x1b[36m`），标题粗体青（`\x1b[1;36m`）；
- **STATS 侧栏**：黄色标题框（`\x1b[33m`），标签与数值分层（数值粗体高亮）；
- **转轮动画 (Heartbeat)**：洋红/紫（`\x1b[35m`），动态指示存活；
- **HELP 侧栏**：暗调青或灰色边框，按键说明清晰；
- **GAME OVER 视图**：红色双线框与高亮横幅，提示清晰分明。

### 2. 关键约束与技术实现路径

1. **ANSI 样式库模块化与安全封装 (`demo/tui/snake/style.scm`)**：
   - 建立 `(demo tui snake style)` 模块，封装 `style-head`, `style-body`, `style-food`, `style-border`, `style-title`, `style-accent`, `style-dim`, `style-reset` 等函数；
   - 支持环境变量 `NO_COLOR`（检测到非空环境变量 `NO_COLOR` 时自动关闭所有样式代码，返回纯文本）；
   - 提供 `style-enabled?`、`style-enable!`、`style-disable!` 与 `with-color-mode` 动态控制，便于非交互测试与无色环境测试。

2. **`virtual-terminal` 对 ANSI 转义序列的兼容**：
   - 现有的 `virtual-terminal` 在 `%vt-write!` 中按字符写入屏幕缓冲区 `vt-lines`，遇到 `\x1b` 时会把转义字符写入屏幕网格并向右移动光标；
   - 完善 `(liii tui terminal virtual)`：在向虚拟屏幕 `vt-lines` 填字与推进光标时跳过 ANSI CSI 序列；
   - 保证：
     1) `virtual-terminal-screen` 依然返回干净的纯可见字符矩阵，所有行宽与元素坐标与原无色版 100% 对齐；
     2) `virtual-terminal-raw` 完整保留包含 ANSI SGR 的原始流，供断言样式正确性；
     3) 现有所有基于 `virtual-terminal-screen` 的断言零破坏。

3. **文本宽度与差分渲染兼容性**：
   - `display-width` 已天然支持 `strip-ansi`，保证带 ANSI 字符的可见宽度恒等于原字符数；
   - `screen-diff` 使用 `string=?` 比较字符串，包含样式的字符串在颜色发生改变时能产生 `update`；
   - `%render-diff-op!` 使用 `display-width` 判断缩短行，清除尾部不会因颜色代码误判；
   - 保持 DECSET 2026 同步输出与单帧写入完整性，零闪烁。

4. **无色降级一致性**：
   - 当 `NO_COLOR` 启用或禁用样式时，`render-grid-lines`、`make-game-view`、`make-game-over-view` 产生的内容与此前版本完全一致，保障跨平台终端降级安全性。
