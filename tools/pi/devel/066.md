## 架构与配色方案设计

### 1. 配色视觉层级规划

在遵循终端 16 色 ANSI 标准的基础上，规划清晰且现代的配色体系：
- **蛇头 (`@`)**：粗体亮绿色（`\x1b[1;32m`），突出头部位置与动向；
- **蛇身 (`o`)**：常规绿色（`\x1b[32m`），与蛇头形成梯度区分；
- **食物 (`*`)**：粗体亮红（`\x1b[1;31m`），醒目警示；
- **棋盘标题与 STATS 标题**：粗体青色（`\x1b[1;36m`）；
- **STATS 侧栏数值**：粗体黄色高亮（`\x1b[1;33m`），重点突出；
- **转轮动画 (Heartbeat)**：粗体洋红/紫（`\x1b[1;35m`），动态指示存活；
- **HELP 侧栏与提示**：灰色暗调（`\x1b[90m`），按键说明清晰不喧宾夺主；
- **GAME OVER 视图**：粗体亮红（`\x1b[1;31m`）横幅与 RECORD 标题，分明警示。

### 2. 关键约束与技术实现路径

1. **ANSI 样式库模块化与安全封装 (`demo/tui/snake/style.scm`)**：
   - 建立 `(demo tui snake style)` 模块，封装 `style-head`, `style-body`, `style-food`, `style-title`, `style-accent`, `style-dim`, `style-heartbeat`, `style-game-over`, `style-reset`；
   - 支持环境变量 `NO_COLOR` 规范（检测到非空环境变量 `NO_COLOR` 时自动关闭所有样式代码，返回纯文本）；
   - 提供 `style-enabled?`、`style-enable!`、`style-disable!` 与 `with-color-mode` 动态控制，便于非交互测试与无色环境测试；
   - 默认状态为无色模式，仅在 `demo/tui/snake.scm` 入口或显式 `style-enable!` / `with-color-mode #t` 下激活，零破坏旧有测试用例。

2. **`virtual-terminal` 对 ANSI 转义序列的兼容**：
   - 完善 `(liii tui terminal virtual state)`：新增 `%skip-ansi-csi` 与 `%vt-handle-char!`；
   - 在向虚拟屏幕 `vt-lines` 填字与推进光标时，自动跳过 ANSI CSI/SGR 序列；
   - 保证：
     1) `virtual-terminal-screen` 纯净返回干净的纯可见字符矩阵，所有行宽与元素坐标与原无色版 100% 对齐；
     2) `virtual-terminal-raw` 完整保留包含 ANSI SGR 的原始流，供断言样式正确性；
     3) 现有所有基于 `virtual-terminal-screen` 的断言零破坏。

3. **文本宽度与差分渲染兼容性**：
   - `display-width` 天然支持 `strip-ansi`，保证带 ANSI 字符的可见宽度恒等于原可见字符数；
   - `screen-diff` 使用 `string=?` 比较字符串，包含样式的字符串在颜色发生改变时能产生 `update`；
   - `%render-diff-op!` 使用 `display-width` 判断缩短行，清除尾部不会因颜色代码误判；
   - 保持 DECSET 2026 同步输出与单帧写入完整性，零闪烁。

4. **无色降级一致性**：
   - 当 `NO_COLOR` 启用或禁用样式时，`render-grid-lines`、`make-game-view`、`make-game-over-view` 产生的内容与此前版本完全一致，保障跨平台终端降级安全性。

## 真实终端观感说明（人工确认规范）

- **必须实机人工确认**：在 Windows Terminal 中运行 `bin/gf demo/tui/snake.scm` 观察真实终端观感；
- **色彩层次效果**：
  - 棋盘：蛇头 `@` 呈现鲜亮粗体绿，蛇身 `o` 呈现细腻草绿，食物 `*` 呈现高警示粗体亮红，双线边框中嵌有青色粗体标题；
  - 侧栏：`STATS` 与 `HELP` 标题青色，`Score`、`Best`、`Length` 数值明亮黄色高亮，`Heartbeat` 伴随跳动呈现洋红色动画，按键操作说明使用低调灰色衬托；
  - 结束界面：`=== GAME OVER ===` 与 `RECORD` 呈现粗体亮红色框与文字。
- **关于闪烁的严格判定**：
  - **切勿使用单张静态截图来判定是否存在闪烁**；
  - 闪烁的本质是瞬时绘制中间态或帧间空白窗，需通过 `064-capture.py`（每秒 15+ 帧连拍并由逐像素判定中间行空白事件）以及肉眼连续动态观察判定；
  - 实测连续多秒运行保持 `events=0`，画面坚如磐石，无任何肉眼可见之抖动或闪烁。
