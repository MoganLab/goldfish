## 验收点

1.0 **集成 `(liii tui loader)` 的 Spinner 动画与工具卡片状态数据结构**：
- 定义 ToolCard 数据结构（或 record/vector），包含 `id`、`tool-name`、`args-summary`、`status`（`'running`、`'success`、`'failed`）、`start-time`、`elapsed-seconds`、`result-summary`、`spinner` 实例；
- 提供创建与状态流转接口：`make-tool-card`、`tool-card-tick!`、`tool-card-complete!`、`tool-card-fail!`；
- 参数类型非法时按 Goldfish 规范抛出 `type-error`。

2.0 **收到 `tool_execution_start` 事件时追加并激活状态卡片**：
- 收到工具执行开始事件后，格式化命令行参数摘要，生成状态为 `'running` 的 ToolCard；
- 运行中展示单行动态格式：`[⠋] <tool-name>: <args-summary>`（帧符随 tick 切换）；
- 正确加入 TUI 状态管理器（`state.scm`）的活跃工具列表。

3.0 **主事件循环在 RUNNING 节拍驱动 Spinner 动画帧原地刷新**：
- 在状态机处于 `RUNNING` 状态时，主循环定时 tick（如每 80ms~100ms）驱动活跃 ToolCard 的 `spinner-tick!`；
- 每次 tick 置脏屏幕（`state-dirty!`），主视口触发差分重绘，终端呈现平滑旋转的 Spinner；
- 耗时计算：持续统计或在结束时结算运行秒数（精确到 0.1s）。

4.0 **收到 `tool_execution_end` 事件时 Spinner 停止并平滑替换**：
- 收到执行结束事件后，停止 Spinner 动画；
- 成功态平滑替换为完成卡片：`[✓] <tool-name> (<elapsed>s)`，下方可附带单行或简要结果摘要；
- 失败态平滑替换为错误卡片：`[✗] <tool-name>: failed (<elapsed>s)`，下方展示错误信息摘要；
- 保证差分重绘时行高与内容过渡平滑无闪烁。

5.0 **TDD 单元测试覆盖与门禁验证**：
- 为 ToolCard 创建、Spinner tick 推进、状态变更（成功/失败/耗时）、渲染行排版等编写全面单元测试；
- 门禁四连：`timeout 600 xmake b goldfish`、`timeout 120 bin/gf fmt`、`git diff --exit-code`、`timeout 120 bin/gf check`；
- 全量测试 100% 通过无回归。

## 日期 任务描述

### What

1. 依据 `Agents.md` §3 任务 088 规格建立任务文档 `tools/pi/devel/088.md`；
2. 明确工具调用生命周期看板、Spinner 多帧驱动、完成/失败平滑替换以及 TUI 渲染整合的验收标准。

### Why

在编码 Agent 执行复杂任务时，工具调用往往耗时数秒至数分钟（如编译、跑测试、多文件编辑）。
若终端无即时反馈，用户将面对静止界面产生悬停甚至卡死疑虑。
通过集成 Spinner 帧动画与动态结果卡片，用户能实时感知当前正在执行的具体工具与参数，并在完成后清晰审阅耗时与执行结果。

### How

1. 利用 `(liii tui loader)` 内置的 `make-spinner`，配合预设 frames 提供平滑帧动画；
2. 在 `tool_card.scm` 中封装纯数据状态与格式化渲染函数；
3. 将事件处理挂接到 `state.scm` 与 `viewport.scm`，主循环通过 tick 驱动置脏刷新；
4. 编写 `tool_card-test.scm` 进行 TDD 验证。
