### 提炼（LLM 单发分析，实测）

- 分析器是**独立 CLI**（npm bin `pi-cl-analyze`），对每个工程做**一次**
  `complete()` 调用：输入 = 已有 instincts（紧凑 JSON）+ 新观察（预处理后）+ AGENTS.md，
  输出 = JSON change-set（`create` / `update` / `delete`），由客户端校验后落盘；
- **三层质量过滤**：Tier1 工程约定 → project 作用域；Tier2 通用工作流 → global 作用域；
  Tier3 通用 agent 行为（先读后改、跑 lint 等）**直接丢弃**；
- 保守规则：需 3+ 条独立观察支撑；新 instinct 初始置信度上限 0.85；
  与已有 instinct 相似度 ≥0.6（Jaccard）视为重复，拒绝新建；
- **实测一（零产出）**：首轮 32 条观察，内容是「先读文件 → bash 列目录 → 总结」，
  属 Tier3 → **创建 0 条**（`instincts: +0 ~0 -0`，tokens 6214，$0.0086）；
- **实测二（成功提炼）**：随后 3 个会话反复执行「改代码前跑 `npm test -- --run`、
  改完再跑一次」的工程约定，观察累计 220 条 → 分析器**创建 1 条** project 作用域 instinct。

### 置信度与作用域（实测）

| 环节 | 规则 |
|---|---|
| 初始置信度 | 按 `observation_count` 分档：1-2 → 0.3；3-5 → 0.5；6-10 → 0.7；11+ → 0.85 |
| 反馈增量 | confirmed：+0.05（第 1-3 次）/ +0.03（4-6 次）/ +0.01（7+ 次）；contradicted：-0.15；inactive：0 |
| 被动衰减 | -0.05 / 周（分析器每次运行前统一施加一次） |
| 截断 | `[0.1, 0.9]`；低于 0.1 标记 `flagged_for_removal` |
| 算术归属 | **客户端重算**（不信任模型给的置信度算术）；同一会话只计一次确认（`last_confirmed_session` 去重） |

- 作用域两档：**project**（工程内，Tier1）与 **global**（跨工程，Tier2）；
- `project_id` = `sha256(remote || root)` 前 12 位（无 remote 时取 root 绝对路径），
  沙箱实测 `0bbadc08d95f`。

### 注入形态（实测）

会话每个 turn 前把 instincts 追加到系统提示词末尾：

```
## Learned Behaviors (Instincts)
- [0.70] when modifying code files: Always search with grep to find relevant context before editing files.
- [0.55] before making any code changes in this project: Run npm test with the run flag to confirm the baseline passes before editing code, and run it again after modifying files to verify tests pass.
```

- 过滤：`confidence >= min_confidence`（默认 0.5）且未标记移除；
- 排序：**领域匹配优先**（由 prompt 关键词推断 domain，`workflow`/`git` 为通用域恒优先），
  其余按置信度降序；
- 上限：`max_instincts` = 20 条、`max_injection_chars` = 4000 字符；预算不足时追加
  `(1 lower-confidence instinct omitted)`（复数时 `instincts`）——实测把
  `max_injection_chars` 调到 200 后即出现该行；
- **实测：领域只影响排序、不影响过滤**——`domain: testing` 的 instinct 在与测试无关的
  prompt 中仍被注入；
- **实测：低于阈值的 instinct 不注入**——`confidence: 0.4` 的 instinct 未出现在注入块中；
- 事实（facts）另起一段 `## Project Knowledge`，格式 `- [0.80] The test database runs on port 3306`。

### 实测缺陷（八条，均有实测或源码依据）

1. **print 模式吞掉扩展输出**：`pi -p "/instinct-status"` 退出码 0、**stdout 0 字节**
   （与 044 偏差 #15、045 #17、046 #21、047 #27、048 缺陷 1 同源：扩展的
   `ctx.ui.notify` / `sendUserMessage(deliverAs:"followUp")` 在 print 模式下被丢弃）。
2. **后台分析器与 pi 0.85.1 不兼容（启动即崩）**：扩展 0.14.4 的 peer 范围是
   `^0.74.0`，而本机 pi 是 0.85.1 —— pi-ai 0.85.1 把 `complete` 迁到
   `@earendil-works/pi-ai/compat`、`AuthStorage` 不再从包根导出、
   `ModelRegistry.create(authStorage)` 签名已变 →
   `node dist/cli/analyze.js` 直接 `SyntaxError: The requested module
   '@earendil-works/pi-coding-agent' does not provide an export named 'AuthStorage'`
   启动失败（本次对照靠本地给 `dist/cli/analyze-model.js` 打补丁绕过）。
3. **分析器不读 pi 的 httpProxy**：`settings.json` 的 `httpProxy` 对 CLI 无效，
   国内网络下模型调用报 `fetch failed`（需自行设置 `HTTPS_PROXY` +
   `NODE_USE_ENV_PROXY=1` 才能跑通）。
4. **`pi install` 不把 `pi-cl-analyze` 链进 PATH**：npm 的 bin 目录未被链接，
   README 里的 `pi-cl-analyze` 命令开箱不可用（本次对照直接用 `node dist/cli/analyze.js`）。
5. **默认分析器 provider 不可达**：默认 `provider: anthropic` / `model: claude-haiku-4-5`
   （本机无 Anthropic 访问权限，且 Anthropic 不在维护范围）；
   配置改 `google/gemini-3.8-flash` 后才可用。
6. **无内置调度器**：Linux 下需自行配 cron / launchd；不装调度器则观察只增不析，
   置信度既不更新也不衰减。
7. **触发门槛偏高**：`min_observations_to_analyze` 默认 20，单工程观察不足 20 条时
   分析器直接跳过（本次对照临时调到 5）。
8. **注入标题文档与实现不一致（次要）**：实现常量是
   `## Learned Behaviors (Instincts)`（美式 Behaviors），README 写的是
   `## Learned Behaviours (Instincts)`（英式 Behaviours）。

## 形态裁定

脚本模式无 TUI、无斜杠命令、无后台守护进程、无 `~/.pi/continuous-learning/` 共享目录，
但 continuous-learning 的核心价值是**「会话 → 观察 → 提炼出可复用 instinct → 注入下一轮
→ 反馈闭环更新置信度」**这条链路。裁定如下（务实裁剪：六扩展中最复杂的一个，
只保留链路主干，砍掉整合/毕业/全局作用域/事实条目/导入导出）。

### 1. 命令面：2 个 CLI 开关 + 1 个逃生舱

```bash
# 打印 instincts 状态报告（纯本地，不调模型、不需凭据）
bin/gf pi --instinct-status

# 从工程内的观察流水提炼 instincts（单次 LLM 调用），报告写 stdout
bin/gf pi --instinct-extract

# 关闭系统提示词注入（逃生舱）
bin/gf pi --no-instinct-inject "..."
```

互斥与前置（`instinct/args.scm` 校验，报可读错误并退出码 1）：

- `--instinct-status` 与 `--instinct-extract` 互斥（一次调用只做一件事）；
- 二者与 `--code-review` / `--simplify` / `--red-green` / `--blueprint` /
  `--codemap` / `--tour` 互斥（同一轮只能有一种工作流，对齐 046/047/048 的校验风格）；
- `--no-instinct-inject` 只能与常规会话（带 prompt）同用，不与两个工作流开关同用；
- `--instinct-status` **不需要凭据**（纯本地读文件）；`--instinct-extract` **需要凭据**
  （要调 LLM），凭据缺失按既有错误规范报错并退出码 1。

### 2. 落盘位置：工程内 `.pi/`，绝不写 `~/.pi/`

- `.pi/instincts/<id>.md`：instinct 本体（YAML frontmatter + 正文，与 native 同构，
  人类可读可手改）；
- `.pi/observations.jsonl`：会话观察流水（追加写）；
- `.pi/instinct-config.json`：可选配置（`min_confidence` / `max_instincts` /
  `max_injection_chars` / `model` / `provider`）；
- **绝不写 `~/.pi/` 任何目录**（native 写 `~/.pi/continuous-learning/`，与原生 pi 共存时
  会互相污染；本项目对 `~/.pi/agent/` 一直保持只读复用约定，不应例外）。

### 3. 观察记录：会话内记录 + 写盘前清洗与预处理

- 会话期间记录 `user_prompt` / `tool_start` / `tool_complete` / `turn_end` /
  `agent_end`（与 native 事件集一致，字段形态对齐 native）；
- 写盘前做秘密清洗（bearer / api_key / secret / `AKIA…` / `sk-ant-…` → `[REDACTED]`）
  与长度截断（5000 字符，对齐 native）；
- 发给 LLM 前的预处理与 native 一致：丢弃 `turn_start` 与 `tool_start`；
  成功 `tool_complete` 剥离 `output`；失败保留错误输出；
- 观察行带 `active_instincts`（本轮注入的 instinct id）——闭环验证的输入。

### 4. 提炼：单次 LLM 调用 + 客户端应用 change-set

- system prompt 移植 native 的分层规则（Tier1 工程约定 / Tier2 通用工作流 /
  Tier3 丢弃）、保守规则（3+ 观察、初始置信度上限 0.85）、置信度分档、
  AGENTS.md 去重、矛盾检测提示；
- user prompt = 已有 instincts 紧凑 JSON + 新观察（预处理后）+ 工程 AGENTS.md；
- 模型只返回 JSON change-set（`create` / `update` / `delete`），**客户端**负责：
  字段校验、kebab-case 检查、相似度去重（≥0.6 拒绝新建）、置信度截断、
  写入 `.pi/instincts/<id>.md`；
- 提炼用**主模型**（不引入独立模型通道，理由同 045 偏差 #18），
  LLM 调用必须带超时（默认沿用 `--timeout`，120s）。

### 5. 置信度：纯函数移植 native 表，客户端重算

- `initial-confidence`（按观察数分档 0.3/0.5/0.7/0.85）；
- `adjust-confidence`（confirmed +0.05/+0.03/+0.01 三档递减；contradicted -0.15；
  inactive 0）；
- `apply-passive-decay`（-0.05 / 周）；
- 截断 `[0.1, 0.9]`，低于 0.1 标记移除；
- **不信任模型给的算术**：确认/矛盾增量由客户端按上表重算，并做
  `last_confirmed_session` 的每会话去重（对齐 native `buildInstinctFromChange`）。

### 6. 作用域：只做 project 作用域

- 全部 instinct 落工程内 `.pi/instincts/`（脚本模式按 cwd 隔离，避免跨工程互污）；
- **不做 global 作用域**（native 的 Tier2 通用工作流因此降级为 project 作用域，
  记录为有意偏差）；**不做** `/instinct-promote`。

### 7. 注入：会话开始时一次性注入

- 过滤：`confidence >= min_confidence`（默认 0.5）且未标记移除；
- 排序：领域匹配优先（由 prompt 关键词推断 domain，`workflow`/`git` 为通用域恒优先），
  其余按置信度降序（对齐 native `filterInstincts`）；
- 上限：`max_instincts` = 20、`max_injection_chars` = 4000；预算不足追加
  `(N lower-confidence instinct(s) omitted)`（对齐 native 文案）；
- 注入块标题沿用实现里的美式拼写 `## Learned Behaviors (Instincts)`；
- `--no-instinct-inject` 关闭；**无 instinct 文件即不注入**（既有会话行为零变化）。

### 8. 闭环验证：观察带 `active_instincts`，提炼时一并判定

- 上一轮注入的 instinct id 随观察落盘；
- `--instinct-extract` 时把这些 id 交给模型判定
  `confirmed` / `contradicted` / `inactive`（对齐 native 的 feedback 分析：
  「注入且被遵循且用户未纠正 → confirmed」；「注入但出现工具错误 → contradicted」；
  「注入但触发条件未出现 → inactive」），
  客户端按第 5 节的表重算置信度并写回；
- **不做**被动衰减的定时任务（脚本模式无守护进程）；衰减函数保留，提炼时按
  `updated_at` 顺带施加一次（对齐 native「分析前统一施加一次衰减」）。

### 9. 内置工具：四个

| 工具 | 入参 | 返回 |
|---|---|---|
| `instinct_list` | 可选 `scope` / `domain` | `N instinct(s):` + 每条 `[0.70] id (domain, scope)` + `Trigger:` / `Action:`；无匹配时 `No instincts found matching the given filters.` |
| `instinct_read` | `id` | 单条同款形态 |
| `instinct_write` | `id/title/trigger/action/confidence/domain/scope/计数/evidence` | `Created instinct: <id>` / `Updated instinct: <id>`；校验失败 `Invalid instinct: <reason>`；重复 `Similar instinct already exists: "<id>" (similarity: N%). …` |
| `instinct_delete` | `id` | `Deleted instinct: <id> (was <scope>-scoped)` |

- 四个工具**默认注册**（对齐 native：模型随时可记录/查阅工程约定），
  `--no-tools` / `--exclude-tools` 可关闭；
- 显式给出 `--tools` 白名单时**不自动追加**（白名单即用户意图，同 048 决策）；
- 四个工具**不进 `PI_ALL_TOOL_NAMES`**（与 `tdd_*` / `blueprint_*` / `codebase_map` 同款约定：
  工作流工具不占可选工具清单），既有 `pi-tools-basic-test.scm` 的
  `(length PI_ALL_TOOL_NAMES) => 8` 断言不受影响；
- **不做** `instinct_merge`（用 write + delete 组合替代）与四个 `fact_*` 工具。

### 10. 不做项（务实裁剪）

- facts / 知识条目（`## Project Knowledge` 段）——本任务只做 instincts；
- `/instinct-dream`、`/instinct-evolve`（LLM 整合/去重/晋升）——留给后续任务；
- `/instinct-graduate`（毕业到 AGENTS.md / skill / command）；
- `/instinct-promote`（提升到 global）、`/instinct-export`、`/instinct-import`、
  `/instinct-projects`；
- 后台守护进程与定时调度（无 cron / launchd 集成）；
- 事实的 `fact_*` 工具族与事实注入段。

### 11. 输出形态

- print 模式：`--instinct-status` / `--instinct-extract` 的报告**写 stdout**
  （修 native 的 print 空输出缺陷，实测缺陷 1）；
- JSON 模式：stdout 保持**纯 JSONL**（既有事件序列完全不变），
  报告摘要写 **stderr**（对齐 045/046/047/048 的 stdout/stderr 分流）；
- `--instinct-status` 不调用模型 → 不产生 agent 事件流（无凭据也能跑）；
- `--instinct-extract` 是「一次 LLM 调用 + 落盘」的独立流程，不进入 agent 循环
  （不产生 agent 事件流）。

### 12. 安全与既有规范

- 每条命令、每次 IO 都有超时（提炼的 LLM 调用必带 `:timeout`）；
- 错误信息人可读且可诊断（含原因摘要），退出码语义按 print 规范（错误退出码 1）；
- 日志不写凭据、代理地址与请求体；观察落盘前做秘密清洗；
- 只读工程内文件；状态只写工程内 `.pi/`；
- 单文件不超过 300 行（`bin/gf check` 硬约束），超限继续拆子模块。
