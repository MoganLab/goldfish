### 原生 `/review` 的行为（实测）

1. **命令面**：`/review`（审查未提交改动）、`/review --staged`（只审查暂存区）、
   `/review --ref=main`（与指定 ref 比较）、`/review src/foo.ts`（审查指定文件）。
   默认 ref 为 `HEAD`，即 `git diff --name-status HEAD`（含暂存 + 未暂存）；
   该命令失败时回退 `git diff --name-status HEAD~1`；最多审查 10 个文件
   （超出时提示 `Reviewing first 10 of N changed files.`）。
2. **无变更文件**：通知 `No changed files found. Specify file paths or make some
   changes first.`（RPC 模式实测为 `extension_ui_request` / `notify` / `info` 事件）。
3. **有 Anthropic key 时**走 `claude-haiku-4-5-20251001` 直连，要求模型返回
   `{"findings":[{"severity","file","line","category","message","suggestion"}]}`，
   解析后格式化为
   `## Code Review Findings (2 CRITICAL, 1 HIGH)` + `- **CRITICAL** [category] file:line: message`
   + `  Suggestion: ...`；无问题时输出
   `Code review complete: no issues found. Code looks clean.`。
   **本机 Anthropic 通道不可用**，实测落到 fallback 分支。
4. **fallback（无 key 或直连失败）**：把提示词交给会话 agent
   （`Review the following recently changed files for code quality issues. Read each
   file, then report findings.` + Format 段：Severity CRITICAL/HIGH/MEDIUM/INFO、
   File 与行号、Category、Issue 与 suggestion + 分语言 Focus areas 清单 +
   文件列表 + `Read each file, identify issues, and report your findings. Fix any
   CRITICAL or HIGH issues immediately.`），agent 读文件后给出报告，
   **并且会直接改写文件修复 CRITICAL/HIGH**（实测改写了 `src/app.ts` 与 `src/auth.ts`）。
5. **语言检测**：`.ts/.tsx/.js/.jsx`→typescript、`.py`→python、`.go`→go、
   `.rs`→rust、`.java`→java、`.php`→php；每语言 5 条检查清单
   （如 typescript：Type safety / Error handling / Null safety / Naming / Security）。
6. **自动审查（零成本）**：hook `tool_execution_end` 收集 Write/Edit 改过的文件 →
   `turn_end` 快照 → `before_agent_start` 向系统提示词注入
   `## Code Review\n\nYou edited: <files>. Before proceeding, briefly verify:<checklist>\n\nFix any issues found, then continue.`。
   **本机 pi 0.85.1 实测未触发**：内置工具名是小写 `read/bash/edit/write`，
   而扩展只跟踪 `"Write"/"Edit"`；且 write 工具结果是
   `{content:[{type:"text",text:...}]}`，不含 `file_path`/`path`，路径提取同样失败。
7. **print 模式缺陷**：`pi -p "/review"` 退出码 0 但 stdout 为空——扩展的异步
   follow-up 回合没有被 print 模式等待；只有 `pi --mode rpc` 才能观察到完整审查输出。

原生扩展源码位置：`~/git/pi-extensions/packages/pi-code-review/src/`
（`index.ts`、`review-command.ts`、`review-prompt.ts`、`review-parser.ts`、
`review-injector.ts`、`language-detector.ts`、`edit-tracker.ts`）。

## 形态裁定

脚本模式无 TUI、无斜杠命令，映射为 CLI 开关，语义与原生 `/review` 对齐：

```bash
# 主动审查：审查未提交改动（git diff --name-status HEAD，回退 HEAD~1）
bin/gf pi --code-review
# 只审查暂存区
bin/gf pi --code-review --staged
# 与指定 ref 比较
bin/gf pi --code-review --ref=main
# 审查指定文件
bin/gf pi --code-review src/foo.ts src/bar.py

# 自动审查：write/edit 之后的下一回合注入分语言检查清单
bin/gf pi --auto-review "实现 xxx 功能"
```

- 报告输出：print 模式 stdout 打印 Markdown 报告（标题含各严重级计数、按严重级
  降序、每条含 `file:line` 与 `Suggestion`）；JSON 模式沿用既有事件流。
- 严重级：`CRITICAL > HIGH > MEDIUM > INFO`，语义与原生一致
  （安全漏洞/数据丢失/崩溃 → 缺陷与类型安全 → 反模式与可维护性 → 风格）。
- 结构化输出契约：要求模型返回 JSON findings（与原生 Haiku 分支同款），
  解析容忍 ```json 围栏；解析失败降级为一条 INFO 级 `parse-error` 记录，不抛异常。
- 语言清单在原生 7 种语言之外**追加 Scheme（`.scm`）**，因为本项目主体语言是 Scheme。

### 与原生 pi 的有意偏差（登记到 PI_PLAN §7 偏差清单）

| # | 偏差 | 理由 |

| 12 | 审查默认**只读**，不自动修复被审查文件 | 原生 fallback 会直接改写文件；脚本模式默认不改用户工作树，修复由用户显式再发起 |

| 15 | print 模式直接打印报告 | 原生 `pi -p "/review"` 因异步 follow-up 未被等待而 stdout 为空 |

## 验收点

1. **CLI 形态与参数解析**：
   - `bin/gf pi --code-review` 审查未提交改动；`--staged` 只审查暂存区；
     `--ref=REF` 与指定 ref 比较；位置参数为指定文件列表（与原生 `/review` 对齐）；
   - 未支持的组合（如 `--code-review` 与 `--auto-review` 同时给出）报可读错误并退出码 1；
   - 未知选项进入既有 unknown-flags 处理，不静默吞掉。
2. **变更文件收集**：
   - 通过 bash 工具执行 `git diff --name-status`（必带 `:timeout`），解析 `M/A/R/C`
     状态与路径（重命名/复制取第三段路径）；
   - 默认 ref 为 `HEAD`；该命令失败时回退 `HEAD~1`；两者都无结果时输出
     `No changed files found...` 提示并退出码 0；
   - 文件数超过上限时按上限截断并给出提示。
3. **语言检测与检查清单**：
   - 按扩展名映射 typescript/python/go/rust/java/php/scheme，未知扩展名不进入清单；
   - 生成与原生等价的分语言检查清单段落（每语言 5 条），多语言时按语言去重合并。
4. **审查提示词构造**：
   - 含 JSON 结构化输出契约、严重级语义说明、无问题时的 `{"findings": []}` 约定、
     分语言检查清单与待审查文件列表。
5. **审查执行与解析**：
   - 走既有 agent 循环（当前 provider、既有超时/重试/会话规范）；
   - 解析 JSON findings，容忍 ```json 围栏；解析失败降级为 INFO 级 `parse-error`
     记录并继续输出报告，不抛未捕获异常。
6. **报告输出**：
   - print 模式 stdout 打印 Markdown 报告：标题含各严重级计数、条目按严重级降序、
     每条形如 `- **CRITICAL** [category] file:line: message` 并附 `  Suggestion: ...`；
   - 无问题时输出 `Code review complete: no issues found. Code looks clean.`；
   - JSON 模式输出对应事件且不破坏既有事件序列。
7. **自动审查清单注入**：
   - `bin/gf pi --auto-review "<prompt>"` 时，write/edit 工具调用后的下一回合系统
     提示词追加 `## Code Review` 块（You edited: ... / before proceeding verify 清单）；
   - 未开启该开关时行为与现状完全一致（零回归）。
8. **边界与安全**：
   - 审查只读，不修改被审查文件；
   - 无凭据/超时/网络失败按既有错误规范报错并退出码 1；
   - 日志不泄露 API key、代理地址与请求体；
   - 所有外部命令与网络 IO 均带超时。
9. **回归与门禁**：
   - `bin/gf pi` 既有测试全绿；新增单元测试镜像源码库结构（一个函数一个测试文件）；
   - `xmake b goldfish` → `bin/gf fmt` → `git diff --exit-code` → `bin/gf check`
     → `bin/gf doc --build-json` 依次通过；单文件不超过 300 行。

4. **解析与格式化**：JSON 解析 + 围栏剥离 + 逐条字段校验（severity 白名单），

  → 退出码 1，stderr `Stream idle timed out after 5 seconds`。
- `bin/gf pi --code-review --auto-review x` → 退出码 1，错误可读。
- `--ref=main`、`--ref main` 解析通过；`--ref=main` 单独出现退出码 1。
