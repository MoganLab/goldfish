## 验收点

- CLI 参数解析支持：
  - 支持 `--exclude-tools <tools>` 命令行选项，接收逗号分隔的工具名称字符串（如 `--exclude-tools bash,write,edit`）。
  - 未指定时默认值为 `#f`，不改变既有工具解析行为。
- 工具排除过滤逻辑：
  - 从基准工具集（默认工具集或通过配置/参数指定的工具集）中排除黑名单中的工具。
  - 支持逗号分隔的多个工具名称，并去除首尾空白字符（如 `"bash, edit"`）。
  - 容错性与健壮性：排除列表中包含不存在或未启用的工具名时（如 `foo,bash`），安全忽略未知工具名称，正常剔除存在的工具（`bash`），其余工具保持不变。
- 白名单与黑名单共存时的优先级（排除优先）：
  - `--tools` 为白名单替换（显式指定可用工具列表）。
  - `--exclude-tools` 为黑名单排除。
  - 两者共存时**排除优先**：先根据 `--tools`（或 settings 配置）确定工具列表，再从该列表中排除 `--exclude-tools` 指定的工具（例如 `--tools read,bash,edit --exclude-tools bash` 最终结果为 `("read" "edit")`）。
  - 仅指定 `--exclude-tools` 时，从默认工具集 `("read" "bash" "edit" "write")` 中排除指定工具（例如 `--exclude-tools bash,write,edit` 快速变为只读模式 `("read")`）。
- 帮助文本与文档：
  - `bin/gf pi --help` 包含 `--exclude-tools <list>` 的选项说明。
  - `PI_SPEC.md` 包含 `--exclude-tools` 的说明与典型用法示例。
- 门禁检查与测试全绿：
  - `timeout 600 xmake b goldfish`
  - `timeout 120 bin/gf fmt`
  - `git diff --exit-code`
  - `timeout 120 bin/gf check`
  - `bin/gf doc --build-json`
  - 既有单元测试与相关新增测试全绿。

#### Why

- 当前 `bin/gf pi` 仅支持 `--tools` 白名单替换机制；在需要快速关闭高危工具（如关闭写操作变成只读审计模式：`--exclude-tools bash,write,edit`）时，用户需显式列出所有想要保留的工具，不够便捷灵活。引入 `--exclude-tools` 黑名单排除机制可极大提高安全性与使用便利度。

#### How

- 在 `tools/pi/liii/pi/args.scm` 中增加 `--exclude-tools` 命令行参数项。
- 在 `tools/pi/liii/pi/tools.scm` 或 `tools/pi/liii/pi/config.scm` 中实现排除过滤逻辑，并集成到 `resolve-active-tools` 中。
- 遵循 TDD 规范，分别在 `pi-args-test.scm`、`pi-tools-basic-test.scm` 和 `pi-config-test.scm` 中添加针对排除生效、未知工具过滤、与 `--tools` 组合优先级等测试用例。
- 更新 `tools/pi/liii/pi/help.scm` 与 `PI_SPEC.md`。
