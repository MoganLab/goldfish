## 2026-10-20 任务描述

### What

1. 建档任务 050（文档阶段完成）；
2. 梳理 deepseek tool_use 在 anthropic 协议层触发 `value-error (("input") ...)` 的复现路径与取证信息；
3. 在开发阶段将通过 TDD 补充单元测试，修复 input 参数解析与序列化问题，并进行真实冒烟验证。

### Why

差距清单 #11：在任务 037 开发自举过程中，使用 deepseek 模型执行首轮包含大上下文 prompt 时连续两次秒崩，会话文件仅记录 2 行，导致 deepseek 作为主力模型在首轮大上下文 tool 调用时无法稳定工作。必须彻底定位并根治此解析缺陷。

### How

1. 根因分析：
   - 在 goldfish C++ 扩展 `src/liii_json.cpp` 的 `json_write_object_entry` 中，对象的每一个 entry 必须是 dotted pair（`chain_length == -1`）或长度 >= 2 的 list；
   - 若出现 `("input")`（即 `(list "input")`），链长为 1，将抛出 `json_write_exception{"value-error", " must be null, pair, or list with at least 2 elements", d, false}`；
   - 在 Scheme 端，当 arguments 为 `'()` 时，若执行 `(cons "input" '())` 会产生 `("input")`；或者当 API 返回的 tool_use input 为 JSON 字符串时未被解析反序列化，或 deepseek stream-parse 中 delta 拼接后的参数结构不符合 alist 规范。
2. 修复思路：
   - 在 `anthropic-parse-response` 与流式 `stream-parse` 中，对 `input` 统一进行结构归一化：若为 JSON 字符串则先 `string->json`；若为空则保证为 `'()` 且序列化时使用正确 key-value 对或空对象表示；
   - 在 `pi-block->alist` 与 `%assistant-blk->anthropic-blk` 中，确保 `"input"` 对应的 entry 在为空时不会退化成 `("input")`；
   - 增加单元测试与回归断言。
