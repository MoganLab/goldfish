## 验收点

- 差距清单 #10（用户怀疑方向，已实证）：
  - auth 解析此前优先读取 `auth.json` 存储条目，导致设置 `KIMI_API_KEY` 环境变量时被 `auth.json` 中的旧 key 忽略覆盖，假 key 也返回周配额 403 而非 401。
- 修复凭据解析优先级为环境变量优先（env > auth.json）：
  - 当对应 provider 的环境变量存在且为非空字符串时，优先使用环境变量中的 API Key，不读取 `auth.json` 中的配置。
  - 当环境变量未设置或为空字符串时，回退使用 `auth.json` 中的配置。
  - 解锁用户通过 `KIMI_API_KEY` 环境变量切换不同 Key 分摊周配额的能力。
- 同步核查并统一其他 Provider 的环境变量优先级：
  - `kimi-coding`：`KIMI_API_KEY` 优先于 `auth.json`。
  - `google`：`GEMINI_API_KEY` 优先于 `auth.json`。
  - `anthropic`：`ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` 优先于 `auth.json`。
  - `glm`：`ANTHROPIC_AUTH_TOKEN` / `GLM_API_KEY` / `ANTHROPIC_API_KEY` 优先于 `auth.json`。
  - `deepseek`：`DEEPSEEK_API_KEY` 等优先于 `auth.json`。
  - 均未配置且无可探测文件时，返回 `#f`。
- TDD 单测覆盖：
  - 在 `tools/pi/tests/liii/pi/pi-resolve-provider-key-test.scm` 中，将既有“存储条目优先”的假设修改为“环境变量优先”；
  - 针对各 provider 编写当同时存在 `auth.json` 条目与环境变量时，断言解析结果为环境变量值的单测用例。
- 门禁检查与测试全绿：

#### Why

- 解决差距清单 #10：解除 `auth.json` 对环境变量的覆盖，使用户能够通过 `KIMI_API_KEY` 等环境变量自由切换 Key 分摊配额。

#### How

- `pi-resolve-provider-key` 先调用 `%resolve-provider-env-key`，仅当未设置或为空字符串/纯空白时才回退至 `auth-alist`，深层文件探测（如 deepseek）置于 `auth-alist` 之后兜底。

### 2026-10-19 任务建档

#### What

1. 查阅 `PI_PLAN.md` §3 任务 035（差距清单 #10）的验收点与背景说明。
2. 从 `tools/pi/devel/ddd.md` 模板复制建立 `tools/pi/devel/035.md` 任务文档。
3. 明确任务涉及的代码文件、验收点（环境变量优先于 auth.json、核查各 provider 环境变量解析、TDD 单测覆盖）、测试方案及门禁流程。

#### Why

- 当前 `pi-resolve-provider-key` 实现中，首要匹配 `auth-alist`，导致环境变量成为仅在 `auth.json` 不存在对应 provider 时的后备项。
- 当 `auth.json` 中配置了过期或配额耗尽的 key 时，用户试图通过环境变量 `KIMI_API_KEY=xxx` 覆盖该 key 无效，系统仍旧使用旧 key，严重阻碍多 key 切换与配额分摊。
- 明确修正凭据优先级规范为 `env > auth.json`，解决差距清单 #10。

#### How

- 在 `tools/pi/liii/pi/auth.scm` 的 `pi-resolve-provider-key` 中，先探测 provider 对应的环境变量，若环境变量存在且非空则直接返回；否则再探测 `auth-alist`（并按需回退深层文件如 deepseek 相关探测）。
- 更新 `tools/pi/tests/liii/pi/pi-resolve-provider-key-test.scm`，将原先存储优先的测试改为断言环境变量优先，并增加覆盖各 provider 在 env 与 auth.json 并存时的优先级单测。
