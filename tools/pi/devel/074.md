## 验收点

从 `tools/pi/Agents.md` §3 任务表 074 提取并细化：

1. **Prompt 注入器（Prompt Injectors）机制与动态装配**：
   - 扩展 API 支持注册 prompt-injector（如 `register-prompt-injector!` 或 `api.registerPromptInjector`）；
   - 注入器支持返回字符串或过程 `(lambda (tool-calls) ...)`，支持在不同轮次基于历史状态动态生成上下文；
   - `modes/flow.scm`（与提示词装配模块）通过当前活跃扩展注册表动态获取所有已启用的 prompt injectors，按注册顺序组合并追加到系统提示词中；
   - 彻底移出 `modes/flow.scm` 中硬编码的 `pi-auto-review-system-prompt`、`pi-tdd-turn-system-prompt`、`pi-blueprint-turn-system-prompt` 与 `pi-compass-turn-system-prompt` 分支；
   - 兼容既有 blueprint、compass 与 red-green 的上下文注入效果。
2. **`tool_call` 拦截钩子与 Input Override**：
   - 工具执行前派发 `tool_call` 事件，传递规范化 payload（`((name . <name>) (tool . <name>) (input . <args>) (id . <id>))`）；
   - 监听器可通过返回 `(override (input . <new-args>))` 替换原工具调用输入参数，工具按修改后的参数执行；
   - 监听器可通过返回 `(block (reason . <reason>))` 或 `((action . block) (reason . <reason>))` 拦截工具调用，工具不被实际执行，直接将 reason 封装为 tool-result 返回给 agent；
   - 多个监听器按顺序执行，单个监听器异常安全捕获并隔离，不影响整体流程。
3. **补齐原生 pi 的 `terminate` 语义**：
   - 对齐原生 `ToolCallEventResult.terminate` 语义（原生 `packages/coding-agent/src/core/extensions/types.ts:1462`）；
   - 拦截结果支持携带 `(terminate . #t)`；
   - 当某个工具调用被 block 且携带 `terminate: #t` 时，向 agent 循环发出批次终止信号，中断当前批次中剩余尚未执行的 tool calls（其余 tool calls 可标记为跳过或不执行），提示 agent 结束当前工具批次并基于拦截信息合成最终回复，而不是继续盲目执行后续工具。
4. **`tool_result` 生命周期事件派发**：
   - 在每个工具调用执行完毕后，派发 `tool_result` 事件，携带 `((name . <name>) (id . <id>) (input . <args>) (result . <text>) (isError . <bool>))`；
   - 移除 `agent/tools.scm` 中硬编码的 `(pi-tdd-write-gate ...)` 与 `(pi-tdd-observe-tool! ...)` 调用，通过插件机制订阅 `tool_call` 与 `tool_result` 实现相同能力。
5. **核心层提示词与工具说明解耦**：
   - 清理 `prompt.scm` 中硬编码的 `tdd_*`, `codebase_map`, `code_tour` 等非内置工具的 snippets 与 guidelines，改由注册表在构建 system prompt 时动态整合扩展工具声明的信息。
6. **严格门禁与代码规模控制**：
   - 生产代码严格遵守 <= 300 行硬约束：`modes/flow.scm`（当前 238 行）、`agent.scm`（当前 261 行）、`prompt.scm`（当前 269 行）、`agent/tools.scm`（当前 159 行）；
   - 单元测试 TDD 覆盖 prompt 注入、tool_call 拦截、input override、terminate 语义截断与 tool_result 派发；
   - 通过 `timeout 600 xmake b goldfish`、`bin/gf fmt`、`git diff --exit-code`、`bin/gf check`；
   - 提供 `tools/pi/devel/074.scm` 验收脚本，全部断言通过。

3. 设计 Prompt Injectors 机制：注册表存储注入器清单，在构建系统提示词时动态收集并调用注入器，支持静态追加与动态多轮上下文（`tool-calls -> text`）；
4. 完善 `(liii pi extension event)` 中的 `tool_call` 事件拦截逻辑：支持 `override`（修改 input）、`block`（拦截阻止）以及原生 pi 关键的 `terminate`（终止工具批次）语义；
5. 在 `agent/tools.scm` 中接入 `tool_call` 与 `tool_result` 事件派发，支持批次截断，并剥离硬编码的 TDD gate 和 observe；
6. 规划行数控制，确保 `modes/flow.scm`、`agent.scm`、`prompt.scm` 等文件行数均维持在 300 行安全红线以内。

### Why

在原生 pi 架构中，扩展的一大核心能力就是根据当前环境和任务状态动态丰富 system prompt（如 codemap 结构拓扑、blueprint 阶段要求、TDD 约束等），并在模型产生 `tool_call` 时进行参数校验、修改或权限拦截，甚至通过 `terminate` 机制引导 agent 立即收敛总结。
主仓库目前在 `modes/flow.scm` 中直接以硬编码的方式调用各个扩展的 prompt 注入函数，且在 `agent/tools.scm` 中直接写死 TDD 的写保护与执行观察，未能形成标准化的拦截钩子。这不仅破坏了扩展系统的正交解耦，而且遗漏了原生 pi 中至关重要的 `terminate` 语义。必须在 074 中实现通用的 prompt 注入与生命周期拦截机制。

### How

1. **Prompt Injectors 抽象**：
   在 `(liii pi extension types)` 中为 `extension-registry` 增加 `prompt-injectors` 字段；在 `(liii pi extension builtin)` 中提供 `register-prompt-injector!`；在 `modes/flow.scm` 中用 `(extension-registry-collect-prompt-injectors reg)` 动态替换硬编码链。
2. **`tool_call` 拦截与 Terminate 语义补齐**：
   在 `event.scm` 的 `pi-emit!` 中解析拦截返回结构，若返回结构中包含 `(terminate . #t)` 或 `((terminate . #t) ...)`，则最终 emit 结果标明 `(terminate . #t)`；在 `agent/tools.scm` 的批次循环中，若某工具调用触发 `terminate`，立即终止后续工具调用执行，返回已完成和拦截的结果列表，并通知 agent 循环。
3. **`tool_result` 派发**：
   工具调用完成后派发 `tool_result` 事件，传递规范化载荷，允许外部监听器完成状态更新和观察（如 TDD 测试分析）。
4. **行数控制与解耦**：
   将特定扩展从 `modes/flow.scm` 和 `agent/tools.scm` 彻底剥离，使这些核心文件行数不增反减，稳固维持在 300 行以内。
