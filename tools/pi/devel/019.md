## 日期 任务描述

### 2026-10-19 开发阶段完成

#### What

1. 在 `(liii pi auth)` 中支持 `"glm"` provider 的 API Key 解析：优先消费 `auth.json` 中的 `"glm"` 条目，未配置时通过 `ANTHROPIC_AUTH_TOKEN`、`GLM_API_KEY`、`ANTHROPIC_API_KEY` 环境变量兜底；无有效凭据时返回 `#f`。
2. 在 `(liii pi models)` 中为 `"glm"` 设置默认端点 `https://open.bigmodel.cn/api/anthropic`，上下文大小默认 128000，max-tokens 默认 8192；支持通过 `ANTHROPIC_BASE_URL` 或 `GF_PI_BASE_URL` 覆盖。
3. 在 `(liii pi config)` 中配置 `"glm"` 默认模型为 `"glm-4-plus"`，支持通过 `GLM_MODEL` 或 `GF_PI_MODEL` 环境变量覆盖。
4. 在 `(liii pi agent)` 的 `%request-provider-stream` 中将 `"glm"` 路由至现有的 `anthropic-request-stream` 流式处理链路，完整复用 Anthropic 协议与工具调用。
5. TDD 补齐单元测试与 stub 测试：
   - `pi-resolve-provider-key-test.scm`：glm 凭据优先级与环境变量测试
   - `pi-resolve-model-metadata-test.scm`：glm 默认端点、上下文及环境变量覆盖测试
   - `pi-config-test.scm`：glm 配置解析与默认模型测试
   - `pi-agent-test.scm`：glm 单轮流式事件与多轮工具调用 stub 测试
6. 真实冒烟验证：
   - 凭据缺失明确报错退出码 1
   - 真实 glm 端点纯文本输出通过（返回 PONG）
   - 真实 glm 端点 bash 工具调用往返通过
   - 真实 glm 端点 JSON 模式流式事件序列验证通过

#### Why

GLM 官方完全兼容 Anthropic Messages 协议（`/v1/messages`、SSE 流式事件与 tool_use），复用现有 Anthropic 链路是最精简、最健壮且维护成本最低的实现方式。

#### How

遵循小步快跑与最小改动原则：
1. 凭据解析、模型元数据与模型解析均采用最小修改，文件行数严格控制在 300 行门禁以下。
2. 保持对所有历史 provider（google, anthropic, kimi-coding）零破坏，111 项测试全部通过。

3. 在 `(liii pi agent)` 中，当 provider 为 `"glm"` 时，直接复用 `anthropic-request-stream` 执行请求。
