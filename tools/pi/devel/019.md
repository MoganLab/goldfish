## 验收点

- 凭据与端点发现（与 pi 共享机制一致）：
  - 凭据优先从 `~/.pi/agent/auth.json` 消费 `glm`（type: "api_key"）。
  - 若 `auth.json` 未配置，支持通过环境变量 `ANTHROPIC_AUTH_TOKEN` 或 `GLM_API_KEY` 兜底。
  - 端点默认走 `https://open.bigmodel.cn/api/anthropic`，支持通过 `ANTHROPIC_BASE_URL` 或 `GF_PI_BASE_URL` 环境变量覆盖。
  - 凭据缺失时明确报错（退出码 1，错误信息清晰可读，不静默挂起）。
- 复用 Anthropic 兼容路径：
  - 请求构造、消息映射、流式 SSE 解析与 function calling（工具调用）复用 Anthropic 协议实现。
  - 支持 `--provider glm` 命令行参数。

  - stub 单元测试覆盖 glm 的凭据解析、端点映射与模型配置。

## 日期 任务描述

### 2026-10-19 任务建档

#### What

1. 查阅 `PI_PLAN.md` §3 任务 019 验收点，明确 GLM provider 的复用方案与凭据端点规则。
2. 从 `tools/pi/devel/ddd.md` 模板建立 `tools/pi/devel/019.md` 任务文档。
3. 规划相关实现文件（auth/models/config/agent）、测试范围以及验收测试方案。

#### Why

根据用户裁定，GLM 与 DeepSeek provider 分开独立实现。GLM 官方提供了 Anthropic 兼容协议端点（`open.bigmodel.cn/api/anthropic`），复用既有的 Anthropic 协议流式请求与工具调用链路，可以最大程度复用高质量代码并与现有生态无缝衔接。

#### How

1. 在 `(liii pi auth)` 中，为 provider `"glm"` 增加凭据解析逻辑：优先从 `auth-alist` 获取 `"glm"` 条目，若无则检查 `ANTHROPIC_AUTH_TOKEN`、`GLM_API_KEY` 等环境变量。
2. 在 `(liii pi models)` 中，为 `"glm"` 设置默认端点 `https://open.bigmodel.cn/api/anthropic`，并在 `ANTHROPIC_BASE_URL` 或 `GF_PI_BASE_URL` 存在时允许覆盖；配置默认模型（如 `glm-4-plus`）及上下文大小。
3. 在 `(liii pi agent)` 中，当 provider 为 `"glm"` 时，直接复用 `anthropic-request-stream` 执行请求。
4. 编写针对凭据解析与模型元数据解析的单元测试，并在具备凭据时执行真实冒烟测试。
