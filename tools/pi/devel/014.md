## 验收点

1. prompt 包含 4 字节 UTF-8 字符（如 emoji 🚀、生僻字 𠀀 等）与 `<` 等特殊字符组合时，程序正常运行并返回输出，绝不静默挂起。
2. 复现命令 `timeout 60 bin/gf pi -p '🚀 <'` 在超时限制内正常完成（退出码 0，且 stdout 输出非空）。
3. JSON 模式调试与验证：`timeout 60 bin/gf pi --mode json -p '🚀 <'` 产生完整的事件序列流（`session` -> `agent_start` -> `turn_start` -> `message_update`* -> `turn_end` -> `agent_end` -> `agent_settled`），退出码为 0。
4. 流式空闲超时机制健全：在网络阻断或长时间无新数据块到达时，流式空闲超时（idle-timeout）必须可靠触发并结构化报错（退出码 1），杜绝无限卡死。
5. 防回归测试：新增或补全针对 4 字节 UTF-8 字符与特殊字符组合在流式解析与请求构造中的单元测试。
6. 门禁检查全部通过：
   - `timeout 600 xmake b goldfish`
   - `timeout 120 bin/gf fmt`
   - `git diff --exit-code`
   - `timeout 120 bin/gf check`
   - `bin/gf doc --build-json`

#### How 与历史失败记录

##### 1. 缺陷表现与历史失败排查记录
- **现象**：执行 `timeout 60 bin/gf pi -p '🚀 <'` 时发生静默挂起，超过 60s 仍未退出，且即使配置了流式空闲超时，超时机制也未按预期兜底退出。
- **前 3 次失败尝试分析**：
  1. *第 1 次尝试*：怀疑是 JSON 序列化字符转义（`<` 转义或 4 字节 UTF-8 截断导致 JSON 格式损坏），在 `(liii json)` 和 `pi-serialize-event` 补充了多组单元测试（commit `eedccff8`），单元测试均通过，但真实请求依然挂起。
  2. *第 2 次尝试*：在 stub server 环境中加入 `🚀 <` 的 CLI e2e 测试（commit `eedccff8`），由于 stub server 快速返回模拟数据，测试通过；但未能真实复现真实 Gemini 网络环境下的挂起场景。
  3. *第 3 次尝试*：旧代码定位曾局限在 `goldfish/liii/pi/provider.scm`，但由于当时核心库结构庞大且未完成 record 化，调试追踪困难，未能定位到根因，任务被回退。
