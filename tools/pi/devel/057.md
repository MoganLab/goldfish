### 架构约定与设计原则

1. **终端抽象规范（Terminal Protocol / API）**：
   - 终端接口提供一套统一操作方法，向上支撑差分渲染引擎（061）与上层交互组件，向下既支持脱机模拟的 `virtual-terminal`，也支持向真实标准输出/自定义端口输出 ANSI 转义序列的 `standard-terminal`；
   - 核心抽象接口规范包括：
     - `terminal?`：断言是否为终端实例；
     - `terminal-write`：向终端当前光标位置写入文本；
     - `terminal-size`：查询终端尺寸，返回 `(list width height)`；
     - `terminal-cursor`：查询当前光标坐标 `(list x y)`（0-indexed，x 为列，y 为行）；
     - `terminal-set-cursor!`：移动光标至指定位置 `(x, y)`，带边界安全约束；
     - `terminal-clear`：清屏并重置光标至 `(0, 0)`；
     - `terminal-clear-line`：清除当前行文本；
     - `terminal-hide-cursor!` / `terminal-show-cursor!`：控制光标显隐状态；
     - `terminal-cursor-visible?`：查询光标当前显隐状态；
     - `terminal-flush`：刷新终端输出。

2. **`virtual-terminal` 内存虚拟终端（脱机测试核心）**：
   - 完全在内存中维护字符二维网格/行缓冲区，具备 100% 确定性；
   - 支持多行文本写入、换行符（`\n`）与回车符（`\r`）语义：
     - `\n`：光标移动到下一行（超出底部时自动向上平滚滚动屏幕）；
     - `\r`：光标回到当前行首（x = 0）；
     - 普通字符写入：在当前 `(x, y)` 覆盖/填充对应网格位置，光标自动右移；
   - 维护原始调用日志 `virtual-terminal-raw`：完整记录写入的历史字符串流，便于底层转义序列断言；
   - 屏幕快照提取 `virtual-terminal-screen`：获取当前屏幕当前视口的行文本列表（每行字符串，空格对齐）；
   - 动态调整尺寸 `virtual-terminal-resize!`：支持动态修改宽高，保持已有内容并裁剪/填充行缓冲区，光标位置安全修正。

3. **`standard-terminal` 真实终端抽象（ANSI / stdio 输出）**：
   - 封装实际的输出端口（默认 `(current-output-port)`）；
   - 使用 ANSI 转义序列执行光标控制与清屏：
     - 光标定位：`ESC [ <y+1> ; <x+1> H`；
     - 清屏：`ESC [ 2 J ESC [ H`；
     - 清行：`ESC [ 2 K \r`；
     - 隐藏/显示光标：`ESC [ ? 25 l` / `ESC [ ? 25 h`；
   - 跟踪逻辑光标坐标；尺寸查询委托给动态尺寸探测过程（可注入或使用默认 `terminal-detect-size`）。

4. **尺寸查询与环境变量兜底 (`terminal-detect-size`)**：
   - 提供独立纯函数 `terminal-detect-size`；
   - 优先读取环境变量 `COLUMNS` 与 `LINES`（解析为合法正整数）；
   - 若环境变量缺失、为空或无法解析为数字，默认回退到 80 列 × 24 行；
   - 全程无异常崩溃，保证在 CI、无头服务器或任何环境均稳定可靠。

5. **单文件 300 行与拆分规范**：
   - 遵循 `bin/gf check` 的单文件 <= 300 行硬约束；
   - 模块清晰拆分为：
     - `(liii tui terminal protocol)`：协议定义与派发分发
     - `(liii tui terminal size)`：尺寸检测与环境变量解析
     - `(liii tui terminal virtual)`：内存虚拟终端实现
     - `(liii tui terminal standard)`：真实标准输出终端实现
     - `(liii tui terminal)`：统一门面导出

## 验收点

1. **终端尺寸探测 (`terminal-detect-size`)**：
   - 缺省无环境变量时，稳定返回默认尺寸 `'(80 24)`；
   - 当设置合法 `COLUMNS` 与 `LINES` 时，正确解析并返回对应数值；
   - 当环境变量为非数字、负数或零等非法内容时，安全回退默认 `'(80 24)`，不抛未捕获异常。
2. **`virtual-terminal` 基础创建与属性**：
   - 支持指定自定义宽度和高度构造（如 `(make-virtual-terminal :width 40 :height 10)`）；
   - 支持缺省参数构造，自动采用检测尺寸；
   - 初始光标位于 `'(0 0)`，初始屏幕行缓冲区为空格行。
3. **文本写入与行缓冲区维护 (`terminal-write`)**：
   - 写入单行普通文本，对应行内容正确更新，光标推进到对应列；
   - 写入含 `\n` 的多行文本，正确切行并更新光标位置；
   - 写入含 `\r` 的文本，光标正确定位回行首；
   - 超出屏幕高度时自动向上平滚；
   - `virtual-terminal-screen` 能提取当前屏幕视口的内容列表；
   - `virtual-terminal-raw` 能获取写入过程记录的原始文本。
4. **光标位置与显隐控制 (`terminal-set-cursor!` 等)**：
   - `terminal-set-cursor!` 能准确定位光标到目标 `(x, y)`；
   - 超出屏幕边界的坐标安全钳位（clamping）在 `[0, width-1]` 和 `[0, height-1]` 之内；
   - `terminal-hide-cursor!` 和 `terminal-show-cursor!` 正确更新光标可见性状态；
   - `terminal-clear` 清空所有屏幕行并重置光标至 `'(0 0)`；
   - `terminal-clear-line` 清空当前行。
5. **动态尺寸调整 (`virtual-terminal-resize!`)**：
   - 改变尺寸后，`terminal-size` 准确反映新宽高；
   - 现有缓冲区内容按新宽度进行裁剪或在新高度下扩展/保留；
   - 光标位置自动安全约束在新尺寸边界内。
6. **真实终端抽象 (`make-standard-terminal`)**：
   - 支持指定自定义输出端口（如 `open-output-string`）；
   - 光标移动输出标准 ANSI 转义码 `\x1b[<row>;<col>H`；
   - 清屏输出 `\x1b[2J\x1b[H`；
   - 显隐光标输出 `\x1b[?25l` / `\x1b[?25h`；
   - 写入文本直接流向目标端口并 flush。
7. **门禁与代码规范**：
   - 所有单元测试非交互运行，10 秒内快速完成；
   - 单文件 <= 300 行；
   - `bin/gf fmt` 与 `bin/gf check` 通过；
   - `bin/gf doc --build-json` 成功更新函数索引。

#### Why
终端 UI（组件布局、交互编辑器、贪吃蛇游戏、差分渲染刷新）需要解耦于物理终端设备的通用终端接口抽象。内存中的 `virtual-terminal` 提供 100% 确定性的脱机无头模拟环境，使得所有上层组件与渲染算法都能在无需真实 TTY 的环境下进行精准无误差的自动化断言与回归测试；同时 `standard-terminal` 则为真实终端交互提供了标准的 ANSI 控制通道。

#### How
1. 基于 `<terminal>` record 协议，将终端行为标准化为 10 个核心接口（`terminal-size`、`terminal-write`、`terminal-cursor`、`terminal-set-cursor!`、`terminal-clear`、`terminal-clear-line`、`terminal-cursor-visible?`、`terminal-hide-cursor!`、`terminal-show-cursor!`、`terminal-flush`）；
2. `terminal-detect-size` 纯函数解析 `COLUMNS`/`LINES` 环境变量，异常或缺失安全兜底 80x24；
3. `virtual-terminal` 在内存中维护二维字符网格向量与原始字符串流，支持 `\n` 自动向下推进并在超出高度时向上平滚，支持 `\r` 回车行首，支持光标绝对定位与边界钳位，支持随时提取整屏快照字符串列表；
4. `standard-terminal` 向指定 output-port 写出标准 ANSI CSI/SGR 控制序列并管理逻辑光标；
5. 遵守单文件 <= 300 行硬约束，拆分子库分工明确。
