### 架构约定与设计原则

1. **终端抽象规范（Terminal Protocol / API）**：
   - 终端接口提供一套统一操作方法，向上支撑差分渲染引擎（061）与上层交互组件，向下既支持脱机模拟的 `virtual-terminal`，也可扩展真实标准输出设备；
   - 核心接口规范包括：
     - `terminal-write`：向终端当前光标位置写入文本；
     - `terminal-size`：查询终端尺寸，返回 `(width . height)` 或 `(list width height)`；
     - `terminal-cursor`：查询当前光标坐标 `(list x y)`（0-indexed，x 为列，y 为行）；
     - `terminal-set-cursor!`：移动光标至指定位置 `(x, y)`，带边界安全约束；
     - `terminal-clear`：清屏并重置光标至 `(0, 0)`；
     - `terminal-clear-line`：清除当前行文本；
     - `terminal-hide-cursor!` / `terminal-show-cursor!`：控制光标显隐状态；
     - `terminal-flush`：刷新输出缓冲区。
2. **`virtual-terminal` 内存虚拟终端（脱机测试核心）**：
   - 完全在内存中维护字符二维网格/行缓冲区，具备 100% 确定性；
   - 支持多行文本写入、换行符（`\n`）与回车符（`\r`）语义：
     - `\n`：光标移动到下一行（超出底部时自动向下扩展行缓冲或滚动）；
     - `\r`：光标回到当前行首（x = 0）；
     - 普通字符写入：覆盖或追加在当前 `(x, y)` 位置，光标自动右移；
   - 维护原始调用日志 `virtual-terminal-raw`：完整记录写入的历史字符串流，便于底层转义序列断言；
   - 屏幕快照提取 `virtual-terminal-screen`：获取当前屏幕当前视口的行文本列表（每行字符串）；
   - 动态调整尺寸 `virtual-terminal-resize!`：支持动态修改宽高，保持已有内容并裁剪/填充行缓冲区，光标位置安全修正。
3. **尺寸查询与环境变量兜底**：
   - 提供独立纯函数 `terminal-detect-size`；
   - 优先读取环境变量 `COLUMNS` 与 `LINES`（解析为合法正整数）；
   - 若环境变量缺失、为空或无法解析为数字，默认回退到 80 列 × 24 行；
   - 全程无异常崩溃，保证在 CI、无头服务器或任何环境均稳定可靠。
4. **单文件 300 行与拆分规范**：
   - 遵循 `bin/gf check` 的单文件 <= 300 行硬约束；
   - 模块清晰拆分为尺寸检测、虚拟终端核心与统一门面；
   - 测试按 goldfish 规范单函数单测试，镜像源码库结构。

## 验收点

1. **终端尺寸探测 (`terminal-detect-size`)**：
   - 缺省无环境变量时，稳定返回默认尺寸 `'(80 24)`；
   - 当设置合法 `COLUMNS` 与 `LINES` 时，正确解析并返回对应数值；
   - 当环境变量为非数字、负数或零等非法内容时，安全回退默认 `'(80 24)`，不抛未捕获异常。
2. **`virtual-terminal` 基础创建与属性**：
   - 支持指定自定义宽度和高度构造（如 `(make-virtual-terminal :width 40 :height 10)`）；
   - 支持缺省参数构造，自动采用检测尺寸；
   - 初始光标位于 `'(0 0)`，初始屏幕行缓冲区为空或全空格行。
3. **文本写入与行缓冲区维护 (`terminal-write`)**：
   - 写入单行普通文本，对应行内容正确更新，光标推进到对应列；
   - 写入含 `\n` 的多行文本，正确切行并更新光标位置；
   - 写入含 `\r` 的文本，光标正确定位回行首；
   - 支持多次连续写入，字符正确在指定位置追加或覆盖；
   - `virtual-terminal-screen` 能提取当前屏幕视口的内容列表；
   - `virtual-terminal-raw` 能获取写入过程记录的原始文本。
4. **光标位置与显隐控制 (`terminal-set-cursor!` 等)**：
   - `terminal-set-cursor!` 能准确定位光标到目标 `(x, y)`；
   - 超出屏幕边界的坐标安全钳位（clamping）在 `[0, width-1]` 和 `[0, height-1]` 之内；
   - `terminal-hide-cursor!` 和 `terminal-show-cursor!` 正确更新光标可见性状态；
   - `terminal-clear` 清空所有屏幕行并重置光标至 `'(0 0)`。
5. **动态尺寸调整 (`virtual-terminal-resize!`)**：
   - 改变尺寸后，`terminal-size` 准确反映新宽高；
   - 现有缓冲区内容按新宽度进行裁剪或在新高度下扩展/保留；
   - 光标位置自动安全约束在新尺寸边界内。
6. **边界与单测覆盖**：
   - 单函数单测试，全量覆盖尺寸检测、虚拟终端写入、光标定位、清屏与 resize；
   - 全程不依赖真实 TTY 设备，在脱机无头环境中 100% 确定性运行。
7. **门禁与代码规范**：
   - `timeout 600 xmake b goldfish` 构建通过；
   - `timeout 120 bin/gf fmt` 格式化通过无 diff；
   - `git diff --exit-code` 保证工作区整洁；
   - `timeout 120 bin/gf check` 静态检查（单文件 <= 300 行）全绿；
   - `timeout 120 bin/gf doc --build-json` 成功更新函数索引。

## 日期 任务描述

### What

1. 建立 057 任务文档 `tools/pi/devel/057.md`，对齐 `tools/pi/Agents.md` §3 任务表验收点；
2. 设计 `(liii tui terminal)` 规范接口与 `virtual-terminal` 内存虚拟终端架构；
3. 规划单函数单测试、文件拆分与环境变量回退机制。

### Why

终端用户界面（TUI）渲染引擎与交互组件需要一个稳定的终端操作抽象层；为了实现脱机无头测试（避免依赖真实 TTY、支持在 CI/CD 中进行 100% 确定性自动化测试），必须首先实现内存模拟的 `virtual-terminal`，为后续 058 布局容器、060 输入编辑器以及 061 差分渲染提供坚实的基础设施。

### How

1. 抽象通用终端方法集（写入、清屏、光标定位、显隐、尺寸查询）；
2. 构造 `virtual-terminal`：内部使用字符网格/行向量或行列表记录屏幕像素行，光标坐标 `(x, y)` 0-indexed 定位，支持换行与回车控制符推进，支持屏幕快照读取与原始调用记录；
3. 尺寸探测纯函数解析 `COLUMNS`/`LINES` 环境变量并以 80x24 作为兜底；
4. 严格按照每个单函数拆分测试文件，遵守 300 行硬约束。
