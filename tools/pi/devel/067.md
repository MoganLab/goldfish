## 架构与自适应方案设计

### 1. 终端尺寸探测机制与平台限制分析

- **底层现状**：
  `(liii tui terminal standard)` 中的 `make-standard-terminal` 通过 `terminal-detect-size` 探测终端宽高，实现位于 `(liii tui terminal size)`；
  当前主要读取 `COLUMNS` 与 `LINES` 环境变量（默认回退为 80x24）；同时支持通过 `:detect-size-fn` 注入自定义查询函数。
- **平台限制与应对**：
  在 Windows 标准控制台且未注入 Win32 API 胶水时，直接修改窗口大小可能不会实时广播给已启动进程的环境变量。
  因此方案采取：
  1) `terminal-size` 抽象层完全解耦，`demo/tui/snake.scm` 每帧通过 `terminal-size` 探测；
  2) 提供可测试的注入支持与尺寸模拟，在 `virtual-terminal` 和自定义 `detect-size-fn` 下确保实时触发；
  3) 文档详述真实终端运行与验证指南。

### 2. 纯函数布局计算 (`snake-compute-layout`)

将终端尺寸到组件布局的映射设计为无副作用的纯函数，位于 `(demo tui snake view)`：
- **输入**：`term-width`, `term-height`；
- **参数规格**：
  - 棋盘最小尺寸：宽 10、高 5；最大尺寸：宽 60、高 30；
  - 侧栏宽度：STATS 约 16 列，HELP 约 24 列，组合 side-stack 约 26 列；
- **自适应分支**：
  - **宽终端模式（Side-by-side 水平布局）**：当 `term-width >= 50` 且 `term-height >= 12` 时：
    - 棋盘宽度 = `min(60, max(10, term-width - 26 - 3))`；
    - 棋盘高度 = `min(30, max(5, term-height - 4))`；
    - 布局模式 = `'horizontal`，右侧保留完整 STATS 与 HELP；
  - **中等终端模式（Compact 垂直或单侧栏布局）**：当 `35 <= term-width < 50` 时：
    - 折叠 HELP 侧栏，仅保留精简 STATS（宽度约 16 列）；
    - 棋盘宽度 = `max(10, term-width - 16 - 3)`；
  - **窄/小终端模式（Vertical 垂直上下布局）**：当 `term-width < 35` 或 `term-height < 12` 时：
    - 棋盘宽度 = `max(10, term-width - 2)`；
    - 棋盘高度 = `max(5, term-height - 7)`；
    - 侧栏移至棋盘下方或精简为单行状态，避免水平挤压超宽。

### 3. 逻辑层状态缩放算法 (`snake-resize`)

位于 `(demo tui snake logic)` 的核心纯函数：
- **签名**：`(snake-resize game new-width new-height)` -> `<snake-game>`
- **安全取模与裁剪规则**：
  1) 若新宽高与当前一致，原样返回 `game`；
  2) **蛇身处理**：
     - 对身体每节坐标 `(x, y)` 取模：`(modulo x new-width, modulo y new-height)`；
     - **去重防重叠**：棋盘缩小时取模可能使多节重合，从头到尾去重，保留不重复的有效身体；
     - **长度上限安全裁剪**：缩减后身体长度不超过新棋盘总面积的一半（`(* new-width new-height)` / 2），避免满屏无法移动；头部始终保留；
  3) **食物处理**：
     - 原始食物坐标同样安全取模；
     - 若食物落在新的蛇身中，调用 `snake-spawn-food` 寻找新棋盘上的安全空位；
  4) **属性继承**：
     - 分数 `snake-score`、最高分 `snake-high-score`、移动方向 `snake-dir`、状态 `snake-status`、计数器 `snake-tick-count` 完全保留。

### 4. 主循环与屏幕刷新集成

- 启动时根据初始 `terminal-size` 动态构建棋盘游戏；
- 每一帧主循环中调用 `(terminal-size term)` 检查尺寸；
- 一旦发生变化：
  1) 计算新尺寸与布局；
  2) 调用 `(snake-resize current-game new-w new-h)` 更新游戏逻辑对象；
  3) 调用 `(screen-resize! screen cur-cols cur-rows)` 清屏并重置主屏幕缓冲区；
  4) 以实际终端宽度调用 `(component-render view cur-cols)` 进行全量平滑重绘。
