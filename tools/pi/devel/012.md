## 验收点

- CLI 参数与配置解析：
  - CLI 支持 `--thinking-level <off|low|medium|high>`（区分 off / low / medium / high 四种级别）。
  - 未显式传入 `--thinking-level` 时，默认从 `settings.defaultThinkingLevel` 读取；未配置时默认为 `off`。
  - 传入非法级别时明确报错并退出。
- 请求构造（Gemini & Anthropic）：
  - Gemini provider：非 off 时在请求体注入 `generationConfig.thinkingConfig`（包含 `includeThoughts: #t`，并按 thinking-level 映射思考预算或参数）；off 时不注入或显式关闭。
  - Anthropic provider：非 off 时在请求体构造 `thinking` block（如 `type: "enabled", budget_tokens: ...`）；off 时不注入。
  - 其余 provider（如 kimi-coding）：不报错，优雅忽略或兼容处理。
- 响应解析与输出表现：
  - 响应解析：模型返回的 thinking / thought 内容正确解析并归入消息结构（区分 text 与 thinking）。
  - print 模式：默认只输出最终 text 块，不打印 thinking 过程。
  - JSON 模式：事件流中区分 thinking 增量块与 text 增量块（`assistantMessageEvent` type 区分 text/thinking）。
- 测试与门禁：
  - TDD 覆盖参数解析、配置读取、Gemini/Anthropic 请求体与响应流解析。
  - 真实冒烟命令可用：
    - `timeout 300 bin/gf pi -p --thinking-level low "分析这段递归的时间复杂度并优化"` 正常输出 text 结果。
    - `timeout 300 bin/gf pi --mode json --thinking-level low "证明：任意三角形内角和为180度"` 事件流中产生 thinking 增量。
  - 门禁全绿：
    - `timeout 600 xmake b goldfish`
    - `timeout 120 bin/gf fmt`
    - `git diff --exit-code`
    - `timeout 120 bin/gf check`
    - `bin/gf doc --build-json`
