## 验收点

（从 `PI_PLAN.md` §3 任务表复制展开，逐条可验证）

1. **Gemini 模型注入 web_search 工具声明 (functionDeclaration)**：
   - 当使用 Gemini provider / 模型时，若生效工具集包含 `web_search`（或通过 `--tools` / 配置开启），Gemini 请求体中正确注入 `web_search` 的 `functionDeclaration`（基于任务 040 的 Schema）；
   - 请求体同时能兼容 Google Search grounding 与标准 functionCallingConfig 设置（AUTO 模式）；
   - 不影响无 web_search 或其他 provider（如 DeepSeek/Kimi/Anthropic/MiniMax）的工具声明机制。
2. **Agent 事件循环调度执行器与回传 tool_result 闭环**：
   - 当大模型在推理过程中发起 `web_search` tool call 时，Agent 事件循环正确捕获该 tool call；
   - 自动分发至任务 042 实现的 `pi-execute-web-search` 网络执行器；
   - 执行器获取检索正文与 Grounding 数据，生成格式化结果（含正文与 Sources 引用），包装为标准的 `tool_result` 消息（role: "tool" / "user" 根据 provider 协议规范适配）；
   - 将 `tool_result` 追加至会话上下文并回传给模型发起下一轮 Agent turn，模型能够基于检索到的引用与事实生成最终回答。
3. **CLI 前端展示搜索 query 与引用来源**：
   - 在 print 模式与 JSON 事件流中，清晰展示 `web_search` 的执行状态；
   - 能够解析并展示用户检索 query（如 `tool_execution_start` / CLI 日志输出）；
   - 最终模型输出或工具执行反馈中保留来源引用（Sources / Citations）并在终端对用户友好展示；
   - 遵守日志安全规范：网络搜索请求不泄露 API key 等敏感信息。
4. **整体回归与读写编辑既有工具保障**：
   - web_search 闭环调用不干扰 `read`、`write`、`edit`、`bash`、`ls`、`find`、`grep` 等既有 7 个核心工具；
   - 在多轮交互中支持混合工具调用（如先 `web_search` 获取信息，再 `write` 写入本地文件）；
   - 既有单元测试全量通过，无功能回归。
5. **门禁与工程规范**：
   - 遵守单文件 300 行硬约束（必要时对超限模块进行合理拆分解耦）；
   - 所有外部命令与网络/子进程 IO 均带超时保护（强制 `:timeout`）；
   - TDD 驱动，单元测试镜像源码库结构，不引用三份计划文档；
   - 顺序通过 `timeout 600 xmake b goldfish`、`timeout 120 bin/gf fmt`、`git diff --exit-code`、`timeout 120 bin/gf check`、`timeout 120 bin/gf doc --build-json`。

## 2026-10-20 任务描述

### What

1. 建立任务 043 任务文档，明确阶段四（web_search Agent 工具调用闭环联调）的目标与验收点；
2. 梳理 Gemini 模型下注入 `web_search` 声明的触发条件与请求体构造；
3. 规范 Agent 循环中收到 `web_search` tool call 的执行分发、`tool_result` 组装与下一轮对话上下文回传；
4. 规划 CLI 前端在执行搜索时的 query 展示与最终 Sources 引用呈现；
5. 明确与既有 7 个工具的混合调用测试与全量回归要求。

### Why

在阶段一（040）完成了工具 Schema 与校验，阶段二（041）实现了请求体构造与 Grounding 解析，阶段三（042）完成了执行器网络调用与结果拼装。
本任务（043）是 web_search 扩展的收官阶段，将前三阶段成果整合进 Agent 事件循环，实现从「模型决定搜索 -> 执行器网络抓取 -> 结果反馈模型 -> 模型生成带引用的最终答案」的完整闭环，真正具备开箱即用的联网搜索能力。

### How

1. **工具声明注入**：在 `(liii pi gemini request)` 和 `(liii pi gemini stream)` 中，检查生效工具列表（`effective-tools`），确保包含 `web_search` 时能够将其作为 `functionDeclarations` 正常下发给 Gemini；
2. **Agent 工具执行与消息转换**：Agent 的 `pi-execute-tool-calls` 已经能够通过 `execute-tool-call` 调用 `pi-execute-web-search`，重点验证 `tool_result` 文本与元数据能否被 Gemini 协议转换层正确识别并塞入 contents 列表；
3. **前端展示与事件流**：在 print 模式与 JSON 事件流中确保 `tool_execution_start`（携带 query）与 `tool_execution_end` 正常派发，终端输出清晰显示搜索与引用信息；
4. **端到端集成测试**：在 stub server 中构造多轮 tool-call 场景（第一轮返回 web_search toolCall，第二轮接收 tool_result 返回最终答案），编写端到端单元测试；
5. **门禁检查与全量回归**：确保通过 check、fmt 与现有所有测试。
