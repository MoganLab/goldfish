### 实测基线（2026-10-19，本机 `~/.pi/agent/`）

| 命令 | 结果 |
|---|---|
| `pi --list-models` | 8 provider / **70** 模型（anthropic 14、deepseek 6、glm 6、google 23、kimi-coding 4、minimax 4、minimax-cn 3、zai-coding-cn 10） |
| `bin/gf pi --list-models` | 1 provider（`settings.json` 的 `defaultProvider` = google）/ **23** 模型 |
| `bin/gf pi --provider zai-coding-cn --list-models` | 可用（bin/gf 独有的按 provider 过滤能力，pi 无此参数） |
| `pi --list-models flash` | 跨 provider 命中（deepseek/glm 也在内）；`pi --list-models g25f` 命中 `gemini-2.5-flash`（子序列匹配） |
| `bin/gf pi --list-models flash` | 只在默认 provider 内做子串匹配 |

本地目录实况：`models-store.json` 6 个 provider（google 23 / kimi-coding 4 / zai-coding-cn 4 / minimax-cn 3 / minimax 3 / deepseek 2）；
`models.json` 3 个 provider（glm 6 / deepseek 3 / minimax 4）；pi 内置目录 7 个 provider 共 60 个模型
（anthropic 14 / deepseek 3 / google 23 / kimi-coding 4 / minimax 3 / minimax-cn 3 / zai-coding-cn 10）。

**合并后（`models.json` > `models-store.json` > 内置目录）恰好得到 8 provider / 70 模型，与 pi 的模型集合逐条一致**；
逐行比对后仅 `kimi-coding` 4 行的 `max-out`/`images` 两列与 pi 不同——因为 pi 联网刷新了远程目录
（pi：max-out 16.4K、images no；本地 `models-store.json` 缓存：131.1K / 32.8K、images yes）。

### 内置目录数据来源（开发阶段一次性提取，数据入库后不再依赖 pi）

pi 的内置目录在源码仓 `~/git/pi` 中由脚本生成（`packages/ai/src/providers/data/*.json` 未入库），
**已安装的 pi 包里有打包后的目录数据**，开发阶段从那里提取精确值（不能从 `pi --list-models`
的表格反推，表格值是四舍五入后的显示值）：

- 目录：`~/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/bundle/chunks/*.js`
- 定位：目录数据在形如 `var anthropic_default={...}` 的对象字面量里，
  provider 变量名为 `<provider>_default`（`kimi_coding_default`/`minimax_cn_default`/`zai_coding_cn_default` 等），
  可用 `grep -l 'claude-fable-5' dist/bundle/chunks/*.js` 定位所在 chunk。
- 提取：把对象字面量用 node 求值后转 JSON，取 `id`/`name`/`contextWindow`/`maxTokens`/`reasoning`/`input`/`baseUrl` 字段，
  生成 `models/builtin/<provider>.scm` 里的 Scheme 数据（每 provider 一个模块，避免单文件超 300 行）。
- 入库后 `bin/gf pi` **不依赖** pi 安装包（运行时只读 `~/.pi/agent/` 与内置目录快照）。

### 裁定（文档阶段，本任务按此实现）

1. **无 `--provider` 时全局列出**（对齐 pi）：遍历合并目录的全部 provider，输出所有模型；
   `--provider X` 保留 bin/gf 既有的按 provider 过滤能力（pi 无此参数，属有意超集）。
2. **合并目录**＝内置目录 ＋ `~/.pi/agent/models.json`（用户自定义）＋ `~/.pi/agent/models-store.json`（远程目录缓存），
   优先级 `models.json` > `models-store.json` > 内置目录（与 pi「远程目录 > 自定义 > 内置」一致，
   离线场景下远程目录退化为其本地缓存）。
3. **内置目录数据对齐 pi**：内置目录替换为 pi 内置目录快照（7 provider / 60 模型），按 provider 拆成
   `models/builtin/<provider>.scm`（对齐 pi 的 `providers/<provider>.models.ts` 拆分），聚合入口仍是
   `PI_PROVIDER_BUILTIN_MODELS`；`PI_SUPPORTED_PROVIDERS` 补入 `zai-coding-cn`。
4. **格式对齐**：`pi-format-token-count` 与 pi `formatTokenCount()` 逐条等价
   （阈值 1e6 / 1e3，整除取整否则保留 1 位小数，四舍五入语义取「四舍五入远离零」，
   对齐 JS `toFixed(1)`；例如 1000000 → `1M`、1048576 → `1.0M`、1250000 → `1.3M`、131072 → `131.1K`）。
   表头、列宽、两空格分隔、按 provider → model id 排序与 pi 一致（现状已一致，需回归锁定）。
5. **搜索语义对齐**：改用 pi `fuzzyFilter()` 的子序列匹配（token 以空白或 `/` 切分，全部 token 命中才算匹配），
   匹配对象为 `"<provider> <model>"`；命中集仍按 provider → model id 排序（pi 亦如此）；
   无命中时输出 `No models matching "<pattern>"`（与 pi 文案一致）。
6. **默认模型随目录修正**：`pi-provider-default-model` 的返回值必须仍在目录内——
   anthropic `claude-3-7-sonnet-20250219` → `claude-opus-4-8`（pi `defaultModelPerProvider`），
   deepseek `deepseek-chat` → `deepseek-v4-pro`（pi 默认，目录内亦有），
   glm `glm-4-plus` → `glm-5.3`（pi 无内置 glm，glm 走 `models.json`），
   zai-coding-cn 新增 → `glm-5.3`（pi 默认）；google / kimi-coding / minimax / minimax-cn 维持现值。
   并按 pi `buildFallbackModel()` 补一条兜底：**默认模型不在目录内时回退到该 provider 目录中的第一个模型**，
   仍无则维持既有 `pi-config-error` 报错文案。
7. **有意偏差（不做）**：pi 联网刷新远程目录（`pi.dev`）并写回 `models-store.json`；
   `bin/gf pi` 只读 `~/.pi/agent/`（settings/auth/models-store/models.json 全部只读），
   故个别模型的 `max-out`/`images` 可能与 pi 当次输出不同（当前实测仅 `kimi-coding` 4 行）。
   该偏差记入 `PI_PLAN.md` §7 偏差清单。
8. **有意偏差（不做）**：pi 只列**已认证** provider（`auth.json` ＋ 环境变量凭据）；`bin/gf pi` 列合并目录全量
   （离线也能看到可用模型目录）。本机两者集合恰好一致（8 provider）。

### Why

- `--list-models` 是用户挑选模型的主入口；bin/gf pi 只列默认 provider，导致 anthropic / glm / deepseek /
  minimax / zai-coding-cn 等 provider 的模型「看不见」，与 pi 本尊行为严重不一致。
- 目录数据与格式不对齐（pi `1M` vs bin/gf `1.0M` 的观感差异）会让用户误判模型能力与上下文窗口。

### How

- 分层：内置目录数据（`models/builtin/<provider>.scm`）→ 合并目录（`models/catalog.scm`）→
  列表与格式化（`models/list.scm`）→ CLI 装配（`cli.scm`）；路由默认值单独在 `models/route.scm` 修正。
- 内置目录按 provider 拆模块以满足单文件 300 行约束，并保持 `PI_PROVIDER_BUILTIN_MODELS` 聚合入口不变，
  既有调用点与测试不回归。
- 合并目录用「按模型 id 覆盖」的逐 provider 合并实现，优先级 `models.json` > `models-store.json` > 内置目录；
  运行期（`config.scm`）与列表共用同一目录构造器，避免两处口径不一致。
