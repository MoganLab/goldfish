## 验收点

从 `tools/pi/Agents.md` §3 任务表 070 提取并细化：

1. **核心 Record 类型定义**：
   - `ExtensionAPI` / `ExtensionContext` 记录类型，具备规范的构造器、谓词与字段访问器；
   - 支持扩展工具定义（`name`, `description`, `parameters`, `execute` 等）；
   - 支持扩展 flag 定义（`flag`, `description`, `handler`/`action`, `type` 等）；
   - 支持扩展 command 定义（`name`, `description`, `handler` 等）。
2. **注册 API 契约与功能**：
   - `(extension-register-tool! api tool-def)`：能够将工具注册入扩展注册表，校验必填字段并支持查询；
   - `(extension-register-flag! api flag-def)`：能够注册自定义 CLI 标志与解析选项；
   - `(extension-register-command! api command-def)`：能够注册斜杠命令或子命令；
3. **事件生命周期监听与派发（对齐原生 pi）**：
   - 提供 `(pi-on! api event-type handler)` 与 `(pi-emit! ctx event-type payload)`；
   - 事件生命周期完整对齐原生 pi：
     - `session_start`：会话初始化；
     - `agent_start`：轮次/Agent 开始；
     - `tool_call`：工具调用前触发，支持拦截、拒绝（block）或改写输入参数；
     - `tool_result`：工具执行完成后触发，传递执行结果；
     - `agent_end`：轮次/Agent 结束；
   - 监听器执行异常隔离，单监听器报错不中断事件链其余监听器（错误记录至 stderr 或返回值）。
4. **测试与质量门禁**：
   - 单元测试 TDD 覆盖全部记录类型与核心函数（`tests/liii/pi/extension/*-test.scm`）；
   - 通过 `timeout 600 xmake b goldfish`、`bin/gf fmt`、`git diff --exit-code`、`bin/gf check`；
   - 提供 `tools/pi/devel/070.scm` 验收脚本，全部断言通过。

## 2026-10-20 任务描述

### What

1. 依据 `Agents.md` 大任务规格，建立任务 070 的 PLAN 任务文档 `tools/pi/devel/070.md`；
2. 明确 Extension 机制核心数据结构与契约：`ExtensionAPI`, `ExtensionContext`, `register-tool`, `register-flag`, `register-command`, `pi-on!`, `pi-emit!`；
3. 规划后续 TDD 单元测试目录与验收点，为开发阶段打好基础。

### Why

原生 pi 的扩展机制核心理念是事件驱动与可插拔扩展。为了在 Goldfish Scheme 中实现同等强大且自包含的 Extension 机制，必须先建立稳固的核心概念模型抽象（`ExtensionAPI` 与生命周期派发），使随后的工具层解耦（072）、CLI 路由解耦（073）、提示词与工具拦截（074）以及内置插件迁移（075）能够统一基于此标准契约运作。

### How

1. 设计纯 Scheme 的轻量注册表和上下文对象：
   - 使用 `define-record-type` 定义清晰的 record 结构；
   - 状态隔离：注册表可以实例化与独立管理，避免全局变量污染，方便测试隔离；
2. 事件拦截设计：
   - 对 `tool_call` 等可拦截事件，设计标准返回值协议（例如允许 handler 返回 `(:block reason)` 或 `(:override new-input)` 或普通继续），对齐原生 pi 拦截能力；
3. 严格遵循 Goldfish 规范：单文件 < 300 行、函数与测试文件 1:1 镜像、全量 fmt / check。
