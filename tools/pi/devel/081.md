## 验收点

1.0 **CLI 参数解析与启动路由支持 TUI 缺省模式**：
- `parse-pi-args` / `resolve-app-mode`：当未显式指定 `--print`、`--mode json` 且命令行无 prompt、标准输入与输出均为 TTY 时，模式正确解析为 `'tui`；
- `cli.scm` 调整缺省无参逻辑：用户直接运行 `bin/gf pi`（无任何参数且输入为 TTY）时，不再直接输出帮助信息退出，而是平滑拉起 TUI 交互界面。

2.0 **终端全屏初始化（StandardTerminal）与模式切换**：
- 在 `modes/tui.scm` 中，通过 `(make-standard-terminal)`（或传入自定义/虚拟终端）初始化终端环境；
- 启动进入 Alternate 屏幕缓冲区（`\x1b[?1049h`）、隐藏光标（`terminal-hide-cursor!`）、开启 raw 模式（`console-raw-mode! #t`）并清屏。

3.0 **`dynamic-wind` 安全还原兜底（100% 健壮防卡死）**：
- 使用 `dynamic-wind` 严格包裹 TUI 执行体；
- 无论正常退出、按键退出、未捕获 Scheme 异常还是外部中断，out-guard 100% 触发清理逻辑：恢复光标可见（`terminal-show-cursor!`）、退出 Alternate 屏（`\x1b[?1049l`）、恢复终端 cooked 模式（`console-raw-mode! #f`）并 `terminal-flush`；
- 确保终端绝不残留卡在 raw 模式或隐藏光标状态，保障用户开发环境安全。

4.0 **最小事件响应骨架与优雅退出**：
- 循环使用 `terminal-poll-key` 监听输入事件；
- 当捕获到按键 `'escape` 或字符 `"q"` 时，能够优雅结束循环并返回退出码 0。

5.0 **虚拟终端确定性测试覆盖（TDD & CI）**：
- 编写 `tui-test.scm`，通过 `make-virtual-terminal` 注入按键流（如 `'escape`、`"q"` 或常规按键）；
- 验证进入/退出生命周期、屏幕缓冲区切换序列以及异常发生时的还原保证；
- 门禁四连：`xmake b goldfish`、`bin/gf fmt`、`git diff --exit-code`、`bin/gf check` 与相关测试全部 100% 通过。

## 2026-10-21 任务描述

### What

建立 `bin/gf pi` 的交互式 TUI 架构骨架与启动路由：
1. CLI 参数与路由支持缺省无参时进入 `mode = 'tui`；
2. 新建 `modes/tui.scm`，实现终端环境初始化（StandardTerminal / raw 模式 / Alternate 屏幕 / 隐藏光标）；
3. 借助 `dynamic-wind` 实现 100% 安全终端还原（退出 Alternate 屏、还原 cooked 模式、显示光标）；
4. 提供最小事件响应循环，响应 q/Esc 优雅退出；
5. 基于 `virtual-terminal` 实现无 TTY 环境下确定性单测覆盖。

### Why

`bin/gf pi` 至今已完成全部非交互式能力（print 模式、JSON 模式、扩展插件机制、预算感知等）。
随着通用终端 UI 库 `(liii tui)` 正式合入主干（PR #1159），进入第二阶段核心目标：实现纯 Scheme 原生沉浸式 TUI 交互界面。
本任务 081 为该阶段奠基，打通 CLI 启动门面与终端安全屏障。

### How

- 利用 `(liii tui terminal)` 的协议和 `make-standard-terminal` / `make-virtual-terminal`；
- 封装 `with-pi-tui-terminal` 高阶函数，以 `dynamic-wind` 保证无论何种控制流离开均安全恢复终端形态；
- 使用虚拟终端注入按键进行全自动化无头单测，摆脱物理终端依赖。
