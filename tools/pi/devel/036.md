## 形态对齐（pi 源码 → `bin/gf pi` 脚本模式）

对齐依据：`~/git/pi/packages/coding-agent/src/core/compaction/`
（`compaction.ts` / `branch-summarization.ts` / `utils.ts`）、

`packages/coding-agent/src/modes/interactive/interactive-mode.ts`（`/compact`）、
`packages/coding-agent/src/modes/rpc/rpc-mode.ts`（`compact` 命令）。

pi 侧的压缩入口共三个：

| pi 入口 | 语义 | 脚本模式可用性 |
|---|---|---|
| TUI `/compact` | 手动压缩当前分支，压缩后继续对话 | 交互式 TUI 属 Non-goal |
| 阈值自动压缩 | `shouldCompact(tokens, contextWindow, settings)`：上下文 token 超 `contextWindow - reserveTokens` 时压缩 | 可用（脚本模式同样有超窗风险） |
| RPC `compact` 命令 | 手动压缩（RPC 模式） | RPC 模式属 Non-goal |
| print / 脚本模式 | **pi 本尊无任何压缩入口** | — |

结论（文档阶段裁定，本任务按此实现）：

1. **`--compact` 手动压缩**（对应 pi 的 `/compact`）：压缩「最近会话」——
   会话目录取当前 cwd 对应目录（`~/.pi/agent/sessions/--<cwd>--/`，与 pi 本尊同目录），
   目标文件为该目录下最新的 `*.jsonl`；`--continue` 时即其续接会话。
   - 带 prompt（位置参数 / `@文件` / stdin）时：**先压缩，再执行本次 prompt**（上下文 = 压缩后上下文 + 本次 prompt）；
   - 不带 prompt 时：**只压缩并退出**（stdout 打印一行压缩摘要）。
   - 无会话可压缩时 stderr 报人可读原因，退出码 1。
2. **阈值自动压缩**（对应 pi 的自动压缩）：每轮 provider 请求前估算上下文 token，
   超过 `contextWindow - reserveTokens` 时自动压缩一次再继续本轮；
   `compaction.enabled=false`（settings.json）或 `--no-auto-compact` 时不触发。
3. **不做**（与 pi 的有意偏差，文档化即可）：分支摘要（`branch-summarization.ts`）、
   切分回合的 turn-prefix 摘要（split turn）、模型级 `compaction.modelOverrides`、
   扩展钩子（`session_before_compact`）、压缩成本统计展示（TUI 专用）。
4. **会话文件格式与 pi 兼容**：`bin/gf pi` 与 pi 本尊共享 `~/.pi/agent/sessions/`，
   压缩条目按 pi 的 `CompactionEntry` 形状写入
   （`type`/`id`/`parentId`/`timestamp`/`summary`/`firstKeptEntryId`/`tokensBefore`/`details`），
   pi 本尊可读我们的压缩结果，反之亦然；`details` 放 pi 约定的扩展数据
   （`reason`/`readFiles`/`modifiedFiles`），避免污染 pi 已知字段。
5. **压缩后上下文投影**对齐 pi 的 `buildSessionProjection`：
   最新 compaction 条目的 summary 以 `COMPACTION_SUMMARY_PREFIX + summary +
   COMPACTION_SUMMARY_SUFFIX` 作为一条 user 消息置首，其后接 `firstKeptEntryId`
   之后的原始消息；被摘要掉的原始条目**仍留在会话文件里**（原文可追溯）。

## 验收点

（来自 `PI_PLAN.md` §3 任务 036，逐条可验证）

1. **形态对齐结论落地**（见上文「形态对齐」节）：`--compact` 手动压缩 +
   阈值自动压缩两条路径都实现；pi 的分支摘要 / split turn / 扩展钩子明确不做并文档化。
2. **压缩消息构造**（TDD）：压缩后的上下文首条消息为
   `COMPACTION_SUMMARY_PREFIX + summary + COMPACTION_SUMMARY_SUFFIX` 的 user 消息，
   前后缀逐字对齐 pi `messages.ts`。
3. **截断策略**（TDD）：切点只落在 user / assistant 消息上（toolResult 不可切）；
   自最新向前累加估算 token 达 `keepRecentTokens` 后取最近合法切点；
   `keepRecentTokens` 缺省 20000、`reserveTokens` 缺省 16384、`enabled` 缺省 #t
   （与 pi `SETTINGS_DEFAULTS.compaction` 一致）。
4. **会话文件含 summary 消息、原文保留可追溯**：压缩后会话 JSONL 追加一条
   `type:"compaction"` 条目（`id`/`parentId`/`timestamp`/`summary`/`firstKeptEntryId`/
   `tokensBefore`/`details`），**原有 message 条目一条不少**（`firstKeptEntryId` 指向保留段首条）。
5. **压缩后继续会话可用**：压缩完成后 `bin/gf pi -c -p "…"` 能基于
   「summary + 保留的最近消息」继续，退出码 0；`bin/gf pi --compact "…"`
   压缩后直接执行本次 prompt，print 模式输出最终 assistant 文本，退出码 0。
6. **自动压缩**：上下文估算超 `contextWindow - reserveTokens` 时自动压缩一次并继续本轮；
   `compaction.enabled=false`（settings.json）或 `--no-auto-compact` 时不触发。
7. **错误路径**：无会话可压缩 / 摘要调用失败（provider error 或 length 截断）时，
   stderr 输出人可读原因（含原因摘要），退出码 1，**不写入半截 compaction 条目**。
8. **超时规范**：摘要调用沿用本次运行的 HTTP 超时（`--timeout`，缺省 120s），
   不允许静默挂起；`bin/gf pi --compact` 整体受 `--session-timeout` 约束。
9. **日志安全**：摘要请求/响应不落盘日志，stderr 只输出压缩摘要（条数 / token 估算），
   不打印 key、代理地址与请求体。
10. **门禁**：`timeout 600 xmake b goldfish`、`timeout 120 bin/gf fmt`、
    `git diff --exit-code`、`timeout 120 bin/gf check`、相关测试全部通过；
    无超 300 行文件；`bin/gf doc --build-json` 后函数索引包含压缩相关新函数。
11. **既有行为零回归**：`bin/gf pi` 既有 print / json 模式、工具集、会话持久化、
    `--continue` 等行为不变（既有测试全绿）；JSON 模式事件序列不变
    （不新增事件类型，压缩信息走 stderr 摘要）。

   **print / 脚本模式没有压缩入口**——因此 `bin/gf pi` 需自行定义脚本模式的对应形态。
4. 裁定并写入本文件「形态对齐」节：`--compact` 手动压缩（带 prompt 则压缩后继续、
   不带则只压缩退出）+ 阈值自动压缩；会话文件按 pi `CompactionEntry` 形状写入以保证
   与 pi 本尊同目录互读；分支摘要 / split turn / 扩展钩子明确不做。
5. 从 `tools/pi/devel/ddd.md` 模板复制建立 `tools/pi/devel/036.md`，填写状态、
   代码文件、验收点、测试方法与提交清单。

#### Why

- 长会话在脚本模式下会撞上模型上下文窗口；pi 靠 TUI `/compact` 与阈值自动压缩兜底，
  `bin/gf pi` 缺这两条路径，自举执行大体量任务时会在超窗处失败。
- `bin/gf pi` 与 pi 本尊共享 `~/.pi/agent/sessions/`，压缩条目格式必须对齐 pi，
  否则两边互相读取会话会得到不一致的上下文投影。

#### How

- 纯函数分层：token 估算（`compact/tokens.scm`）→ 截断点（`compact/cut.scm`）→
  序列化与文件操作（`compact/serialize.scm`、`compact/fileops.scm`）→
  提示词与摘要消息（`compact/prompt.scm`）→ 摘要生成（`compact/summary.scm`）→
  会话集成（`compact/session.scm`）→ 门面（`compact.scm`）；每层单文件 < 300 行。
- 摘要调用复用既有 provider 分发（`pi-request-provider-stream`），不带工具、
  单条 user 消息 + 摘要系统提示词，与 pi `completeSummarization` 语义一致。
- 自动压缩通过给 `run-agent-loop` 注入可选 `compactor` 过程实现，
  agent 层不反向依赖 compact 层（避免循环 import）。

  无会话时退出码 1 且 stderr 含原因摘要。
