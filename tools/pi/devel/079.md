# [079] 工具调用 timeout 语义重定：对齐原生 pi + 默认 600s

> 本文件是任务 079 的任务文档，从 `tools/pi/devel/ddd.md` 模板建立。
> 编号与 `tools/pi/Agents.md` §3 任务表 079 一一对应。
> 本任务负责重定工具调用 timeout 语义并对齐原生 pi：
> 1) 默认 timeout 从 120s 提升为 600s（对齐 session-timeout 默认 600s）；
> 2) 工具 timeout 只由模型决定，模型显式值即生效值，不再被默认 clamp 压回；
> 3) 非法值（≤0 / 非有限 / 超 sanity cap）显式抛错，而非静默忽略；
> 4) schema 描述动态如实，让模型知晓真实默认值；
> 5) `--timeout` 语义从天花板改为默认超时，消除 `--timeout 0` 语义冲突；
> 6) 既有用例按新语义改写并补齐 TDD 测试。

## 验收点

1.0 **默认值提升至 600s 且仅作为缺省值**：
- bash 工具及 CLI/agent 循环的默认超时从 120s 提升为 600s（与 `--session-timeout` 默认 600s 对齐）；
- 默认 timeout 仅在模型未指定 `timeout` 参数时生效，不再作为不可突破的"天花板"。

2.0 **模型显式值即生效值（解除 min clamp，对齐原生 pi）**：
- 模型在工具调用中传入显式 `timeout` 时，直接采用模型值，不再与默认超时做 `(min valid-arg valid-def)` 截断；
- 即使默认超时或 CLI 指定了较小值（如 1s），若模型明确请求更大超时（如 1000s），生效值应为 1000s，最终兜底为会话死线。

3.0 **非法 timeout 显式报错与 Sanity Cap 保护**：
- 对齐原生 pi（`packages/coding-agent/src/core/tools/bash.ts`）：模型传入非法 timeout（如 ≤ 0、负数、非数值等）时，显式抛错（返回错误结果或抛出异常），不得静默忽略或静默压回；
- 引入合理性上界 `MAX_TIMEOUT_SECONDS = 2147483.647`（约 24.85 天）作 sanity cap，超出该上界时同样显式报错。

4.0 **动态如实的 Schema 描述**：
- `pi-bash-schema` 描述动态反映真实默认超时（如 `"Timeout in seconds (optional, defaults to 600s)"`），明确指出默认值非上限，让模型在决策前知晓准确语义。

5.0 **CLI 参数语义与 `--timeout 0` 冲突消除**：
- `args.scm` 中 `--timeout` 缺省值改为 `#f`，以区分用户显式指定与未指定；
- `flow.scm` 及相关模块明确将 `--timeout` 定位为"默认超时"；消除 `--timeout 0` 的语义矛盾。

6.0 **既有用例与回归测试更新**：
- 改写 `tools/pi/tests/liii/pi/pi-execute-bash-test.scm`：废除旧有的"模型超大 timeout 不能突破顶层用户限制"用例，改写为断言"模型显式 timeout 能够超越默认值生效"；
- 补齐非法值（负数、0、超 sanity cap）显式报错的测试用例；
- 全量单测与门禁检查无回归。

7.0 **统一其余内置工具超时语义与可见性**：
- 统一 read/edit/write/grep/find/ls 等工具的超时行为与可见性规则。

## 2026-10-21 任务描述

### What

1.0 重定 `tools/pi/liii/pi/bash.scm` 超时语义：默认 600s，解除 `min` 截断，对齐原生 pi；
2.0 增加对非法 timeout（≤0、非数值）及超过 sanity cap（2147483.647s）的显式报错；
3.0 将 `pi-bash-schema` 改造为支持动态默认超时描述；
4.0 修改 `args.scm` 使 `--timeout` 缺省为 `#f`，并在流程控制中处理缺省 600s 语义；
5.0 改写 `pi-execute-bash-test.scm` 既有回归测试，增加对新语义的全面单测断言；
6.0 编写 `tools/pi/devel/079.scm` 验收脚本，验证门禁与超时新语义。

### Why

- 原生 pi 中工具超时完全由模型决定，不存在 CLI 级天花板，且非法超时会显式抛出错误；
- 当前 goldfish 存在四处不合：`(min valid-arg valid-def)` 将默认值作为上限强制压回；非法值被静默忽略；schema 描述硬编码 120s；`--timeout` 缺省写死 120 导致无法区分显式传参；
- 解决模型需要执行耗时任务时无法自主申请更长超时的限制，确保工具调用的灵活性与健壮性。

### How

- 在 `bash.scm` 中移除 `min` 逻辑，优先采用模型的 `timeout` 参数；
- 校验模型传入的 `timeout`，若为非有限数、≤0 或 > 2147483.647，抛出显式错误或返回错误元组；
- 在 `args.scm` 中缺省设为 `#f`，在 `modes/flow.scm` 和 `agent.scm` 中统一定义缺省值为 600s。
