### 架构约定与设计原则

1. **核心模型与状态管理（Editor Model & Buffer）**：
   - 文本行缓冲区：以行列表 `(list of string)` 组织文本内容，支持单行模式（`:multiline #f`）与多行模式（`:multiline #t`）；
   - 光标位置：以 `(row, col)` 零基坐标（0-based）精确定位光标行号与字符列索引；
   - 字符与显示对齐：列移动与定位遵循字符索引，视图渲染时结合 `(liii tui text-width)` 的 `display-width` 准确显示光标高亮或插入符号；
   - 占位提示：支持 `:placeholder` 文本，在内容为空时呈现提示信息。

2. **核心编辑操作与光标移动**：
   - **字符插入**：在当前光标位置插入字符或多字符字符串（包含普通 ASCII 及 CJK 等宽字符），光标跟随右移；
   - **退格删除（`'backspace`）**：删除光标左侧字符，光标左移；在多行模式下处于行首时，将当前行拼接到上一行末尾，光标移至上一行末尾；
   - **向后删除（`'delete`）**：删除光标右侧字符，光标位置不变；在多行模式下处于行尾时，将下一行拼接到当前行尾；
   - **左右移动（`'left` / `'right`）**：光标左右微调，遇到行首/行尾提供边界保护（单行时停在边界，多行时可环绕到上一行末或下一行首）；
   - **行首/行尾（`'home` / `'end`）**：光标快速跳至当前行首（列 0）或当前行尾；
   - **多行上下移动（`'up` / `'down`）**：多行模式下跨行移动光标，列位置尽量对齐或贴近目标行长度（吸附行尾）；
   - **回车换行（`'enter`）**：
     - 单行模式下：触发提交动作（`:on-submit` 回调），并将当前输入提交入历史记录；
     - 多行模式下：将当前行从光标处分裂为两行，新起一行，光标移至新行行首。

3. **输入历史记录机制（History）**：
   - 独立的历史记录管理器 `editor-history`，支持保存已提交历史记录项；
   - 历史浏览与草稿保护：
     - 在单行模式下按 `'up` 向上回溯历史记录，按 `'down` 向下前进历史记录；
     - 当从当前正在编辑的行向上浏览历史时，自动暂存当前输入作为草稿（draft）；
     - 当向下回到底部时，自动恢复用户暂存的草稿；
   - 支持历史最大容量上限保护与去重/跳过空白。

4. **`<component>` 协议实现与无头非交互测试**：
   - 实现 `component-render`：接收当前总渲染宽度 `width`，根据内容、光标位置、`:focused` 聚焦状态以及 `:placeholder` 渲染文本行列表（支持 ANSI 反显光标或字符光标指示）；
   - 实现 `component-handle-input`：接收来自 `(liii tui keys)` 解析出的按键符号（`'up`、`'down`、`'left`、`'right`、`'home`、`'end`、`'backspace`、`'delete`、`'enter`、`'tab`、`'ctrl-c`、`'ctrl-d` 或单字符文本输入），消费并更新内部状态，返回 `#t`（已处理）或 `#f`；
   - 纯函数/无头环境验证：支持脚本化按键事件流与原始 ANSI 转义序列解析后连续驱动，断言编辑器状态、文本内容与光标位置，完全不依赖真实 TTY。

5. **单文件 300 行与模块拆分规范**：
   - 严格遵循 `bin/gf check` 的单文件 <= 300 行硬约束；
   - 模块划分为：
     - `goldfish/liii/tui/editor/history.scm`（输入历史记录管理）
     - `goldfish/liii/tui/editor/buffer.scm`（文本行缓冲区操作纯函数与光标移动算法）
     - `goldfish/liii/tui/editor/view.scm`（编辑器视图行渲染与光标位置高亮指示）
     - `goldfish/liii/tui/editor/component.scm`（`<component>` 协议实现、`make-editor` / `make-text-input` / `make-text-area` 构造器与事件派发）
     - `goldfish/liii/tui/editor.scm`（`(liii tui editor)` 门面导出）
     - `goldfish/liii/tui.scm`（`(liii tui)` 顶级门面再导出）
   - 单函数单测试，镜像源码库结构，测试无协议头，实现文件使用 MIT 许可协议头。

## 日期 任务描述

### 2026-10-21 [061] PLAN 建档

#### What

1. 规划 061 `(liii tui editor)` 单行与多行交互编辑器组件架构方案与接口规范；
2. 明确文本缓冲区、光标导航、删除退格、多行换行与历史记录状态机设计；
3. 规划子库拆分路径（`history.scm`、`buffer.scm`、`view.scm`、`component.scm` 等），确保每文件严格 <= 300 行；
4. 明确单元测试与端到端非交互按键回放验收脚本覆盖范围。

#### Why

交互式 TUI 应用（如 REPL、表单、提示框、控制台以及随后的贪吃蛇菜单等）需要通用的键盘交互文本输入组件。通过在 `(liii tui editor)` 中实现可测试、非阻塞的单行/多行输入组件，为完整的终端交互应用提供基础。

#### How

- 将编辑器数据结构抽象为行列表与行列坐标；
- 光标移动与编辑操作作为纯函数或受控状态机实现，完全解耦于真实 TTY；
- 与 056 `(liii tui keys)` 对齐，将按键事件（如 `'up`、`'backspace`、`"a"` 等）输入到 `component-handle-input`；
- 在渲染层结合 055 `(liii tui text-width)` 计算真实列宽，并通过 ANSI 反白或标记渲染当前光标；
- 单行模式下利用 Up/Down 实现输入历史翻阅与草稿保存；多行模式下实现行列上下跳转。
