## 日期 任务描述

### 2026-10-19 任务建档

#### What

1. 查阅 `PI_PLAN.md` §3 任务 020 验收点，调研 DeepSeek 的凭据来源与端点协议：
   - 调研 `~/git/pi` 源码（`packages/ai/src/providers/deepseek.ts`）：官方 `baseUrl` 为 `https://api.deepseek.com`，消费 `DEEPSEEK_API_KEY`。
   - 调研 `~/.claude` 生态：在 `~/.claude/settings.json.deepseek` 中配置了 `ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic`，DeepSeek 提供了完全兼容 Anthropic Messages 协议的网关，以及在 `~/.deepseek.json` 中配置了 `api_key`。
2. 建立 `tools/pi/devel/020.md` 任务文档，详细记录状态、涉及文件、验收点与测试方法。
3. 规划实现方案：在凭据发现中支持 `auth.json`、`DEEPSEEK_API_KEY`、`ANTHROPIC_AUTH_TOKEN` 及本地 Claude 生态配置文件；端点与流式链路优先复用兼容路径，保证健壮性与最小改动。

#### Why

根据用户裁定，DeepSeek provider 单独实现。通过调研本地环境和生态，DeepSeek 官方既有 OpenAI 兼容接口，又在 `https://api.deepseek.com/anthropic` 提供了 Anthropic Messages 兼容网关，且本地已在 `~/.claude/settings.json.deepseek` 验证并稳定使用该网关。复用兼容链路可极大降低实现复杂度并保证流式与工具调用的高可靠性。

#### How

1. 在 `(liii pi auth)` 中，为 provider `"deepseek"` 增加凭据解析逻辑：
   - 优先从 `auth-alist` 消费 `"deepseek"` 条目（type: "api_key"）；
   - 次优先检查环境变量 `DEEPSEEK_API_KEY`、`ANTHROPIC_AUTH_TOKEN`；
   - 兜底检查本地生态配置文件（`~/.claude/settings.json.deepseek`、`~/.deepseek.json`）；
   - 缺失时返回 `#f`。
2. 在 `(liii pi models)` 中，为 `"deepseek"` 设置默认端点 `https://api.deepseek.com/anthropic`（支持通过 `DEEPSEEK_BASE_URL`、`ANTHROPIC_BASE_URL` 或 `GF_PI_BASE_URL` 覆盖），默认模型设为 `deepseek-chat` 或 `deepseek-v4-flash`。
3. 在 `(liii pi agent)` 中支持 `"deepseek"` provider 路由分发。
4. TDD 编写单元测试覆盖凭据解析与模型配置，并执行真实冒烟测试。
