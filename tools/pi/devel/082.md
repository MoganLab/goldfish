## 验收点

1.0 **定义 `pi-tui-state` 核心会话状态模型**：
- 支持包含以下核心属性：
  - `status`：支持状态集合 `'idle`（等待输入）、`'running`（思考中）、`'streaming`（流式回包中）、`'confirm`（模态确认中）、`'exit`（退出）；
  - `messages`：历史与当前会话消息列表；
  - `input-editor`：用户当前输入状态或缓冲占位；
  - `active-tool`：当前正在执行的工具名称与状态；
  - `scroll-offset`：视口纵向滚动偏移量；
  - `dirty?`：屏幕/状态脏标记，用于触发重绘；
- 提供类型谓词 `pi-tui-state?`、工厂函数 `make-pi-tui-state` 以及纯函数式或受控变异的状态更新原语（如 `state-with-status`、`state-mark-dirty!`、`state-clear-dirty!` 等）。

2.0 **主事件循环驱动器（响应式轮询与节拍控制）**：
- 对接 `(liii tui terminal)` 的非阻塞按键轮询（`terminal-poll-key`），在每轮 tick 中及时响应用户输入；
- 提供可配置的节拍控制（默认 ~30-60fps，例如每帧间隔 0.016s~0.033s），避免无节制空转消耗 CPU；
- 维护循环调度生命周期：根据状态机是否处于 `'exit` 或遇到终止按键（Esc/q）安全跳出。

3.0 **脏标记局部与整帧重绘驱动机制**：
- 支持注册 render 渲染钩子；
- 仅当 `state-dirty?` 为真（或窗口尺寸/内容变化）时才触发重绘回调，重绘后自动重置 dirty 标记；
- 避免未变更时的无谓重刷，保证渲染高效稳定。

4.0 **基于虚拟终端（VirtualTerminal）的确定性 TDD 覆盖**：
- 利用 `(make-virtual-terminal)` 注入一系列按键事件，驱动主循环流转；
- 验证从 `'idle` 接收按键切换状态、触发脏标记重绘，直到流转至 `'exit` 优雅退出的完整过程；
- 异常保护：按键处理或重绘回调中的非法输入均有安全防护与类型检查；
- 门禁四连：`timeout 600 xmake b goldfish`、`timeout 120 bin/gf fmt`、`git diff --exit-code`、`timeout 120 bin/gf check` 与相关单测 100% PASS。

## 2026-10-21 任务描述

### What

1. 新建 `(liii pi modes tui state types)` 与 `(liii pi modes tui state)`，实现 `<pi-tui-state>` 核心状态模型与状态迁移原语；
2. 新建 `(liii pi modes tui loop)`，实现响应式主事件循环驱动器 `run-tui-loop`，包含非阻塞按键轮询、~30-60fps 节拍控制与基于脏标记的 render 重绘调度；
3. 更新 `(liii pi modes tui)` 门面库，重新导出所有状态与循环驱动函数；
4. 编写 `state-test.scm`（71 项断言）与 `loop-test.scm`（16 项断言），通过 `make-virtual-terminal` 实现 100% 确定性自动化单测覆盖。

### Why

TUI 界面与传统的 CLI 流式打印不同，需要维持长生命周期的状态机，并以固定帧率/按键事件驱动屏幕更新。通过将状态表示（`pi-tui-state`）与驱动逻辑（`run-tui-loop`）独立解耦，不仅保证后续输入组件（任务 083）、动态布局（任务 084）、流式输出（任务 086）能够纯粹作为状态消费者，还能通过 VirtualTerminal 进行完全确定的无头自动化回归。

### How

- 使用 Scheme 原生 `define-record-type` 定义不可变与高效更新的 `pi-tui-state`，状态集合包含 `'idle`、`'running`、`'streaming`、`'confirm`、`'exit`；
- 在主循环中分离三种驱动源：键盘输入事件（`terminal-poll-key`）、定时 tick（用于驱动状态轮转与后续的 spinner 动画）、以及外部 agent 事件队列；
- 通过 `dirty?` 标志合并同帧多次变更，保证单次 render 刷新。
