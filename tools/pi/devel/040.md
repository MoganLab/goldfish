原生 `web_search` 的关键形状：

- 工具名：`web_search`（扩展 `~/git/pi-web-search/src/index.ts` 注册）
- 调用参数：`{"query": "\"Goldfish Scheme\" github release OR latest release"}`
- 工具返回文本：答案正文内联 `[1][2]` 角标，末尾追加
  `## Sources` 编号列表（title + URL）
- `details` 字段：`sources`（title/url 数组）、`providerKind: "google"`、
  `nativeSearchUsed: true`、`nativeSearchEvents:
  ["google.groundingMetadata.webSearchQueries"]`、`searchQueries`、
  `searchResults`（含 `source: "google.groundingChunks"`、`raw.index`、
  `raw.uri`、`raw.title`）、`grounded`、`resultCount`
- 扩展源码里的 Schema（`src/web_search.ts`）：

```ts
Type.Object({
  query: Type.String({ description: "The search query or question to answer" }),
  urls: Type.Optional(Type.Array(Type.String(), {
    description: "Additional URLs to analyze along with search (up to 20)",
    maxItems: 20
  })),
})
```

原生扩展还额外注册 `url_context` 工具；本任务范围只对齐 `web_search`，
`urls` 作为 `web_search` 的可选参数保留。

## 验收点

1. **Schema 形状对齐原生 pi**：`pi-web-search-schema` 返回 JSON Schema 对象，
   `type` 为 `"object"`；`properties.query` 为必填 string；`properties.urls`
   为可选 array（元素 string、`maxItems` 20）；`required` 为 `#("query")` 或
   等价的单元素字符串列表。
2. **门面导出**：`pi-web-search-schema` 与参数校验函数可从
   `(liii pi web-search)`、`(liii pi tools)`、`(liii pi)` 三层导入使用。
3. **可选工具列表注册**：`web_search` 进入 `PI_ALL_TOOL_NAMES`，但**不**进入
   `PI_DEFAULT_TOOL_NAMES`；`parse-tools-selection "+web_search"` 能把它加入
   选择结果，`parse-tools-selection "web_search"` 能单独选中它。
4. **参数校验**：`(pi-validate-web-search-args args)` 对合法参数返回 `#t`；
   缺少/空 `query`、`query` 非 string、`urls` 非 list、`urls` 元素非 string、
   `urls` 超过 20 项时给出人可读的结构化错误（`value-error`/`type-error`），
   不允许静默通过。
5. **无回归**：现有工具 Schema/选择逻辑测试全部通过；`PI_ALL_TOOL_NAMES`
   长度断言从 7 更新为 8；`bin/gf check` 与 `bin/gf fmt` 干净。
6. **范围约束**：本阶段不发起网络请求、不改 Gemini 请求体、不实现
   `pi-execute-web-search`；这些分别由 041/042/043 验收。

## 2026-10-20 任务描述

### What

1. 建档任务 040，锁定阶段一范围与验收点；
2. 实测原生 pi + `npm:pi-web-search` 的 `web_search` 行为，记录工具名、参数、
   返回文本引用格式与 `details` 结构，作为 `bin/gf pi` 的对照基准；
3. 开发阶段将按 TDD 新增 `pi-web-search-schema` 与参数校验测试，再实现 Schema
   与可选工具列表注册。

### Why

`bin/gf pi` 目前只有 read/bash/edit/write/grep/find/ls 七个内置工具。要让脚本模式
具备联网搜索能力，先建立与原生 pi 扩展一致的 `web_search` 工具声明：Schema 是
后续 Gemini `googleSearch` 工具注入、`groundingMetadata` 解析和 Agent 工具调用
闭环的共同契约，必须先稳定下来。

### How

1. 对照原生扩展 `~/git/pi-web-search/src/web_search.ts` 的 TypeBox Schema，
   用 `(liii pi grep)` 同类的手写 alist 风格实现 `pi-web-search-schema`；
2. Schema 只描述 JSON 结构，语义校验放在独立函数
   `pi-validate-web-search-args`，便于 042 执行器直接复用；
3. `web_search` 只加入 `PI_ALL_TOOL_NAMES`（可选工具列表），保持默认工具集
   四件套不变，避免未实现执行器时默认调用失败；
4. 按项目惯例一个函数一个测试文件，先写失败测试再实现。
