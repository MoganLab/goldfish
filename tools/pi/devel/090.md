## 验收点

1.0 **高危工具调用拦截识别机制（结合 074 `tool_call` 拦截钩子）**：
- 识别高危操作：`write` 工具（覆盖或新建文件）、`edit` 工具（修改关键源码）、高危 `bash` 命令（如 `rm`、`git reset --hard`、`git push`、`kill` 等破坏性命令）；
- 结合 Extension 机制的 `tool_call` 生命周期拦截钩子，判定需要人在回路授权时触发模态拦截；
- 参数类型非法或结构不符时按 Goldfish 规范抛出 `type-error`。

2.0 **模态确认对话框数据模型与状态机切换（`CONFIRM`）**：
- 定义 ConfirmRequest / ConfirmDialog 状态模型，包含 `tool-call-id`、`tool-name`、`args`、`danger-level`、`target-summary`（如目标文件路径、执行命令摘要）、`diff-preview`（修改差异或写入内容预览）；
- 触发拦截时，TUI 状态机切入 `'confirm` 状态，置脏屏幕（`state-mark-dirty!`）；
- 弹窗记录上下文，允许挂起当前工具执行等待用户决策。

3.0 **居中模态警告对话框排版与差异预览渲染**：
- 对话框采用带警示边框或标题的单线/双线 Box 居中悬浮排版；
- 详细格式化展示：工具名（如 `Tool: write`）、目标文件/参数（如 `Path: config.json`）、差异或内容预览摘要；
- 底部显式展示操作提示：`[y] 允许 / [n] 阻止 / [e] 编辑`；
- 针对窄终端自动折行或截断，避免超出屏幕边界。

4.0 **用户按键响应与工具执行放行/拒绝闭环**：
- 在状态机为 `'confirm` 时，按键调度器优先捕获用户交互：
  - 按 `y` / `Y`：允许执行，恢复状态机至前序状态（如 `'running`），解除拦截放行工具继续调用；
  - 按 `n` / `N` / `Esc`：阻止执行，返回拒绝或取消的 tool-result（如 `isError: #t`，提示 `Operation rejected by user`），恢复状态机；
  - 按 `e` / `E`：进入编辑模式（可将命令或内容填入输入框供用户微调修改）；
- 弹窗关闭后，平滑恢复原有主界面（消息视口与状态栏）无闪烁残影。

5.0 **TDD 单元测试覆盖与门禁验证**：
- 编写全面的单元测试，覆盖高危工具检测、确认模型创建、状态机切换、按键分发逻辑、渲染排版以及放行/拒绝分支；
- 门禁四连：`timeout 600 xmake b goldfish`、`timeout 120 bin/gf fmt`、`git diff --exit-code`、`timeout 120 bin/gf check`（所有源文件 <= 300 行）；
- 全量测试 100% 通过无回归。

## 日期 任务描述

### What

1. 依据 `Agents.md` §3 任务 090 规格建立任务文档 `tools/pi/devel/090.md`；
2. 明确人在回路敏感操作识别、CONFIRM 状态机流转、居中模态告警对话框渲染排版、y/n/e 响应决策与工具放行/拦截闭环的验收标准。

### Why

Coding Agent 在执行自动化任务时，可能触发覆盖重写代码、删除关键文件、强制推送 git 分支或终止系统进程等高危操作。
通过人在回路（Human-in-the-loop）机制，在执行敏感操作前挂起并弹出模态确认对话框，展示清晰的参数与变更摘要，
赋予开发者最终审查与决策权（允许、阻止或微调编辑），这是保障代码资产与运行环境安全的坚实屏障。

### How

1. 在 `confirm.scm` 中实现高危工具调用识别规则（判定 write、edit、高危 bash 等）；
2. 设计 ConfirmRequest / ConfirmDialog 结构，封装操作元数据与预览文本；
3. 在 `state.scm` 中增加 confirm 状态切片管理，处理从 running/streaming 切入 confirm 及恢复；
4. 在按键调度器 `loop/dispatch.scm` 中，为 `'confirm` 状态设计最高优先级的按键拦截器，处理 y/n/e/Esc 等按键并产出对应动作；
5. 在界面布局层实现居中浮层渲染与屏幕恢复机制；
6. 严格按 TDD 规范编写单元测试并确保通过全部门禁。
