## 验收点

- 会话创建处 ID 生成迁移：
  - `tools/pi/liii/pi/session.scm` 中的 `%init-new-session-file` 改用 `uuid7` 生成 `sid`。
  - `tools/pi/liii/pi/event/record.scm` 中的 `pi-event-session` 缺省 ID 改用 `uuid7`。
  - 会话文件名（`YYYY-MM-DDTHH-mm-ss-sssZ_<sid>.jsonl`）正确携带 uuid7 标识符。
- TDD 覆盖 ID 格式断言：
  - 生成的会话 ID 必须满足 RFC 9562 UUIDv7 标准：
    - 长度恒为 36 字符（8-4-4-4-12 格式，索引 8、13、18、23 处为 `-`）；
    - 版本位（第 15 个字符，索引 14）必须为 `#\7`；
    - 变体位（第 20 个字符，索引 19）必须属于 10xx 变体（`#\8`、`#\9`、`#\a`、`#\b`、`#\A`、`#\B`）；
    - 时间戳前缀具备合理性（前 48 位 Unix 毫秒时间戳与当前系统时钟接近，具备时间单调递增特性）。
  - `tools/pi/tests/liii/pi-session-test.scm` 断言新建会话文件及读取出的会话 ID 符合 UUIDv7 格式。
  - `tools/pi/tests/liii/pi/pi-event-session-test.scm` 断言缺省生成的会话 ID 符合 UUIDv7 格式。
- 对齐原生 pi 并消除偏差清单 #9：
  - 原生 pi 会话 ID 使用 uuidv7，迁移后 goldfish pi 与原生 pi 规格完全对齐，消除偏差清单 #9。
- 门禁检查与测试全绿：

## 2026-10-19 任务建档

### What

1. 查阅 `PI_PLAN.md` §3 任务 027（会话 id 迁移至 uuid7）的验收点与背景说明。
2. 从 `tools/pi/devel/ddd.md` 模板复制建立 `tools/pi/devel/027.md` 任务文档。
3. 明确任务涉及的代码文件、验收点（会话 ID 生成从 uuid4 迁移为 uuid7、TDD 断言覆盖版本位与变体位、对齐原生 pi 消除偏差清单 #9）、测试方案及门禁流程。

### Why

- `(liii uuid)` 在合并 main 后已提供标准的 `uuid7` 实现（基于 RFC 9562，前 48 位包含毫秒级时间戳并具有单调性）。
- 原生 pi coding agent 的 session id 规范即为 uuidv7。之前因 s7 生态暂无 uuidv7 实现而记录了偏差清单 #9。
- 现底座能力已完备，将会话 ID 迁移至 uuid7 可消除偏差 #9，与原生 pi 保持一致。

### How

1. 迁移 `tools/pi/liii/pi/session.scm` 中 `%init-new-session-file` 的 `(uuid4)` 为 `(uuid7)`。
2. 迁移 `tools/pi/liii/pi/event/record.scm` 中 `pi-event-session` 的默认 ID 生成为 `(uuid7)`。
3. 在 `(liii pi)` 门面中按需导出 `uuid7`。
4. 在对应单测中编写 RFC 9562 UUIDv7 结构校验断言（36 字符长度、8-4-4-4-12 连字符、第 15 位字符为 '7'、第 20 位字符为变体位），确保测试驱动开发全覆盖。
