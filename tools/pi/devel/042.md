## 验收点

（从 `PI_PLAN.md` §3 任务表复制展开，逐条可验证）

1. **网络执行器 `pi-execute-web-search`**：
   - 复用 `(liii http)` 的 HTTP POST 能力与超时控制机制（强制带超时，默认取配置或入参）；
   - 正确复用 Gemini 配置通道：自动读取有效凭据（Google API Key）、API 基础地址（`baseURL`）与网络代理配置（`httpProxy`，支持 socks5h/http）；
   - 正确构造向 Gemini 模型发起的网络搜索请求（基于 041 的请求体与 Google Search grounding 节构造）；
   - 支持传递可选的 `urls` 列表（最多 20 项）。
2. **回答内容与引用链接拼装格式化**：
   - 参考 `~/git/pi-web-search/src/format.ts` 对齐原生 pi 的格式化规范；
   - 消费 041 解析得到的 Grounding 三要素（`searchQueries`、`searchResults`、`citations`）与模型回答正文；
   - 拼装规范：
     - 正文部分：模型回答文本（Answer Text）；
     - 来源部分：若存在 sources/citations，格式化追加 `## Sources`，按编号输出 `[1] Title - URL`；
     - 补充结果：若存在未引用的 searchResults，格式化追加 `## Additional Search Results`；
     - 结果截断：复用已有的 `pi-truncate-head` 进行长度防护；
     - 结果结构：返回标准工具结果结构（包含 `content` 列表与包含 `sources`/`details` 的元数据）。
3. **异常处理与错误路径健壮性**：
   - 鉴权缺失（未配置 Google API Key / auth 凭据不存在）时，明确报错（返回人可读且可诊断的错误信息），绝不静默成功；
   - 网络超时（通过 timeout 参数约束）触发超时报错或结构化错误退出；
   - HTTP 4xx/5xx 状态码或网络连接失败，捕获并返回包含原因摘要的结构化错误；
   - 响应非 JSON 或空 candidates 安全降级，绝不出现未捕获崩溃或死循环。
4. **Stub Server 验证与 TDD 覆盖**：
   - 在 stub server 中增加或复用 Gemini search 模拟端点，支持正常搜索响应、带引用的 Grounding 响应、401/403 鉴权失败与 500/超时场景；
   - 单测采用 TDD 编写，一个函数一个测试文件，测试目录镜像源码目录；
   - 单元测试不引用三份计划文档，纯本地可重复回归。
5. **门禁与规范**：
   - 遵循单文件 300 行硬约束（执行与格式化分模块实现）；
   - 所有外部命令与 IO 均带超时保护；
   - 通过 `timeout 600 xmake b goldfish`、`bin/gf fmt`、`git diff --exit-code`、`bin/gf check`、`bin/gf doc --build-json`。

### Why

在任务 040 中完成了 Schema 校验与参数解析规范，在任务 041 中实现了请求体构造与 Grounding 三要素解析。
本任务（042）作为承上启下的阶段三，负责通过 `(liii http)` 真正连接 Gemini API 执行搜索，将获取到的文本与 Grounding 数据拼装为人类易读、带有来源引用的标准工具输出，并处理各种网络与鉴权异常，为任务 043 的 Agent 事件循环闭环调用打好坚实基础。

### How

1. 结果格式化（`format.scm`）：
   - 实现 `pi-format-web-search-result`，接收模型返回的文本与解析好的 grounding 详情；
   - 生成带 `## Sources` 和 `## Additional Search Results` 的排版内容，并包裹为标准 tool-result。
2. 网络执行器（`execute.scm`）：
   - 实现 `pi-execute-web-search`，读取传入参数（`query` 与可选 `urls`）；
   - 动态获取当前 Gemini 配置（API Key、代理、端点）；
   - 组装请求并调用 `(liii http)` 的 POST 方法，设置合理的超时；
   - 校验 HTTP 状态码并处理错误，成功时调用格式化函数并返回。
3. 容错与集成：
   - 扩展 stub server 模拟各种网络与响应边界条件；
   - 编写单元测试验证各路径。
